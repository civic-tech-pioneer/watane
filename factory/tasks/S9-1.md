## Goal
`host/tests/hostile.rs` is the one place that shows a hostile page (or a hostile web site on the
same machine) cannot reach a mod it does not own through the real program `watane`. It holds
every page row of TECHNICAL 13.2's `tests/hostile.rs` line that step 1 can run, plus the probes
below. Each probe runs against `watane --preview` (the `Preview` helper in `tests/program.rs`);
when one fails, fix `server.rs` or `pages.rs` so it answers as TECHNICAL 8.1 to 8.4 says. Never
weaken a check to pass a test (AGENTS.md).

## Acceptance
Fixtures `counter` and `hello` installed in one preview; `<port>` is the ready line's port.
Each row is a request -> the exact status (and, for refusals with a JSON body, the error code).
Send paths and headers verbatim with a raw `TcpStream` where reqwest would normalize them.
- AC1 Wrong `Host`: on `127.0.0.1` and `[::1]`, `Host` of `COUNTER.localhost:<port>`,
  `counter.localhost` (no port), `counter.localhost.:<port>`, `counter.localhost:<port>.evil`,
  `evil.example:<port>`, two `Host` headers (`counter.localhost:<port>` then
  `hello.localhost:<port>`), and no `Host` header -> 421 `text/plain; charset=utf-8`
  "unknown host". A valid but not installed name `ghost.localhost:<port>` -> 404 `text/plain`
  on `/`, `/call` and `/events`.
- AC2 Cross-mod `/call`: a `POST /call` on `counter.localhost:<port>` with
  `Origin: http://hello.localhost:<port>` -> 403 `forbidden`, and `api.get` afterwards still
  returns 0 (S11). The same request on `hello.localhost:<port>` with counter's origin -> 403.
- AC3 Preflight and methods: `OPTIONS /call` with `Origin` of hello and
  `Access-Control-Request-Method: POST` -> 405 with `Allow: POST` and no
  `Access-Control-Allow-*` header; no response of a mod origin or the API host carries an
  `Access-Control-Allow-Origin` header (check every response in this file).
- AC4 Body size: a `POST /call` with the exact origin and `Transfer-Encoding: chunked` that
  streams 2 MiB (no `Content-Length`) -> 413 `bad_request`; a `Content-Length: 2097152` header
  with a short body -> 413 or a closed connection, never 200; counter is unchanged after both.
- AC5 Mod origin is not the API host: on `counter.localhost:<port>`, `GET /api/status`,
  `POST /api/install` (with a valid JSON body) and `POST /mcp/preview` with the ready token ->
  404 `text/plain` (served as a missing `ui/` file); nothing is installed. On the API host
  `localhost:<port>`, `POST /call` and `GET /events` -> 404 (no mod is called).
- AC6 Path tricks on a mod origin -> 404 `text/plain`: `/..%2fmods/hello/ui/index.html`,
  `/%2e%2e%2f%2e%2e%2fhome.json`, `/%5c..%5cinstalled.json`, `/./index.html`, `/index.html%00`,
  `/%2fetc/passwd`, `//etc/passwd`, `/.%2e/lock`. `GET /` of counter with
  `Host: counter.localhost:<port>` returns counter's `ui/index.html` bytes, never hello's.
- AC7 `/events` cross-origin: `GET /events` on counter with hello's `Origin` -> 403; with
  `Origin: null` -> 403; a stream opened on hello's origin gets no message within 500 ms after
  `api.add` on counter.
- AC8 `/api/...` with any `Origin` -> 403 `forbidden` (HOST-F-16), including counter's own
  page origin.
- AC9 The step-2 rows of 13.2's `hostile.rs` line ("a subscription function -> 404" and
  "counter without storage grant") cannot run in step 1 (install refuses subscriptions; no
  revoke). Mark them "(step 2)" in that 13.2 line; add no test for them.
- AC10 `cargo test -p watane-host`, clippy `-D warnings --all-targets --all-features`,
  `cargo fmt --check` pass. Existing tests stay green.
