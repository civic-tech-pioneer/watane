Slice: S62 — Alice pairs her server with a code, and only her own machines are served (net N2)

## Goal

Stage N2 of net/TECHNICAL.md 9. Alice's laptop (the anchor: its holder's `is_anchor()` is true)
gives a pairing code for a role; her server joins with it; the laptop asks Alice (an event with the
server's key) and, on her yes, signs a new device list that both machines store. From then on the
device list alone decides who is trusted: the N1 stand-in `Options::trusted` is gone. Removing a
machine or changing a role or the expiry signs a new list that reaches the other own machines.
Every connection passes a `Gate` that applies the caller's allowance and budget (connections,
streams, bytes polled from `Connection::stats()`) before any work, so an unknown node gets `hello`
and `pair` only, within a small shared budget. The spec decisions are already written (net
TECHNICAL 3, 4.2, 5.4, 5.5, ND-12 and ND-15 to ND-17); follow them, do not reopen them.

## Acceptance

AC1 API (net TECHNICAL 3). `Options::trusted` is removed. `Limits` gains four fields that `hello`
does not send (4.2 "Budgets"): `unknown_conns_per_peer: usize` (2), `unknown_streams_per_peer:
usize` (2), `unknown_conns: usize` (16), `unknown_bytes_per_sec: u64` (65536). `Net` gains
`pair_code`, `answer_join`, `join`, `devices`, `remove_device`, `set_role`, `set_expiry` and
`events` with the signatures of section 3, and `pub enum Event` with every variant of section 3
(N2 emits only `JoinAsked` and `DevicesChanged`). `Options`, `Limits` and `Event` derive `Clone`
and `Debug`; `Options` and `Limits` derive or impl `Default` (node Q4).

AC2 Storage (4.5, 5.5). The verified device list is stored as its signed bytes in
`<home>/net/devices`; on a replica the anchor's key text in `<home>/net/anchor`; `anchor_seen` in
`<home>/net/book.json` (a new file has the 4.5 defaults; other fields are kept as found). Every
write: temp file, fsync, rename, mode 0600. A reopen gives the same `devices()` and classes. A
`devices` file that does not verify, or an `anchor` file whose text does not parse, makes `open`
fail with `Corrupt`. The device list form (4.3 and `tests/vectors.rs`) does not change.

AC3 S2 (`tests/pair.rs`, `s2_server_joins_with_a_code_and_alice_confirms`). Laptop (holder
`is_anchor` true, so `MemHoldings` needs a way to say so) calls `pair_code(Role::Full)`: with no
list yet it first signs a list of itself only, as full (seq 1). The code's hints hold the laptop's
bound addresses (`Hint::Addr`). The server calls `join(&code, false)` on another thread; the
laptop's `events()` receiver gets `JoinAsked { node: server key, role: Full }`; the test calls
`answer_join(&server, true)`; `join` returns the list. Both `devices()` are equal: anchor = laptop,
seq 2, devices {laptop: Full, server: Full}. Each rates the other `Trusted`; the laptop gets
`DevicesChanged`. The server's `heads_of(laptop)` and the laptop's `heads_of(server)` work. The
test computes the expected list without `watane_net` beyond the public fields.

AC4 S3 (`tests/pair.rs`, `s3_bad_codes_and_a_no_change_nothing`). Each refused, and after each the
laptop's `devices()` and the joiner's `devices()` (None) are unchanged: a second use of a spent code
(`NetError::BadCode`), a wrong secret (`BadCode`), an expired code (a laptop with
`limits.pair_deadline` of 1 s, joined after 2 s: `BadCode`), `answer_join(.., false)`
(`Declined`), and no answer within `pair_deadline` (`Declined`). The secret is compared in constant
time. A code is spent the moment a `pair` with it arrives, before the participant answers. Also:
`pair_code` on a non-anchor is `NotAnchor`; `join` on a machine that has an anchor and `replace`
false is `HasAnchor` before any network contact; with `replace` true it joins the new anchor.

AC5 S4 (`tests/pair.rs` or `tests/serve.rs`, `s4_an_unknown_node_gets_hello_and_nothing_else`). A
paired server and an unknown node (a fresh `Net` or a raw iroh endpoint from `support`). The
unknown node's `hello` answer has `devices_seq` null and holds no participant key (the bytes of the
answer contain none of the fixture's participant public keys); its `heads`, `entries`, `fork`,
`devices` are `not_allowed`, each message naming the caller's short key. A request that carries a
trusted node's key in a field (e.g. `devices` or `heads` with that key as an argument) is refused
the same way and `class_of(unknown)` stays `Unknown`. A trusted caller's `hello` has `devices_seq`
= the list's seq.

AC6 S10 (`tests/pair.rs`, `s10_removed_or_expired_machines_lose_trust`). Laptop, server and a
second laptop (light) all paired. `remove_device(second)` returns seq + 1 without it; within 5 s
the server's `devices()` has that seq (pushed by `devices` with the higher seq, which the server
pulls back from the laptop, 4.2), and the server answers the second laptop's `heads` with
`not_allowed`. `set_role` and `set_expiry` sign new lists the same way; `remove_device`,
`set_role`, `set_expiry` on a replica are `NotAnchor`. Expiry: the test reads the laptop's
`node.key` seed, signs with `DeviceList::sign` a list with `expires_days` 1 and `time` 2 days ago,
writes it as the server's `devices` (and `anchor`, and a `book.json` whose `anchor_seen` is 2 days
ago), opens the server: it rates the second machine of that list `Unknown` and refuses its `heads`
with `not_allowed`. Then the laptop calls the server (any op): `anchor_seen` is renewed and the
server rates the others `Trusted` again (ND-17). The anchor never expires for itself.

AC7 Lists move only forward (NET-F-11, `devices` op). A list from another node is stored only when
the stored anchor signed it, it verifies and its seq is higher: unit or integration tests for a
list signed by another key, a lower or equal seq, and a list not naming the anchor, each leaving
`devices()` unchanged. `devices(seq)` answers `[list or null, addrs]` (addrs: an empty array in
N2) to trusted callers only.

AC8 S9 budget part (`tests/budget.rs`, `s9_requests_over_limits_and_budgets_are_refused_before_work`).
Each refused before the holder is called (`MemHoldings::calls()` unchanged): a request over
`limits.request` (`too_large`); a third connection from one unknown key held open beside two
others (closed, or `over_budget`); a third concurrent stream from one unknown key
(`over_budget`); an unknown connection beyond `unknown_conns` (use a small value in `Limits` for
the test, e.g. 3, and 4 keys); bytes: with `unknown_bytes_per_sec` 4096, an unknown node that sent a
request of about 16 KiB gets `over_budget` for its next `hello`, and a `hello` passes again after
the bucket refilled. A trusted node has no budget: the same traffic from it is served.

AC9 Gate (`src/allow.rs`, unit tests). `Gate<P: ProtocolHandler>` wraps every handler in the
router (N2: only `watane/1`'s `Serve`), checks the peer's allowance for the ALPN and the connection
budget before the inner `accept`, releases the count when the connection ends, polls
`Connection::stats()` while the inner handler runs and charges the unknown pool; for an ALPN that
cannot answer `over_budget` it closes the connection when the budget is spent. A unit test with a
dummy inner handler on a second ALPN shows: an unknown peer is closed before the inner handler is
called when its allowance for that ALPN is zero; a trusted peer reaches it. No blobs or gossip
handler is added (N3).

AC10 Existing tests keep passing, rewritten to pair through the device list instead of `trusted`
(see Changed tests). `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` are clean
in `net/`. `cargo test --no-fail-fast -- --include-ignored` passes in `net/`.

## Interface

Public, fixed by net/TECHNICAL.md 3: `Net::{pair_code, answer_join, join, devices, remove_device,
set_role, set_expiry, events}`, `Event`, `DeviceList` (unchanged form, `sign`, `verify`),
`Limits` with the four budget fields of AC1. `NetError` variants as 3.2; wire `bad_code` maps to
`NetError::BadCode`, `declined` to `Declined` at the joiner. Nothing outside net uses net yet.

## Cloud rules (binding)

Bind `127.0.0.1`, never `::1`; no test reaches the internet. Every test must also run on macOS: no
`/proc`, no Linux-only paths or syscalls. Build with `CARGO_PROFILE_DEV_DEBUG=0`, use the
workspace's shared `target/`, and remove leaked `/tmp/.tmp*` dirs. Run `cargo test --no-fail-fast`.
Long sleeps in tests: keep each test under about 10 s (use small `Limits` for deadlines).
