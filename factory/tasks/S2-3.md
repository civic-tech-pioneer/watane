Subsystem: host
Effort: high
Slice: S2 — The page calls its logic: a coding agent runs `watane-dev new hello` and `serve --json`; Alice opens the page, clicks its button, and sees the count go up.

## Goal
A mod's page can call its own logic. Each mod origin serves `/watane.js` (the page library) and
answers `POST /call` from its own page only, running the call as `Caller::Page` through
`Host::call_async` (task S2-2). Alice's click on the counter page sends `/call` and gets the new count.

## Acceptance
- AC1 `GET /watane.js` on `<local>.localhost:<port>` answers 200 with exactly the bytes of
  `host/src/watane.js` read from disk by the test, `Content-Type: text/javascript; charset=utf-8`,
  and every header of 8.3. `src/watane.js` is exactly the source in TECHNICAL 8.5; `WATANE_JS`
  equals it. A `ui/watane.js` in the mod does not replace it.
- AC2 With fixture `counter` installed: `POST /call` with `Origin: http://counter.localhost:<port>`,
  `Content-Type: application/json`, body `{"fn":"api.add","args":null}` answers 200 `{"value":1}`,
  then `{"value":2}`; `{"fn":"api.get"}` with `"args":{}` answers `{"value":2}`.
- AC3 Refusals (8.2), each with the literal status and `{"error":{"code":...}}`: GET `/call` → 405
  with `Allow: POST`; no `Origin` or the origin of another mod or of the API host → 403 `forbidden`;
  `Content-Type: text/plain` → 415 `bad_request`; a 2 MiB body → 413 `bad_request`; a body with an
  extra field `caller` → 400 `bad_request`; `fn` not a string, `args` a number → 400.
- AC4 Call errors keep their codes and statuses (2.2): an unknown function → 404 `no_function`;
  `api.add-then-fail` → 422 `trap`; a page-only mod's `/call` → 404 `no_function`; with
  fixture `hog` and a host opened with a low time limit, `api.spin` → 422 `{"code":"limit","limit":...}`
  and then `api.probe` on the same origin answers 200.
- AC5 The program: `watane --preview D --install <counter fixture>` then `/call` on its page origin
  works (one test through `env!("CARGO_BIN_EXE_watane")`, so the program wires the runtime).
  `POST /api/install` of the `counter` folder answers `has_logic: true`.
- AC6 `cargo test`, clippy `-D warnings`, `cargo fmt --check` pass; no new dependency.

## Spec
`host/TECHNICAL.md` 8.1 (routing; `/call` only on a mod origin), 8.2, 8.3 (the host owns
`/watane.js`, `/call`, `/events`; headers on every mod-origin response, also on `/call` answers and
errors), 8.5, 2.2 (statuses), 13.2 rows `pages.rs` (watane.js bytes) and `hostile.rs` (the `/call`
rows that apply: caller field → 400, other origin → 403, 2 MiB → 413), 14 rows "the caller comes
from the transport", "a page reaches only its own mod". FUNCTIONAL S11.

## Interface
Takes from S2-2: `Host::call_async(self: &Arc<Self>, Caller::Page, LocalName, String, Value) -> Result<Value, CallError>`,
`CallError::status()`, its `Serialize`, `Host::open(home, Limits)`.
Provides, fixed: `pub const WATANE_JS: &str = include_str!("watane.js")`; the `/call` body and
answers of 8.2 (dev's template and user-sim send them as `watane.js` does).

## Files
`host/src/{lib,pages,server}.rs`, `host/src/watane.js`, `host/tests/{pages,hostile}.rs`,
`host/tests/program.rs` (one added test), `host/TECHNICAL.md` when wrong. No `Cargo.toml` change.

## Out of scope
`/events` (stays 404 until S3), MCP, tools, links. `watane.on` in `watane.js` is part of the fixed
source; its stream simply finds no `/events` yet.
