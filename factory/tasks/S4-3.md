Slice: S4 — The agent fixes a failing test: it breaks the counter's `add`, runs `watane-dev test`, reads the result, fixes the code, and the tests pass.

## Goal
`watane-dev test` runs the mod's contract tests (`tests/*.json`) through `watane_host::Harness`
after its unit tests, and reports each failing step with file, step, call, expected and got. The
agent can break `add`, see exactly which step fails and why, fix it, and see `test` pass. `serve`
runs `test` first and starts or updates no preview for a mod whose tests fail.

## Acceptance
- AC1 (DEV-S-4) On a new template mod, `test --json` exits 0; `result.contract.passed` equals the
  number of steps in `tests/*.json` (the test counts them with `serde_json`), `files` 1, `failed` 0;
  `result.unit.passed` equals the `#[test]` count (regex). `logic.wasm` exports
  `mods:<slug>/api@0.1.0` (the test loads it with `wasmtime::component::Component`).
- AC2 (DEV-S-17) With `next` in `logic/src/lib.rs` changed to `count.saturating_add(2)`: exit 1;
  an error `test.contract` with message `tests/counter.json step 2 (api.add): expected 1, got 2`
  (2.2 template; steps are 1-based); `result.contract.failures[0]` is
  `{"file":"tests/counter.json","step":2,"call":"api.add","expected":1,"got":2,...}`;
  `next` is `watane-dev test --json`. Restoring `saturating_add(1)` makes `test` exit 0 again.
- AC3 A step `{"call":"api.add","returns":2}` as the first step of a fresh file → `expected 2,
  got 1`, step 1 (the literal DEV-S-17 case).
- AC4 (DEV-S-19, emits part) A step whose `emits` names `changes.counted` with `{"count":1}` passes;
  with count 2, or with an extra event, or a missing one, it fails as `test.contract` naming the
  step; the full name `mods:<slug>/changes.counted` matches too; `expected`/`got` show the event lists.
- AC5 `fails`: `true` passes on a failing call; a string passes when `"<code>: <message>"` contains
  it; a call that succeeds where `fails` is set fails the step.
- AC6 A file that does not parse, has an unknown field, both `call` and `deliver`, both `returns` and
  `fails`, no steps, or a `fakes` key with `@` → `test.contract_file` naming the file. A `deliver`
  step → `test.contract_file` whose message says deliver steps arrive with links between mods
  (step 2). (`parse` unit tests on literal texts.)
- AC7 `json_eq`: key order ignored, `1` equals `1.0`, nested arrays and objects, different types
  unequal (unit tests on literal pairs). `run_steps` unit tests with a closure in place of the host
  (dev 15.1 contract row).
- AC8 (outcome 4) `serve --json` on a mod whose contract test fails: exit 1 with the
  `test.contract` error, and no preview starts (no `previews/<slug>-*` home created, or, when a
  preview already runs, its page still returns the old bytes). On a passing mod `serve` works as
  before. A mod without `tests/*.json` gets `mod.no_contract_tests` from `serve` too.
- AC9 `cargo test`, `WATANE_BIN=<built watane> cargo test -- --include-ignored`, clippy
  `-D warnings --all-targets --all-features`, `cargo fmt --check` pass. Existing tests stay green.
