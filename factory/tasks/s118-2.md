Subsystem: host
Effort: medium
Depends on: none
Slice: S118 — a reinstall after 'Keep data' says the data is kept

## Goal

When Alice removes a mod with 'Keep data' and installs it again, the host's install plan tells
the app that the mod's kept data comes back: `PlanEntry.kept_state` is true for that `New`
entry. Nothing about grants changes: `new_grants` still lists `Storage`, and the granted set is
computed as before.

## Acceptance

AC1: install a mod that declares `Storage` and writes state; `remove(local, false)`; `plan` the
same folder again: its entry is `Change::New` with `kept_state == true`, and its plan JSON has
`"kept_state":true`.
AC2: the same after `remove(local, true)` (delete data): `kept_state == false`.
AC3: a mod never installed in this home: `kept_state == false`. An `Update` and an `Unchanged`
entry: `kept_state == false`.
AC4: the reinstall after AC1 commits and the mod reads its old state (existing behaviour, 4.4);
the install request the app receives carries `kept_state == true` for that entry.

## Spec

host TECHNICAL 3 (`PlanEntry`, the new field), 4.2 step 6 (already amended on `slice/s118`:
read it first), 4.4 `remove`, 7 (table `s/<id>`, `<id>` = first 32 hex of `blake3(identity)`).

## Interface

Provides to s118-3 (app): `pub kept_state: bool` on `watane_host::PlanEntry` (last field;
serialized as `"kept_state"`). `InstalledMod` does not get it.

## Files

host/src/catalog.rs, host/src/state.rs (a read-only check that table `s/<id>` exists), and the
host test files that build or compare a `PlanEntry` or plan JSON; host/tests/it/ (a new test
next to the existing remove/keep-data or plan tests).

## Changed tests

Any test or golden that builds a `PlanEntry` literal or compares plan JSON gains
`kept_state: false` / `"kept_state":false`; search `host/tests` and `host/src` for `PlanEntry {`
and `"new_grants"`. Other subsystems that build a `PlanEntry` literal (search `app/`, `dev/`,
`dist/` for `PlanEntry {` and `new_grants:`) gain `kept_state: false` so the workspace compiles.

## Out of scope

The app's words (s118-3). Any change to grants, `new_grants`, `needs_confirmation` or the
granted set.
