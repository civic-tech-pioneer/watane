## Goal
Three texts of step 6 (`publish --push`, dev/src/share.rs) mislead. After this task:
- `env.git_identity` carries only git's last stderr line (as TECHNICAL 2.2 already says), with git's
  guess of the identity removed: git writes `fatal: unable to auto-detect email address (got
  'root@host.(none)')`, and the user@host in the parenthesis is the person's private machine name.
- `publish.push_failed` no longer repeats `remote: remote:` and keeps no trailing whitespace: each
  kept stderr line has a repeated leading `remote: ` collapsed to one and its trailing whitespace
  trimmed; empty lines are dropped before taking the last five.
- The fix of `publish.push_failed` (and so the `next` of publish, which joins the fixes with ` && `,
  dev/src/cli.rs around line 869: do not edit cli.rs, it changes by itself) shows the git commands
  without `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=60`. Those flags are dev's own guard
  against a stalled transfer; a person or agent rerunning by hand does not need them, and they make
  the command look like something special. dev still passes them to the git it runs.

Decided here: `Run::text()` (the text shown in messages and fixes) omits the `-c http.lowSpeed*`
pairs; the arguments given to the process keep them. If `Run` has one field that both builds the
process and the text, split the display from the argv, not the other way round.
