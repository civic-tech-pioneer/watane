Subsystem: install
Effort: medium
Depends on: none
Slice: S55 — Alice publishes on one machine, Bob installs on another and uses the mod (J3 between two machines)

## Goal
`install/tests/vm_two_machines.sh` runs J3 between this Mac (Alice, and the fake web host) and a
fresh Tart VM cloned from `watane-clean` (Bob), end to end, and prints `TWO-MACHINES PASS`. In the
VM, watane is installed by the one-liner; Bob's app is a debug `driver` build of `watane-app`
(the consent floor lets only a click answer; a script cannot click the release app in the guest:
SIP on, no Accessibility grant, probed 2026-11-19), launched in the guest's GUI session and driven
from the host over ssh. The journey itself is the app test `two_machines::ac1_j3_two_machines`
(task s55-1). Every byte reaches Bob over the VM network; the VM has no share of the host. The
script deletes its VM on every exit. The helpers it shares with `vm_mac.sh` move to one sourced
file.

## Acceptance
- AC1 `tests/vm_lib.sh` (POSIX `sh`, sourced, not run) holds what both drivers use: the askpass
  setup, `remote`, `copy`, `boot <image>` (clone `watane-run-<pid>`, run `--no-graphics`, the
  600 s ip and ssh deadline), `stop_run`, `delete_run` and the cleanup trap that stops and deletes
  only the run's VM. `vm_mac.sh` sources it (by its own folder) and behaves exactly as before:
  `cargo test -p watane-install --test it clean_mac::` passes unchanged.
- AC2 `sh tests/vm_two_machines.sh [--from <release-dir>]` without `tart` exits 2 before creating
  any file, with `vm_two_machines.sh: tart is not installed (see install/TECHNICAL.md 12.6)`.
  With a fake `tart`/`ssh`/`scp` first on `PATH` (as clean_mac.rs's lifecycle test does), a
  failing step stops the run with the step's command named, and the fake records `tart stop` and
  `tart delete watane-run-<pid>` on success, on failure and on TERM. The run never clones from or
  deletes `watane-clean` itself.
- AC3 On a Mac with Tart, the script: (1) builds `cargo build -p watane-app --features driver`
  and `cargo test -p watane-app --features driver --test it --no-run`; (2) boots a clone of
  `watane-clean` with `tart run --no-graphics` and no `--dir`; (3) fails unless the guest's
  `mount` lists no `virtiofs`, `smbfs`, `nfs`, `afpfs` or `webdav` file system and
  `/Volumes/My Shared Files` does not exist (outcome 2); (4) installs watane in the guest by the
  one-liner, with no terminal so no toolchain is offered: by default `curl -fsSL
  https://github.com/civic-tech-pioneer/watane/releases/latest/download/install.sh | sh`
  (the one-liner of TECHNICAL 3.1), with `--from <dir>` the local release folder copied in and
  `WATANE_RELEASE_BASE=file://...`, as vm_mac.sh does; then `~/.local/bin/watane --version`
  answers; (5) wraps `target/debug/watane-app` in a minimal bundle `Bob.app`
  (`Contents/Info.plist` with CFBundleExecutable, CFBundleIdentifier, CFBundlePackageType APPL),
  copies it to the guest, and writes the guest bridge `bob.sh <home_name>`: makes two fifos in a
  fresh temp folder, `open -n -W -i <in> -o <out> --stderr <log> --env WATANE_DRIVER_SCREEN=hidden
  Bob.app --args --home "$HOME/<home_name>" --port 0`, copies `<out>` to its stdout and its stdin
  to `<in>`, and on exit prints the app's stderr log to its stderr; (6) starts the web host,
  `/usr/bin/python3 -m http.server 0 --bind <host ip> --directory <alice home>/dist/site`, where
  the host ip is the address of the VM network's bridge interface (the guest's default gateway,
  `route -n get default` in the guest) and `<alice home>` a new empty temp folder (stock Apple
  python: the host firewall lets Apple-signed programs listen; probed 2026-11-19); (7) runs
  `cargo test -p watane-app --features driver --test it two_machines:: -- --ignored` with
  `WATANE_VM_BOB` (an ssh command running `sh bob.sh` in the guest, `ssh -T`, the same options as
  `remote`), `WATANE_VM_ALICE_HOME` and `WATANE_VM_SITE_BASE` (`http://<host ip>:<port>/`);
  (8) prints the test's output, then `TWO-MACHINES PASS` when it passed, else the first failure.
  The foreman runs this once on the real VM; the check of AC3 is that run.
- AC4 On every exit: the web host and any ssh bridge are killed, the run's VM stopped and deleted,
  the temp folders (Alice's home included) removed.
- AC5 `shellcheck -s sh` passes on `vm_lib.sh`, `vm_mac.sh`, `vm_two_machines.sh` (add them to
  clean_mac.rs's shellcheck list).
- AC6 install/TECHNICAL.md gets 12.6 "Two machines (S55)": what the script does (AC3), what it
  proves (two homes, two network stacks, no shared file system) and does not (NAT across the
  internet, the release app's consent window), the three variables of s55-1, and the exit text of
  AC2; 12.3 says the shared helpers live in `vm_lib.sh`; 12.5's table gets the row; AGENTS.md's
  commands list the script.

## Interface
Takes from s55-1 (fixed): the test `two_machines::ac1_j3_two_machines` in `watane-app`'s `it`
binary (feature `driver`), and the variables
- `WATANE_VM_BOB`: a shell command; `sh -c "$WATANE_VM_BOB <home_name>"` starts Bob's driver app
  with home `~/<home_name>` in the guest and connects its stdin/stdout to the driver channel; it
  exits when its stdin closes and the app quit. Home names used: `.watane`, `bob-tamper`.
- `WATANE_VM_ALICE_HOME`: an existing empty folder on this Mac; Alice's home.
- `WATANE_VM_SITE_BASE`: the URL, ending in `/`, at which the web host serves
  `$WATANE_VM_ALICE_HOME/dist/site` to the guest.
