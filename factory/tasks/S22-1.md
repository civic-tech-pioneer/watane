## Goal
Every file pkg reads from a mod folder is opened once, without following a link in any part of
its path below the mod folder, and checked and read through that same handle. `pack` refuses a
link anywhere under a hidden folder (`ui/.git/x`) as it refuses any link, while hidden regular
files stay out of the package. The on-disk fixtures `reading-list` and `recommendations` pack as
they stand, the on-disk fixture `hello` packs to the golden id of 6.5 and 7.3, and the error for
an empty or cut-off release body says "release" once.

Decided here (not by you): the no-follow walk uses `rustix` (safe `openat`), which is already in
the workspace `Cargo.lock` through `tempfile`; no `unsafe`. The mod folder itself (the path the
caller passes, such as `/tmp/x` on macOS where `/tmp` is a link) is opened normally; only the
parts below it are opened with no-follow.

## Acceptance
Each criterion's test at the lowest level that shows it (`factory/README.md`, "Test pyramid"):
unit tests in the crate for the private open function and `read_file`, `pkg/tests/` for the rest.
- AC1 Hidden folder link. `pack` of a valid mod with a regular dir `ui/.git/` holding a link `x`
  (to a file inside or outside the folder) → `PackageError::Symlink { path: "ui/.git/x" }`. Also
  `ui/.a/.b/y` (link two hidden levels down) and a hidden dir under `wit/` give `Symlink` with
  that path. A link that is itself a hidden folder (`ui/.d` → a directory) stays `Symlink`
  (`ui/.d`). A hidden dir with only regular files is still left out: the package bytes and id
  equal those of the same mod without it.
- AC2 Every part no-follow. The private open function, given root and `ui/index.html` where `ui`
  is a link to a real directory holding `index.html`, refuses with `PackageError::Symlink` naming
  `ui` (the relative path up to the link); likewise for a link two levels down
  (`wit/deps/x` → dir). A FIFO as a middle part, or as the last part, returns (never hangs) with
  `PackageError::Path`. A root path that is itself a link to a real mod folder opens fine.
  `pack` uses it for every file.
- AC3 `folder.rs` reads what it checked. `read_file` opens each file once with the same no-follow
  walk and takes size and file type from the opened handle; no `symlink_metadata` followed by an
  open of the same path remains in it. Unit tests: a link at `mod.toml` → `Invalid` with rule
  `path` and today's text (`replace the symbolic link with a regular file`); a FIFO at `mod.toml`
  → `expected a regular file`, without hanging; a missing optional file → `Ok(None)` as now.
- AC4 Fixtures pack. `pack(tests/fixtures/reading-list, false)` and
  `pack(tests/fixtures/recommendations, false)` succeed on the files as committed, with a
  committed `logic.wasm` each, produced once by the independent producer that
  `tests/support/release.rs::built_fixture` uses (dummy module → component), never by pkg. Keep
  one way to regenerate them: an `#[ignore = "regenerates fixtures"]` test that writes both files.
  Tests that built these per run (`release_check`, `release_golden`, ...) use the committed files
  where they only need a packable mod. `Release::new` on `recommendations` still gives
  `LocalProvider { slug: "reading-list" }`.
- AC5 Hello golden. `pack(tests/fixtures/hello, false)` has the id of 6.5
  (`0866e9df…f62ff87b`) and its release encodes to the 73 bytes of 7.3 (today it differs:
  `ui/app.js` is extra). Make the fixture match 6.5 (move `app.js`, if a test needs it, into that
  test's own fixture or tempdir); 6.5 then names the on-disk fixture. A test asserts both.
- AC6 Release error reads once. `Release::decode(&[])` and `decode` of the first 10 bytes of the
  7.3 golden each give an error whose `Display` contains `release` exactly once and names the
  cause (end of input). Today: `bad release body: release: end of input bytes`. Other
  `Malformed` texts that repeat a word the same way are fixed alike; existing message tests stay

- AC7 `cargo test -p watane-pkg`, `cargo clippy -p watane-pkg --all-targets -- -D warnings`,

## Interface
No public signature, variant or byte format changes. `PackageError::Symlink { path }` and
`PackageError::Path` keep their shapes; `ModError` keeps its rules and texts. The no-follow open
is one private function shared by `package.rs` and `folder.rs`, returning `std::io::Result` plus
the relative path of the part that failed, so each caller maps it to its own error type; put it
in a new private module `pkg/src/open.rs` (one `mod` line in `lib.rs`) or in `folder.rs`.
Unix: `rustix::fs::openat` with `OFlags::NOFOLLOW` (plus `DIRECTORY` for middle parts,
`NONBLOCK` for the last), `ELOOP` (and macOS `EMLINK`) → link, a non-directory middle part or
non-regular last part → `Path`. Add `rustix = { version = "1", features = ["fs"] }` under
`[target.'cfg(unix)'.dependencies]`; drop `libc` if nothing uses it any more. Non-unix: a plain
open plus the metadata check, as today.
