Subsystem: host
Effort: high
Slice: S1 — Hello page: a coding agent runs `watane-dev new hello`, then `watane-dev serve --json`, opens `result.pages[0].url` and sees the template page.

## Goal
The program `watane --preview <dir>` exists. It opens (or creates) a preview home, listens on
loopback, prints the ready line, writes `run.json`, and answers `GET /api/status` and
`POST /api/install` of page-only mod folders. Each installed mod's page is served at
`http://<local>.localhost:<port>/` with the content policy and headers of section 8.3. Installing a
folder again with the same slug updates it in place, so the page shows the new bytes. SIGTERM stops
it and removes `run.json`. This is the thin page-only cut of host stages 3, 5 and 6: no Wasm, no
state, no `/call`, no tools.

## Acceptance
- AC1 `watane --preview D` on a missing or empty `D` creates `D/home.json` (`{"watane_home":1,"mode":"preview"}`)
  and `D/lock`, prints exactly one stdout line that parses as `Ready` with `mode` "preview",
  the absolute `home`, the bound `port` (default port 0 = an ephemeral port), `api` =
  `http://localhost:<port>/api/`, `mcp` null, `token` null, `mods` []; then writes
  `D/run.json` = `{"watane":1,"pid":<pid>,"port":<port>,"mode":"preview"}`.
- AC2 `GET http://localhost:<port>/api/status` answers 200
  `{"watane":1,"mode":"preview","home":"<abs D>","port":<port>,"app":false}` with
  `Cache-Control: no-store`; the same request with an `Origin` header answers 403
  `{"error":{"code":"forbidden",...}}`; a `Host` header other than the API hosts and
  `<local>.localhost:<port>` answers 421.
- AC3 `POST /api/install {"folders":["<abs dir of a page-only mod>"]}` answers 200
  `{"installed":[InstalledMod]}` with `local` = slug (3.2 derivation), `identity` "local/<slug>",
  `page` "http://<local>.localhost:<port>/", `has_logic` false, `enabled` true; the folder's files
  are under `D/mods/<local>/` and `D/installed.json` names it. A relative path is 400 `bad_request`;
  a folder that `Mod::read` refuses is 422 `invalid_mod` with pkg's text; a folder with a logic part
  (world exports anything) is 422 `invalid_mod` ("logic parts arrive in a later step").
- AC4 `GET /` and `HEAD /` on `Host: <local>.localhost:<port>` answer the bytes of `ui/index.html`,
  `Content-Type: text/html; charset=utf-8`, and every header of 8.3, the CSP byte for byte; `/app.js`
  is `text/javascript; charset=utf-8`. The path refusals of 13.2 (`/../x`, `/a//b`, `/.env`,
  `/%2e%2e/x`, `/a\b`) and an unknown local name answer 404 `text/plain; charset=utf-8`. Both
  `127.0.0.1` and `[::1]` serve the page.
- AC5 Installing the same folder again after an edit of `ui/index.html` keeps the local name, and
  `GET /` answers the new bytes.
- AC6 SIGTERM: the process exits 0 within 5 s and `D/run.json` is gone; the port refuses connections.
  A second `watane --preview D` while one runs prints `{"watane":1,"error":{"code":"busy",...}}` and
  exits 1. `watane --version` prints `watane 0.1.0`; a bad argument exits 2 (code `usage`); in this
  slice `watane` without `--preview` is also a usage error (home mode joins later).
- AC7 `cargo test`, clippy with `-D warnings` and `cargo fmt --check` pass. Tests use `reqwest`
  with `resolve("<name>.localhost", addr)` so the `Host` header is real, and run the binary through
  `env!("CARGO_BIN_EXE_watane")`.

## Interface
Takes from `watane-pkg` (task S1-1, already on this branch): `Mod::read`, `Mod::{slug, version,
name, summary, page, logic, world, grants, origin}`, `Slug`, `Version`, `PackageId::of`,
`PublisherKey`, `ReleaseRef`, `Grant`, `ModError` (shown by `Display`).
Provides, fixed (dev task S1-3 builds against them, names and fields exactly as in 2.1 and 2.4):
- `pub struct RunInfo { pub watane: u32, pub pid: u32, pub port: u16, pub mode: String }` +
  `RunInfo::read(home: &Path) -> Result<Option<RunInfo>, HostError>` (None when `run.json` is absent).
- `pub struct Ready { pub watane: u32, pub mode: String, pub home: PathBuf, pub port: u16, pub api: String, pub mcp: Option<String>, pub token: Option<String>, pub mods: Vec<ReadyMod> }`,
  `pub struct ReadyMod { pub local: LocalName, pub page: Option<String> }`; both Serialize + Deserialize.
- `pub fn default_home() -> Result<PathBuf, HostError>`.
- `LocalName`, `HostError` (with `code()`, `status()`), `InstalledMod` (Serialize + Deserialize).
- The program's arguments (12.2), `/api/status` and `/api/install` as in section 11.

## Decisions already made (foreman)
- Install without pack/unpack (pkg stage 5 comes later): copy `mod.toml`, `deps.json` if present,
  `wit/` and `ui/` of the folder into `staging/<16 hex>/`, read it with `Mod::read`, then rename
  into `mods/<local>` as 4.3 step 4 says. Mark it `// ponytail:` as the stand-in for
  `pack(dir,false)` + `unpack`.
- `package` (the `PackageId` in `InstalledMod` and `installed.json`): `PackageId::of` over the copied
  files in sorted relative-path order, each as `<path>\0<len as u64 LE><bytes>`. A stand-in until
  `pack` exists; mark it `// ponytail:`. `Change` is `Unchanged` when that id equals the installed one.
- `installed.json` `grants` and `links` are `[]` for page-only mods.
- `/api/install` in a preview needs no confirmation (W5); `Requester` and `Confirm` are not built yet.
