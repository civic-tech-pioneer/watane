## Goal
A machine that has just joined Alice's machines learns the addresses of the other machines on the
list, so it can reach her server even when the anchor is off and mDNS is off. Today the `pair`
answer carries only the device list (net/src/wire.rs `pair_answer`), and `pairing::pull` (the
`devices` request, whose answer carries addresses, net TECHNICAL 5.10) runs only when a peer's
hello shows a newer seq (client.rs ~266) or a newer list is pushed (serve.rs ~176). A joiner that
is already at the newest seq never pulls, holds only the anchor's address, and `full_machines`
(light.rs ~68) skips the server. Fix: after a successful `join`, the joiner pulls `devices` once
from the anchor it paired with (the existing `pairing::pull` path) and stores the addresses it
gets, before `join` returns. No wire format change. Found by J8 (app/tests/j8.rs AC4).
