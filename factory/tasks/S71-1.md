## Goal

`watane-dev publish --push --owner <account>` lets a maker publish under a GitHub organisation (or
any account other than the one `gh` is logged in as). The repositories dev names itself become
`<owner>/<slug>` (the mod) and `<owner>/watane-channel` (the channel), and the fork of a derived
mod (10.4.2) is created in `<owner>` by adding `-f organization=<owner>` to the fork request when
`<owner>` is not the `gh` login. Without `--owner`, everything is as today (the owner is the
login). `fake-gh` learns `organization=` so the fast suite checks it. Separately, dev's timing test
`ac10_endless_test_stops_with_exact_message_within_deadline` is made to time the stop, not a cold
build.

## Acceptance

AC1 CLI: `publish` gains `--owner <account>` (help: "GitHub account or organisation for the
repositories dev creates [default: the gh login]"). `--owner` without `--push` is a usage error
naming `--push` (exit status of a usage error, TECHNICAL 2.2). An `<account>` that is not 1..=39
ASCII letters, digits or single inner hyphens (GitHub's rule: no leading/trailing hyphen) is a usage
error naming the value. Every `next`/`fix`/rerun that publish builds with `--push` also carries
`--owner <account>` when it was given (the rerun string built around cli.rs:781, and the provider
`next` around cli.rs:761).

AC2 Naming: with `--owner acme` and fake-gh user `alice`, a first `publish --push` of a mod without
`repository` creates `acme/<slug>` and `acme/watane-channel` (fake-gh remotes under `acme/`), writes
`repository = "https://github.com/acme/<slug>"` into mod.toml, and pushes both. Without `--owner`
the same run creates `alice/...` (the existing tests stay green unchanged).

AC3 Fork into the owner: a derived mod (`[origin]`, `remote.upstream` on GitHub) published with
`--owner acme` while the gh login is `carol` runs
`gh api -X POST repos/<upstream>/forks -f name=<slug> -f organization=acme -F default_branch_only=true --jq .full_name`;
the result is `forked: true`, the fork lives at `acme/<slug>` with its parent set, its default branch
is `watane`, and `mod.toml` names `https://github.com/acme/<slug>`. When `--owner` equals the login
(case-insensitively, as GitHub logins are), no `organization` field is sent (the command is exactly
today's). The "account already has a fork" fallback and the `publish.fork_unavailable` warning work
the same in the owner account.

AC4 fake-gh (`dev/src/bin/fake-gh.rs`): the fork request accepts an optional
`-f organization=<org>` between the `name=` field and `-F default_branch_only=true`. With it, the
fork goes under `<root>/<org>/` (the existing-fork scan looks there), and the printed full name is
`<org>/<name>`. `organization=` equal to `FAKE_GH_USER` is refused with exit 1 and a stderr line
naming the field (dev must not send it for the login). Without it, as today. Add unit or
integration coverage for both arms in dev's tests (dev/tests/share.rs has the fake-gh fixture).

AC5 Docs: `dev/template/AGENTS.md` (around line 147) says that to publish under an organisation the
agent adds `--owner <org>`; dev/TECHNICAL.md 10.4.1 and 10.4.2 describe `--owner` (naming, the
`organization` field, default = login, the usage errors); dev/FUNCTIONAL.md where it describes
`publish --push`, one sentence.

AC6 Timing test: `dev/tests/unit_tests.rs::ac10_endless_test_stops_with_exact_message_within_deadline`
times only a run whose build is already cached: run `test` once on the endless source untimed
(asserting the same `test.unit_limit` result), then time a second run of the same source against
the 7 s deadline. `ac11_endless_test_stops_with_exact_message` keeps its 60 s guard and its single
run. Update its row in dev/TECHNICAL.md (DEV-S-16) to say what is timed.
