## Goal

This task closes the adversary's round-7 breaches (65900bf, 94e276b, formatted in dda15cb). `fetch_from_providers`
reads a channel through 5.11 provider bases (hints from listings, or a listed record's fallback bases) and returns
`Fetched.link` at that base, but no record or tombstone ever notes the base in `seen`. A `follow(Fetched.link)`
(the app's follow_fetched, DD-29) then finds the base unseen, gives it, and its redirects reach the local network.
Rule, inside DD-48: every base dist reads in `fetch_from_providers` is a base the record (or the channel's
tombstone) saw. Before the first request to each base, note it in `seen` with `note_seen` (so a full `seen` sets
`seen_full`): in the channel's record when there is one, or else in the channel's tombstone, creating one
(`seen: [base]`, `given: []`, `at: now`) when the channel has none. Save it through the one write path
(`save_staged`, staged with the tombstones as in F2.4) before the read. A later link at that base is then a listed
first read and gives nothing; a link at a base the participant gave, or at a channel's base no listing or hint
named, is unchanged.
