## Goal

Every identity operation of a `Log` (read, create, replace and remove the key, and the temp file
of a write) and the creation of the store file act on the **checked directory handle**, not on a
path that is looked up again. Today `log/src/identity/unix.rs` checks the directory, then opens,
renames and unlinks `dir.join(..)` by path, so a parent folder swapped between the check and the
use redirects those operations (S112 R1.1). After this task, on Unix, the directory is opened once
with `O_DIRECTORY | O_NOFOLLOW`, checked with `fstat`, locked, and every later file operation is
`openat` / `renameat` / `unlinkat` / `fstatat` relative to that descriptor (rustix, already a
dependency). The parent path is not re-checked.

Decisions fixed here (the foreman's):
- Parents writable by others are **not** refused: with every operation relative to the held,
  checked handle, a swapped parent no longer redirects anything, and refusing would break homes
  under `/tmp`-like folders. TECHNICAL 4.7 says so in one sentence.
- SQLite opens `channels.db` by path (it needs the directory for `-wal` and `-shm`); a handle-
  relative open needs a VFS and is out of scope. The store file is *created* with `openat`
  (mode 0600, `O_CREAT|O_EXCL|O_NOFOLLOW`) on the checked handle; then, on Linux, SQLite may be
  opened through `/proc/self/fd/<dirfd>/channels.db` only if that keeps WAL working, else by path.
  Whichever is built, TECHNICAL 4.7/4.8 states what remains path-based, and section 7 / "Not
  protected" says the SQLite open is by path.
- Windows: the handle already held by `lock_directory` is the anchor. Do the same on Windows only
  if you can type-check it here (try `rustup target add x86_64-pc-windows-gnu` and
  `cargo check -p watane-log --target x86_64-pc-windows-gnu`); if that cannot run in this
  container, leave Windows unchanged and say in log TECHNICAL 4.7 that the Windows half is open
  (one line), and report it. Do not push Windows code you could not compile.

## Acceptance

1. AC1 (Unix) After `lock_dir`, swapping the log directory's path for a symlink to another private
   folder (rename the real one away, put a link in its place) and then running the key write,
   replace, and remove steps writes, renames and unlinks only inside the originally checked
   directory: a unit test calls the internal functions with the held handle across the swap and
   asserts the other folder is untouched and the original holds the result.
2. AC2 `read` of the key is `openat(dirfd, "identity.key", O_NOFOLLOW|...)` and the existing
   checks (`NotPlain`, `KeyLinks`, `Exposed`, `KeyMode`, `KeyOwner`, `CorruptKey`) keep their
   existing tests green.
3. AC3 The temp file `.identity.key.<hex>.tmp` is created with `openat(.., O_CREAT|O_EXCL|
   O_NOFOLLOW, 0600)` and on failure removed with `unlinkat` on the same handle; publication is
   `renameat` on the same handle, then `fsync` of the handle.
4. AC4 The store file is created through the handle as in Goal; every existing log test passes.
5. AC5 `log/TECHNICAL.md` 4.7 (and 4.8 if the store open changes) describe the handle-relative
   operations, the not-refused parents, and what stays by path; `log/TECHNICAL.md` 6 lists any new
   rustix feature. Each `//!` line still cites its section.
6. AC6 `cargo test -p watane-log` default and `-- --include-ignored`; `cargo test -p watane-dist`
   still passes (it opens logs); clippy and fmt clean.
