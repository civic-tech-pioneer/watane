## Goal
`install.sh` tells Alice the truth at each of the six spots S50b-fix, S50b-fix2 and S50c's user-sims
found (factory/PLAN.md, `### install`; each re-checked against main on 2026-11-20 and still present):
a Ctrl-C after the receipt commit, or while the toolchain question waits, says that watane is
installed and what to run next; `--status | head -1` ends with no `printf: write error` line;
`skipped` and refusal lines name a path inside the home as `~/...` even when the home resolves
elsewhere (`/var` -> `/private/var` on macOS); the "install it later" command names the URL the
offer named (`WATANE_RUSTUP_URL` when set for offer A); an interrupted fresh install leaves no
empty `~/.local/bin`, `~/.local/share/watane-dev` (or other folder the run created); rustup's own
output is set apart from watane's lines. Each text is defined in TECHNICAL.md first (AGENTS rule 3).

## Acceptance
AC1. A fresh install whose `INT` arrives after the receipt was committed (3.6 step 5 onward, before
     the success block) exits 130, leaves the new version installed, and prints on stderr the line
     `watane <version> is installed; the run was interrupted before it finished.` followed by
     `Run watane-dev doctor to check the maker tools.` (exact texts: define them in 3.8/3.9; these
     are the recommended ones).
AC2. An `INT` while the toolchain question waits (offer shown, no answer typed) exits 130 and prints
     the same two lines as AC1 (watane is installed at that point), plus the "install it later"
     commands of 3.7 for the current state.
AC3. `install.sh --status | head -1` (a receipt present) prints exactly the first status line and
     nothing on stderr; exit is 141 (3.9's PIPE code) or 0, and TECHNICAL 3.9 says which.
AC4. With `HOME` given through a symlinked path (test: `HOME=<tmp>/link` where `link` -> real home),
     each `skipped ...` and `... resolves to ...` line names paths inside the home as `~/...`, both
     the entry and the resolved target; a path outside the home stays absolute.
AC5. With `WATANE_RUSTUP_URL=<url>` set, state `none` offer A, answer `N`: line 3 of the
     "install it later" block is `  curl --proto '=https' --tlsv1.2 -sSf <url> | sh -s -- -y ...`,
     the same URL the question named. Unset: unchanged (`https://sh.rustup.rs`).
AC6. A fresh install (no `~/.local` before) interrupted (`INT`/`TERM`) before the commit leaves no
     folder the run created: `~/.local/bin`, `~/.local/share/watane-dev`, `~/.local/share/watane`,
     `~/Applications` (if the run created it), and `~/.local` itself if the run created it. A folder
     that existed before the run is never removed. Same for a run that failed (exit 3-5) before commit.
AC7. On offer A with `y`, rustup-init's stdout and stderr appear between a line
     `--- rustup's own output follows ---` and a line `--- end of rustup's output ---` (define the
     exact texts in 3.7); rustup's status still decides exit 6 and the signal mapping (3.8) as now.
AC8. The status audit (`tests/it/status_audit.rs`) and `shellcheck -s sh install.sh` still pass;
     every new program call follows 3.8's status rules.
