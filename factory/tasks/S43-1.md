## Goal
When a released package names a `repository`, `watane-dev new <slug> --from <link>` clones that
repository at the ReleaseRef tag, checks the checkout against the verified package, keeps only the
package's files (plus `.git/`), renames `origin` to `upstream` and puts the history on branch
`main`; the result carries `fork`. A clone that fails, or that differs from the package, is removed
and the mod is made from the package as today, with the warning `new.fork_unavailable` or
`new.fork_differs`. The derived mod's first `publish --push` then makes its repository a GitHub fork
of `upstream` (the forks POST), on branch `watane`, which becomes the fork's default; where GitHub
refuses (one fork per account, no upstream on GitHub) it creates a new repository and warns
`publish.fork_unavailable`. `fake-gh` gains the fork and edit calls. This is dev build stage 11.
