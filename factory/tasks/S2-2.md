Effort: high
Slice: S2 — The page calls its logic: a coding agent runs `watane-dev new hello` and `serve --json`; Alice opens the page, clicks its button, and sees the count go up.

## Goal
The host runs logic parts (host stage 1, runtime core). A preview installs a mod folder that has a
built `logic.wasm`, compiles it, and `Host::call` runs one of its exported functions with JSON
arguments and returns JSON. Each call gets a fresh instance with no device access, bounded fuel,
memory and wall time, and the private state of its mod, which commits only when the call
succeeds. State is kept in `state/state.redb`, keyed by the mod's identity. The package
`watane:host@0.1.0` exists as `wit/host.wit` and the constant `HOST_WIT`. An own-package event
import (outlet, `World::events`) links, and its functions do nothing yet (events land in S3).

  something undeclared, is 422 `invalid_mod` with pkg's text. A mod with `calls` or `subscriptions`

- AC3 (FUNCTIONAL S4) `counter`: `api.add` twice returns 1 then 2; `api.get` returns 2;
  `api.add-then-fail` fails with code `trap`; `api.get` still returns 2.
- AC4 Restart: drop the host, open it again on the same home: `api.get` returns 2 (component
  compiled again at open; state persisted). After `drop`, the test opens `state/state.redb` itself
  with redb and reads table `s/<id>`, `id` = first 32 hex of `blake3("local/counter")` computed in
  the test, and finds key `count`.
- AC5 State isolation: a second fixture mod (`echo` or another) writing the same key does not see
  or change `counter`'s value. Reinstalling `counter` from the same folder keeps its state.
- AC6 (S6) `hog` `api.spin`: code `limit`, limit `fuel`, within 10 s.
  (S7) `api.grow(2000)`: limit `memory`. (S8) with `Limits { time: 200 ms, fuel: u64::MAX, .. }`:
  `api.spin` fails with limit `time` after >= 200 ms and < 2 s. After each, a call of another export
  of the same mod still answers.
- AC7 (S9) `hog` `api.probe` returns `["no-dir","no-env","no-socket"]`.
- AC8 JSON encoding (6.9): `echo` round-trips one value per row of the table through `Host::call`
  (literal JSON in and out), arguments by object, by array and `null`; `opt-opt` is `no_function`;
  `1.0` for an integer, an unknown record field, a wrong tuple length, and an out-of-range `u8` are
  `bad_request` with the path in the message (e.g. `$.x: ...`). Unit tests in `src/runtime/json.rs`
  cover each row both ways with literal `Val` trees.
- AC9 Errors of `call`: unknown local → `no_mod`; a mod with no logic part, an unknown interface or
  function → `no_function`. `CallError` serializes as `{"code":"limit","limit":"fuel","message":..}`
  (`limit` only for code `limit`).
- AC10 State limits: a `put` with a key over `key_bytes` or a value over `value_bytes` fails the
  call with `limit`/`state_size`, and nothing is written (test with lowered `Limits`).
- AC11 `cargo test`, clippy `-D warnings`, `cargo fmt --check` pass. Fixtures are built by

## Interface
Takes from pkg (task S2-1): `Mod::check_component(&self) -> Result<(), ModError>`.
Provides, fixed:
- `pub const HOST_WIT: &str` (dev task S2-4 writes it to `wit/deps/watane-host/host.wit`).
- `Host::open(home: &Path, limits: Limits) -> Result<Arc<Host>, HostError>` (S2 cut: still preview
  only; `Mode` joins with home mode). The program passes `Limits::default()`.
- `Host::call(&self, caller: &Caller, local: &LocalName, function: &str, args: serde_json::Value) -> Result<Value, CallError>`
  (blocking, needs a 16 MiB stack) and
  `Host::call_async(self: &Arc<Self>, caller: Caller, local: LocalName, function: String, args: Value) -> Result<Value, CallError>`
  (runs `call` on a new thread with a 16 MiB stack). Task S2-3 builds `/call` on `call_async`.
- `pub enum Caller { Page }` (Agent and Mod join with their slices); `who()` returns "page".
- `pub struct Limits { pub fuel: u64, pub memory: usize, pub time: Duration, pub key_bytes: usize, pub value_bytes: usize, pub call_write_bytes: usize, pub quota_bytes: u64 }`
  with the defaults of 6.2 (depth, hops, deliveries join with links and events).
- `CallError { code: CallCode, message: String }`, `CallCode`, `Limit` as in 2.2, with
  `CallError::status() -> u16` (the `/call` table of 2.2) and `Serialize` in the JSON form of 2.2.
