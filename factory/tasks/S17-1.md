Subsystem: dev
Effort: medium
Depends on: none
Slice: S17 — The simplest tool to start with: a maker's coding agent (Claude or Codex, sandboxed or not) gets from an empty folder to a served mod with fewer commands and fewer errors, without reading watane's source.

## Goal
watane-dev's own output answers what S16's Codex had to read source for. `--help` describes
every command and option. A missing vendor folder says "missing" and its fix works from inside
the agent's own sandbox: the agent can fill a vendor folder in the watane-dev cache, which dev
finds without an exported variable. Doctor's text mode reads as text, not raw JSON, and its
`next` on a gap says to run the fixes. `mod.invalid` WIT errors carry the line the parser gave.
A refused serve's `preview.previous` names the page, not the API. `serve --stop` says, before
and after, that it deletes the preview's data. The red test
`regress_s16_missing_vendor_says_missing` passes and loses its `#[ignore]`.

## Acceptance
- AC1 Help: `watane-dev --help` shows a one-line description after every command (`new`,
  `check`, `doctor`, `test`, `add`, `serve`) and every option (`--json`, `--dir`); each
  command's `--help` describes its own arguments and options (`new <slug>`, `add <provider>`,
  `serve --stop`). `serve --help` says `--stop` stops the preview and deletes its data. One unit
  test in `cli.rs` walks `Cli::command()` and asserts every subcommand has `about` and every
  argument (except clap's own help/version) has `help`; it fails if a new option has none.
- AC2 Missing vendor: with `WATANE_DEV_VENDOR=<p>` and no folder at `<p>`, `doctor --json`
  exits 3 with `env.allowlist`, message exactly `the crate allowlist at <p> is missing`
  (TECHNICAL 2.2), fix `'<abs dev>/scripts/vendor.sh' '<p>'` (no export: the variable is already
  set). The red test `regress_s16_missing_vendor_says_missing` in `tests/doctor.rs` passes with
  its `#[ignore]` removed and its body unchanged. A vendor folder that exists but differs keeps
  the "differs from the allowlist of this watane-dev: <detail>" message.
- AC3 Vendor from the agent's folder: `scripts/vendor.sh [<out>]` writes the vendor folder to
  `<out>` (a relative `<out>` is taken from the caller's folder, not from `dev/`) and to
  `allowlist/vendor` with no argument; it writes nothing else in the watane checkout. dev's
  lookup order (TECHNICAL 6.2) becomes: `WATANE_DEV_VENDOR`; installed
  `share/watane-dev/vendor`; source-tree `allowlist/vendor`; `<cache>/vendor` (the
  `WATANE_DEV_CACHE` folder, section 3). The first that exists is used and verified as today.
  When none exists (no variable set), the error names `<cache>/vendor` as `<path>` and the fix is
  `'<abs dev>/scripts/vendor.sh' '<abs cache>/vendor'`: one command, no export, so it works for
  an agent that can write its cache but not the watane checkout. Unit tests in `allowlist.rs`
  cover the order and both fix texts with literal expectations; one integration test runs the
  real script into a temp `<out>` only if it can use the local registry cache (`--offline`
  fallback), else it is `slow:`.
- AC4 Doctor text: without `--json`, doctor prints per TECHNICAL 2.3 with no JSON syntax in
  `key: value` lines: a nested object becomes one line per field with a dotted key
  (`allowlist.vendor: /abs/...`, `toolchain.wasm32_wasip2: true`), a list is joined with `, `,
  strings are unquoted, null prints `missing`. This is in the shared text printer
  (`outcome.rs`), so every command's text gets it. On a gap, doctor's `next` is
  `Run each error's fix, then run: watane-dev doctor --json`. Unit tests of the printer with
  literal expected text.
- AC5 WIT line: a `mod.invalid` error whose pkg message holds a wit-parser location
  (`--> <file>:<line>:<col>`) reports that `line` and `column` (and that file, relative to the
  mod, when pkg's `file` is less specific). A test with a world that has a syntax error on a
  known line asserts the line. Do not change pkg. If pkg's message for that case carries no
  location, say so in your report and leave `line` null.
- AC6 Contract line: a `test.contract` failure reports the 1-based line in its file where the
  failing step's object starts, if you can do it in about 40 lines with no new dependency
  (for example `serde_json::Deserializer` byte offsets or a small scan of the `steps` array that
  skips strings). If not, keep `line: null`, update TECHNICAL 2.4 to say `step` is the location,
  and say why in your report. Either way a test asserts what is reported.
- AC7 preview.previous: the warning's message names the served mod's page URL
  (`the preview at <page url> still serves the previous build`), and the API URL only when the
  mod has no page. Update the existing test and TECHNICAL 2.2 / 9.3.
- AC8 Next on env gaps: every command whose first error is `env.*` (`test`, `serve`, `check`
  if it can) has `next` `watane-dev doctor --json`; doctor itself as AC4. A unit or integration
  test per command that reaches an env error today.
- AC9 `dev/AGENTS.md` "Commands": the slow-set line drops `--skip regress_s16_missing_vendor_says_missing`,
  and `scripts/vendor.sh` shows the optional `<out>`. One spec-gap line for S17-1.
- AC10 `cargo test -p watane-dev` (default run) stays under 2 minutes; clippy
  (`--all-targets --all-features -D warnings`) and `cargo fmt --check` pass.

## Spec
`dev/TECHNICAL.md` 2 (command line), 2.2 (`env.allowlist` row, `preview.previous`), 2.3 (text
output: write the dotted-key rule there), 2.4 (doctor and contract `next`/locations), 3 (cache
layout: add `vendor/`), 6.2 (lookup order, fixes), 9.3 step 1. Update each in place; they own the
facts. `factory/harness-codex.md` "Lines for S17" for the why. `factory/README.md` "Test pyramid".

## Interface
To S17-2 (the template `AGENTS.md`, built beside you): the vendor fix is
`'<abs dev>/scripts/vendor.sh' '<folder>'`, and dev finds `<cache>/vendor` without any variable.
The serve result shape (TECHNICAL 2.4 `serve`: `api`, `pages[].url`, `mcp.url`, `mcp.token`)
does not change. Do not edit `dev/template/`.

## Files
`dev/src/cli.rs`, `outcome.rs`, `doctor.rs`, `allowlist.rs`, `check.rs`, `contract.rs`,
`preview.rs`, `env.rs`; `dev/scripts/vendor.sh`; `dev/tests/*.rs` (and `tests/support/`);
`dev/TECHNICAL.md`, `dev/AGENTS.md`. Not `dev/template/`, not `host/`, `app/`, `pkg/`
(S12a builds host and app beside you).

## Out of scope
The template `AGENTS.md` (S17-2). MCP `readOnlyHint` annotations (an open question; the human
decides). A `pack` or `install` command (S12b). Changing the serve result shape.
