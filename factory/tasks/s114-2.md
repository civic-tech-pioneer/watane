Slice: s114 — A maker previews an OpenAI-backed mod on scripted responses

## Goal

A maker uses `serve` to run a development preview against the default scripted OpenAI reply or a supplied script.

## Acceptance

1. A mod declaring the OpenAI host automatically gets the built-in script.
2. `--script` takes precedence over the root mod's `scripted-responses.json`. An invalid script reports its path and a fix. `--stop` and `--script` conflict.
3. Serving with an unchanged script reuses the preview. Changed scripts restart it. Stopping the preview removes its data and ends the fake.
4. A maker can read the scripted items through a mod's normal preview interface.

## Spec

spec/FUNCTIONAL.md F-MAKE-4, dev/TECHNICAL.md §9.3, §17 question 15 and §18.3–18.4.

## Interface

`watane-dev serve [--script <file>]` selects the script. Unix development host CLI: `watane --preview <dir> --scripted-openai <program> [--openai-script <file>]`.

## Files

dev/TECHNICAL.md, dev/src/cli.rs, dev/src/preview.rs, dev/src/preview/, dev/tests/it/ with a module registration line.

## Changed tests

None. Existing serve tests without the OpenAI host or a script keep their expectations.

## Out of scope

Changes to agentic-harness, the standalone fake, and the Windows preview support.
