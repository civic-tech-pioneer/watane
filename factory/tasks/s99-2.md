## Goal
A mod with the `claude-code` grant starts Claude Code with a launch document, in a scratch workspace
the host makes for it, and consumes the stream: the host checks the launch, starts the program (in a
preview the one `set_fake_claude` names; in a home the one `AccountSource::claude_binary` gives), runs
`initialize` and the `init` match, pushes `initialized` with the workspace id, then every stdout line
as an item (host items wrapped). `claude-session.say`, `interrupt` and `compact` write to stdin after
the chain commits. `host-info.generation()` tells a mod the host restarted. Also the stage A2
leftovers: the `caller` doc comment, the connection-replaced message of `watane.js`, and R7. This is
S99's half of stage A2 exactly as host TECHNICAL 15, "A2 in two slices", lists it; asks and checks
are S100's.

  --strict-mcp-config --system-prompt-snapshot=off --settings=<json>`, then one `--flag=value` each.
  The host's `initialize` is `{"type":"control_request","request_id":"<id>","request":{"subtype":"initialize"}}`

  {"subtype":"success","request_id":"<id>","response":{...}}}`. `say` writes

  stream-json); write them into 19.3 if a shape there is not yet written out.
- The idle line that ends a turn (19.3 step 6) is `{"type":"system","subtype":"session_state_changed","state":"idle"}`;
  the host passes it unchanged.
