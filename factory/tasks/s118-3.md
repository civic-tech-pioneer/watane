## Goal

The install consent of a mod whose data was kept no longer labels its Storage line `new`; it
says `data kept from before`.

## Acceptance

AC1: `HostConfirm` maps a `PlanEntry` with `change: New`, `kept_state: true` and `Storage` in
`new_grants` to a `PlanMod` whose storage `GrantLine` has `new: false`, `kept: true`; its other
lines are unchanged (a new `Http` grant stays `new: true`, `kept: false`).
AC2: with `kept_state: false` the storage line is `new: true`, `kept: false`, and its JSON has no
`kept` key (old fixtures and pages keep working).
AC3: the consent page renders the storage line of AC1 as
`Allow: <storage text> · data kept from before`, and never `· new` on it (the existing DOM test
harness of the consent page, as other consent label tests do).

## Spec

app TECHNICAL 6.2 (`GrantLine.kept`), 6.3 (the label), the `HostConfirm::install` bullet (all
three already amended on `slice/s118`: read them first). host TECHNICAL 4.2 step 6.

## Interface

Takes from s118-2: `watane_host::PlanEntry.kept_state: bool`. Provides: `GrantLine.kept: bool`
(`#[serde(default, skip_serializing_if = "std::ops::Not::not")]`).

## Files

app/src/confirm.rs, app/src/consent.rs, app/src/words.rs (only if the line builder needs the
flag), app/ui/consent.js, and their tests (app/src tests, app/tests/it/ page tests).

## Changed tests

Tests that build a `GrantLine` literal gain `kept: false`; JSON fixtures stay valid through
`serde(default)`. Search `app/` for `GrantLine {`.

## Out of scope

Host changes (s118-2). Any change to what is granted or withheld.
