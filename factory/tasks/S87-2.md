## Goal
The app window tests that change a full machine's package bytes pass whatever the order of
events. An honest full machine never sends changed bytes (iroh-blobs checks the file and resets
the stream), so the light machine shows one of two problem lines for that machine: `refused
<short>: ... does not match its hash` (the reset reached it as a cut stream) or `unreachable
<short>: package <hex8> was not fetched: not served: it does not have it, or its copy failed
its check` (net emits this from S87-1). The tests accept either, and nothing else.

## Acceptance
- AC1 `app/tests/it/machines.rs` `ac6_s33_corrupt_full_machine_and_no_path_name_causes`: after
  the changed bytes, `wait_machines` waits for a problem of node `short` whose text is either
  of the two lines above (starts with `refused <short>:` and contains "does not match its
  hash", or starts with `unreachable <short>:` and contains "not served"). The rest of the test
  is unchanged (the install error, no cached file, the fresh session's reachability cause).
