Slice: S117 — Windows private-directory error and ACL checks

## Goal

A Windows directory that cannot be inspected reports the operating-system
error. Directories created for private data have independently verified
owner-only ACLs.

## Acceptance

1. Query a directory handle without read-control access. Windows rejects
   the query and the owner check returns `PrivateDirError::Io`. A foreign
   owner or invalid ACL remains `PrivateDirError::Invalid`.
2. Create missing parent and leaf directories with `private_dir`. The
   `icacls /save` oracle finds a protected DACL with a single inheritable
   allow entry for the current user's SID on both directories. A separate
   owner query confirms the same SID. The leaf remains pinned by its handle.

## Spec

log TECHNICAL 4.7 and 11.

## Interface

`watane_log_windows_fs::private_dir(&Path) -> Result<File, PrivateDirError>`.
The existing `Io(io::Error)` and `Invalid(io::Error)` variants distinguish
system errors from validation failures. The public `check_owner_only`
continues to return `io::Result<()>`.

## Changed tests

The Windows helper's
`s112_private_directory_refuses_a_different_owner_sid` asserts the
`Invalid` variant as well as the existing reason and verifies that an OS
access error returns `Io`. The integration test
`s116_private_dir_creates_and_pins_a_checked_directory` checks both ACLs with
the oracle shared with `s110_key_is_private_and_reopens`, which retains its
file and owner checks.

## Out of scope
