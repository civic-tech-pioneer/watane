## Goal
A light laptop that Alice removed and that asks her server for a package is told that the server
refused it, not dist's "is not followed": node keeps the `Result` of `need_blob` (calls.rs:66)
and of `need` and returns net's refusal to the caller. On the real `watane-node`: joining with a
used code says the code was used, and joining while the anchor is off says it did not answer,
without "no direct path". node/tests/restore.rs s9 stops flaking (SiteNotWritten, about 3 in 12,
also on main): find the cause with evidence and fix it in node or in the test.

## Acceptance
- AC1 server = `watane-node run` (the real binary, full) paired to an anchor `Node`; light =
  `Node` paired light. The anchor removes the light machine; the server receives the new list
  (wait for its `machines <seq>:` line). The light machine then installs or fetches a release
  whose package only the server holds: the error's chain contains
  `node <server short> refused: not_allowed` and not `is not followed`. Test in a new
  node/tests/causes.rs (or light.rs).
- AC2 `watane-node join <code>` with a code the anchor already used exits 1 and stderr contains
  `the pairing code was used or has expired` (net's `NetError::CodeSpent` text, S80-1).
- AC3 `watane-node join <code>` while the anchor's net is off (its address in the code) exits 1;
  stderr names the anchor's short key once, does not contain `no direct path`, and says it did
  not answer.
- AC4 restore.rs `s9_alice_restores_and_picks_the_servers_hint` passes 20 of 20 runs in a row
  (shell loop; report the count and the cause you found, with evidence: the failing step and why).
- AC5 `cargo test -p watane-node` passes (with `-- --include-ignored` once); clippy and fmt clean.

Code::NotAllowed }`; `NetError::CodeSpent` Display `the pairing code was used or has expired;
make a new one on the anchor`. Returns the refusal as `NodeError::Net(..)` (or inside the dist
error it already produces, as long as the chain shows the text). A holder method (TECHNICAL 4)
still never calls net.
