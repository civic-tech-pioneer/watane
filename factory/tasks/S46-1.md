Slice: S46 — A hostile mod folder is named, not half-read: a maker or a stranger's package with
links, FIFOs or broken bytes gets one precise refusal and nothing is read past it.

## Goal
`Mod::read` names the real cause in a hostile folder the way `pack` already does: a link anywhere
below `ui/` or `wit/`, hidden folders included, is reported as that link (not as the WIT folder
rule of the directory holding it), and a FIFO or other special file below `ui/` is refused, not
passed. Every walk of the mod folder (the `inspect` walk and the part checks of `Mod::read` in
`folder.rs`; `Input::walk` and `hidden_links` in `package.rs`) lists and stats entries through
directory handles opened by the shared no-follow walk of `open.rs`, never by a path string below
the root, so no path part is followed and nothing is listed through a swapped-in link. A broken
release body says what was expected at the point it broke, and the word "release" is never
written by the reader only to be stripped again in `malformed()`.

Decided here (not by you):
- A link is rule `path` (4.7), message `replace the symbolic link with a regular entry` as now,
  `file` = the link's relative path. Below a WIT directory that 4.7 refuses (`wit/.hid`,
  `wit/other`), the walk still descends (no-follow) looking for links: if it finds any, it reports
  each link and not the directory rule; if none, the directory rule as today.
- A non-hidden entry below `ui/` that is neither a regular file nor a directory is rule `path`,
  `file` = its path, message `expected a regular file or a directory`. Hidden special files stay
  ignored, as `pack` ignores them. Inside `wit/`, behaviour is unchanged (non-`.wit` entries are
  ignored; a non-regular `.wit` is already refused).
- Release reader errors take the form `<field>: expected <what>, found <what was there>` (e.g.
  `format: expected an unsigned integer, found end of input`); the top-level array has no field
  prefix (`expected an array of 12 items, found end of input`), because `Display` already says
  `bad release body:`. `malformed()` only wraps; the call sites pass the right context.
