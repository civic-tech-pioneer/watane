## Goal
A mod that started Claude Code with `ask: true` or a `pre-tool-check` sees each tool request of
`claude` as an `ask` or `check` item that the host built itself (never `claude`'s bytes), answers
it with `claude-session.answer`, and sees each one close with exactly one `ask-resolved` item
(`answered` with its `outcome`, `expired`, or `cancelled`). An ask nobody answers is denied at its
`expires-at`; a check that passes its `expires-at` closes with nothing written to stdin. `interrupt`
ends the turn and closes its open asks and checks; the stream takes the next `say`. A file-tool
`allow` whose path, resolved as `claude` would (symlinks resolved), leaves the launch's workspaces
is refused. `updatedPermissions` is never written. This lifts S99's "waits for S100" cut of host
TECHNICAL 15 ("A2 in two slices") for asks and checks; `agent-handle`, `skills` and the shell grant
stay cut. It also adds the stage B host load test and its record.
## Acceptance
Each criterion is a test in `host/tests/it/` (extend `claude.rs`, `claude_launch.rs`,
`agent_load.rs`; unit tests in `src/agent/claude/` where a rule is pure), at the lowest level
that shows it. Oracles are literal lines; never a value the code under test computed.
AC1. Launch: `ask: true` passes and gives `--permission-prompts=host` and
     `--permission-prompt-tool=stdio` in place of `--permission-prompts=none` (same place in the
     argument order); `pre-tool-check {timeout-s: 5..120}` passes, and the `initialize` the fake
     records holds `hooks.PreToolUse = [{matcher:"*", hookCallbackIds:[<id>], timeout:<timeout-s>,
     onFailure:"block"}]`; `timeout-s` 4 or 121 is `bad-launch {field:"pre-tool-check"}`. With a
     callback, an answer without `hook_on_failure_supported: true` or with `hooks_applied: false`
     ends the stream `mismatch` (19.3 step 2). `agent-handle`, `skills` and `sandbox` still name
     their stage.
AC2. Ask item: a `can_use_tool` `{tool_name:"Read", input:{file_path:"a.txt"}, tool_use_id:"t1"}`
     becomes exactly `{"type":"ask","id":"1","tool_use_id":"t1","tool":"Read","input":{"file_path":"a.txt"},"expires-at":<ms>}`
     (key order as written; `expires-at` within the push time plus 10 minutes ± the test's slack,
     on the host clock); extra request fields (`permission_suggestions`, a stray `"type":"ask"`
     inside `input` is kept only as data in `input`) never appear at the top level. A
     `hook_callback` (PreToolUse) gives the `check` item with `tool`/`input` from
     `input.tool_name`/`input.tool_input` and `expires-at` = push time + `timeout-s`. Ids count
     `"1"`, `"2"`, ... per stream across asks and checks. A missing/empty/non-string
     `tool_use_id`, a non-string tool or a non-object input: deny at once, no item.
AC3. `answer` to an ask: `allow(none)` writes
     `{"type":"control_response","response":{"subtype":"success","request_id":"<claude's>","response":{"behavior":"allow","updatedInput":<the original input>}}}`
     and pushes `{"type":"ask-resolved","ask":"1","by":"answered","outcome":"allow"}`;
     `deny("no")` writes `{"behavior":"deny","message":"no"}` and `outcome":"deny"`; `none` is
     `not-allowed-here`; `allow(some(json))` only for `AskUserQuestion`/`ExitPlanMode` (else
     `not-allowed-here`, nothing written). To a check: `none` writes `{}` (`outcome":"none"`),
     `deny` writes the `hookSpecificOutput` body of 19.3 step 5, `allow` is `not-allowed-here`. A
     second answer, or an answer to an unknown/closed id, is `unknown-ask`. No written line ever
     holds `updatedPermissions` (grep of the fake's log). An answer in a call that fails or is
     rolled back writes nothing (19.6).
AC4. Protected reads, third rule (19.3; FUNCTIONAL S63): `allow` to an ask of `Read` with
     `file_path` `<home>/app/accounts/openai.json`, to `Grep` with `path` `<HOME>/.ssh`, to `Glob`
     with `pattern` `/etc/*` or `../x`, and to `Read` of `<workspace>/link` where `link` is a
     symlink to a file outside the workspace (also a relative path through a symlinked folder, and
     a path to a file that does not exist yet under such a folder): `not-allowed-here`, nothing
     written, the ask stays open and is denied at its `expires-at`. `Read` of `<workspace>/a.txt`
     (and an absent path: the working folder) is answered.
AC5. Expiry, with a clock the test controls (as the 5-minute backstop's): an unanswered ask at its
     `expires-at` gets the deny written and `ask-resolved {by: expired}`; an unanswered check at
     its `expires-at` gets `ask-resolved {by: expired}` and the fake's log holds no stdin line for
     it. An answer after either is `unknown-ask`.
AC6. `control_cancel_request` for an open ask: `ask-resolved {by:"cancelled"}`, the cancel line is
     never pushed, a later answer is `unknown-ask`; a cancel for an unknown request id pushes
     nothing.
AC7. `interrupt` with one ask and one check open: the fake's stdin holds the deny
     (`message` `interrupted`) for the ask, nothing for the check, then the `interrupt`; the stream
     gets `ask-resolved {by:"cancelled"}` for both, in push order; then a `say` is written and the
     stream goes on (not ended).
AC8. A `claude` line typed `ask`, `check` or `ask-resolved` is still `wrapped` (Q36) also while
     asks are open, and never resolves or opens one.
AC9. Load (slow, `#[ignore]`, in `agent_load.rs`): the stage B host load of TECHNICAL 15
     ("Budgets of stage B, the host part"): 8 streams, 2 consumer mods, a 10-entry and a
     10 000-entry turn each with an ask answered; every budget there met; the numbers, date and
     machine (`uname -a`, `nproc`) written into that paragraph.
AC10. Specs: host TECHNICAL 15 "A2 in two slices" says what S100 built; FUNCTIONAL S57/S63 and
     the scenario list match (add a scenario for AC5–AC7 if none covers it); 19.3's "S100" notes
     lifted; 18 Q41 notes that the ask's path check resolves symlinks (what stays open there, if
     anything). `cargo clippy --all-targets -- -D warnings` and `cargo +nightly fmt --check` clean.
