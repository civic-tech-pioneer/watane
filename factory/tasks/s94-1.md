Slice: S94 — a maker runs `cargo test -p watane-install` and it is done in under 2 minutes, proving the same rules

## Goal
install's default `cargo test` costs what the test pyramid allows (factory/README.md, "Test
pyramid" and "Time and value"): under 120 s on a quiet Mac and in the cloud. It took 858 s, then
1059 s, on the Mac. The cost there is process starts, not CPU: measured in the cloud on main
`fee9d0b`, the default run starts about 19,100 processes (one `install.sh` run is about 80 of
them), which at the Mac's ~55 ms per start is the 1059 s. In the cloud the default run took 74 s,
and nearly all of that is a few tests that wait out real deadlines or wait on the run gate.

After this task, each rule is proven at the lowest level that shows it:
- **Shell unit level** (new): one `sh` process loads `install.sh`'s functions and runs many cases
  of one rule (version check, path classification, receipt and journal parsing, allowed paths,
  tilde, shell_quote, foreign-file decisions, ...). One process per rule, not one install per case.
- **Whole-run level**: one script run per *behaviour* that only a whole run can show (the order of
  steps, an exit code and its stderr, what is left on disk after an interrupt), sharing fixtures,
  with several assertions on one run instead of one run per assertion.
- **Slow**: the runs that truly need many whole installs (signal sweeps, pty questions) are
  `#[ignore = "slow: <what no cheaper test proves>"]`.
Nothing that guards a *guard* behaviour loses coverage: receipt and journal checks, refusing
foreign files and paths outside the home, the checksum check, the lock, root refusal.
