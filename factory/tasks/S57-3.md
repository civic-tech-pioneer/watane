## Goal
One dist leftover, re-checked against main on 2026-11-14 (still as the ledger says). When a release
of a channel nobody here follows is fetched and every provider base that answered serves an older
head without that release (all stale mirrors, DD-34), the answer is a bare `UnknownRelease`
("unknown release <ref>", src/error.rs:80, reached through `fetched()` at src/fetch.rs:248 after
the loop at fetch.rs:106-150). A person reads that the release does not exist, when in fact the
mirrors they reached are behind. After this task that case has its own error that names the cause
and a next step.

Decided here (not by you):
- New variant `DistError::StaleBases { release: ReleaseRef, bases: usize }`, where `bases` is the
  number of provider bases that served the channel without the release.
- Text: `release <release> is not on any base that serves its channel: the <bases> base(s) read
  hold an older copy of the channel; follow the publisher's own link, or try again when the mirrors
  catch up`.
- Raised only in the provider-base branch of fetch.rs (the loop over `provider_bases`) when no base
  served the release and at least one base served the channel. `UnknownRelease` stays for every
  other path (a followed or index record whose stored view lacks the release).
- Update DD-34 in dist/TECHNICAL.md section 12 ("When no base has it, the answer is
  `UnknownRelease`") to the new variant, and the error listing (~line 372).
