## Goal

A listing can no longer make Alice's dist send a request into her own network through a host
*name*. Today only `localhost` and local IP literals are refused for a listed read (5.9, DD-26),
so a listed base or a redirect target such as `http://my-router.lan/` or a name in `/etc/hosts`
that resolves to 127.0.0.1 or 192.168.x.x reaches a local port (S112 r2). After this task, every
connection a listed read makes (its first base and every redirect hop) checks the address the
name resolved to, at connect time, with the same address rule as the literals; a local address
refuses the hop before any byte is sent. Followed and chosen links (DD-6) and unlisted reads are
unchanged: they may still use any base.

Decisions fixed here (the foreman's, from the sketch):
- The check is on the resolved addresses that dist would connect to, done in a ureq `Resolver`
  (or equivalent) of a second agent used only for guarded reads, so there is no gap between the
  check and the connect (no separate pre-resolve). If **any** address a name resolves to is
  local, the hop is refused (no fallback to its global addresses).
- When ureq goes through an HTTP proxy from the environment, the proxy resolves the target name
  and dist cannot see it: that case stays "Not protected", and the text says so. Do not disable
  proxies.
- The refusal is the same error a local literal gives today on that path (`BadUrl` with cause
  "local address" for a first base, "redirects to a local address" for a redirect, naming the URL
  as `follow_hops` does now), so callers' fall-through to the next base (A37) keeps working.
- `Options::listed_local` (and the `#[cfg(test)]` `test_local_ok` prefixes) turn the resolved
  check off exactly as they turn the literal check off, so existing tests on 127.0.0.1 servers
  keep working.

   (use `localhost`-free names: e.g. a test resolver, or a name like `127.0.0.1.nip.io` is NOT
   allowed: no network; inject resolution through a test seam on the guarded agent, or resolve a
   name from a test-only hosts map) is refused before any request reaches the local test server
   (the server counts zero connections), with the "local address" error.

   resolves to a private address is refused at that hop, names the base that redirected (as
   today), and the local server sees no connection. A provider fetch then tries its next base
   (A37 behaviour unchanged; one test through `follow_hops`/`get` is enough).

   (DD-6 unchanged).

   resolved check, so the two cannot drift: `local_base` calls it for literal hosts; a unit test
