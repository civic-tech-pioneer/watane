## Goal

The install consent's "data kept from before" is true when Alice approves it. A plan made while a
'Delete data' removal is under way never reports `kept_state == true` for data that the removal
deletes; and a table with no records is no kept data. (Review r1 F1.2, P1.1, P1.2; deputy
rulings on PR #34.)

The race (F1.2): `Host::remove` (host/src/lib.rs ~559-640) saves the new catalog and drops the
catalog lock, then deletes the state table (`self.state.delete`) at the end. A `plan` taken in
between sees the new generation (so `validate` accepts it later) but still finds `s/<id>`, so
`kept_state` is true for data that is gone a moment later.
