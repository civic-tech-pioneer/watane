Slice: S106 — the net pair test stops flaking on macOS

## Goal

Give the made-up operation its own unknown caller so the pair test checks the
wire response independently of the connection opened by hello.

## Acceptance

1. A fresh unknown caller submits `frobnicate` and receives exactly `unknown_op`.
2. The targeted test passes 50 consecutive runs.
3. The production unknown-peer budget defaults match TECHNICAL.md section 4.2.

## Spec

`net/TECHNICAL.md` sections 4.2 and 5.4.

## Interface

None.

## Files

`net/tests/it/pair.rs` and `net/tests/it/budget.rs`.

## Changed tests

`pair::s4_an_unknown_node_gets_hello_and_nothing_else` keeps its exact
`unknown_op` assertion and sends the made-up operation from a fresh identity.
Its receiving node `b` uses `Limits { unknown_bytes_per_sec: 16 << 20, ..Limits::default() }`.
Pairing and the nine raw unknown connections share one byte bucket. Their
post-handshake QUIC traffic can drain the production 64 KiB/s bucket and
trigger `over_budget` (net/TECHNICAL.md 4.2).
`budget::s9_the_byte_budget_of_unknown_peers_empties_and_refills` still checks
enforcement and refill. The new `budget::s9_the_unknown_budgets_default_to_the_spec`
pins the production limits.
