## Goal
`Log::open` reads the identity key from the same handle it checked: it opens `identity.key`
once without following a link (`O_NOFOLLOW`, non-blocking so a FIFO cannot hang) and checks
type and mode on that handle (`fstat`), so no swap between check and open can make it read
another file. The causes stay the same: `NotPlain` (with `link`), `Exposed`, `CorruptKey`.

## Acceptance
AC1. `identity.key` is a symbolic link (to a valid 0600 key file): `Log::open` gives
     `NotPlain { expected: "regular file", link: true }` and does not read the target (as today).
AC2. `identity.key` is a FIFO: `NotPlain { expected: "regular file", link: false }`, returned
     promptly (no hang).
AC3. `identity.key` mode 0644: `Exposed`, the file unchanged (as today).
AC4. The read path has no `symlink_metadata` then `File::open` pair on the key: the check runs on
     the opened handle. A test hook or code review step shows it; a unit test that swaps a link in
     after the old check point (if a hook exists) gives `NotPlain`, not the target's key.
AC5. Creating a key (missing file), the race with another opener (`AlreadyExists`), and
     `open_keyless`/`replace` behave as before; all existing log tests stay green.
