## Goal
`watane-dev publish --push` publishes as `publish` does (9.7) and then shares on GitHub with the
maker's own `git` and `gh`: the first run creates `<owner>/watane-channel` (the site) and
`<owner>/<slug>` (the mod), writes `repository` into `mod.toml` before the test pipeline, commits
and pushes the site folder, commits exactly the consented package files of the mod, tags the
ReleaseRef and pushes. Later runs find both repositories and only commit, tag and push. A missing
git, gh, gh login or git identity stops before anything changes; a failed push reports the release
and the commands that finish it. The result carries `push` and a `next` that asks for the raw site
URL when there is no link yet. Tests run against local bare remotes through git's `insteadOf` and a
new `fake-gh` binary; nothing reaches GitHub. This is dev build stage 10, without the GitHub fork
(see Out of scope).

## Interface
Provides to S42-2 (the app journey), fixed:
- CLI: `watane-dev publish --push --json --dir <mod> --home <home> [--wait <s>]`.
- `result.push.site.repository == "https://github.com/<owner>/watane-channel"`,
  `result.push.site.raw == "https://raw.githubusercontent.com/<owner>/watane-channel/main/"`,
  `result.push.mod.tag == result.release`, `result.link` as 9.7 (null before a site URL is set).

- `fake-gh` is built by `cargo build -p watane-dev --features fake-host --bin fake-gh` and is
  answered from `FAKE_GH_ROOT` and `FAKE_GH_USER` as 15.4.
