## Goal
Stage A4 of the host: `https-stream.start` works. A mod with an `Http` grant for a host can
stream an HTTPS response from it: the first item is `{status, headers}`, then one item per
server-sent event, or one per 64 KiB chunk of a body that is not SSE; no bytes for `idle-s` ends
it `idle-timeout`. Every refusal of 19.4 happens at the call, before a byte leaves. With
`account: "openai"` the host asks the app's `AccountSource::openai_token` for a fresh token per
request and adds `Authorization: Bearer <token>`, only on `POST https://api.openai.com/v1/responses`
and `GET https://api.openai.com/v1/models`, after the account consent of 19.7 is held; no app ends
it `no-app`, no tokens `no-account`, `Unavailable(m)` `failed("account unavailable: <m>")`.
Signing out (`Host::account_changed(&Account::OpenAi)`) and withdrawing the account consent end
the live `openai` streams `gone`. Under borrowed authority (19.5) `https-stream.start` fails the
call `not_granted` (S103 built the check; this task adds its test). The feature `test-net`
(`Host::set_test_net`) points a route's name at a local address and trusts a test root, so all
of this is tested with no real network. The token never reaches a mod.

AC1. Items (case 3): a granted host answers `text/event-stream` with three events: the fixture
     records first `{"status":200,"headers":{..}}` (state the exact item JSON in 19.4: header
     names lower-case, values as sent), then exactly one item per event, each the event's
     `data` text as sent (state the item form in 19.4), then the outcome `closed`. A non-SSE body
     of 150 KiB arrives as items of 65536, 65536 and 22528 bytes with the bytes unchanged. A
     server that sends headers then nothing ends the stream `idle-timeout` after `idle-s: 1`

AC4. Account `openai` (case 19, `openai`): with a `Granted` consent the server receives

AC5. Account consent (19.7): the first `openai` request of an origin client through a mod `via`
