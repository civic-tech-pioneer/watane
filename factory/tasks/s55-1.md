## Goal
J3 runs with Bob's app on a second machine. A new window-test file `app/tests/it/two_machines.rs`
plays J3 with Alice's driver app on this Mac and Bob's driver app reached through a command whose
stdin and stdout are Bob's driver channel (install/tests/vm_two_machines.sh, task s55-2, makes that
command an ssh bridge into a Tart VM). Alice publishes the reading list to a site served by a web
host the test is given, Bob follows her link, sees Alice as the verified publisher, installs and
uses the mod; then a file on the web host is changed and a fresh Bob home refuses it, naming the
cause. Without the VM variables the same test runs on one machine (Bob local, the site served by
`Site::serve`), so it is runnable and checked anywhere the window tests run.

Why a driver build for Bob: the consent floor lets only a click in the consent window answer, and
a script cannot click the release app in the guest (SIP on, no Accessibility grant for ssh, probed
2026-11-19). The driver build answers by clicking the consent page via `eval`, exactly as
`tests/it/j3.rs` does. This is a test method only; no product code changes.

## Acceptance
- AC1 `App::over(command: &str, home_name: &str) -> App` in `tests/support/driver.rs` runs
  `sh -c "<command> \"$1\"" sh <home_name>` (the home name is the one argument; the command is
  trusted, from the environment) with piped stdin/stdout, and speaks the same JSON-lines protocol
  as `App::start` (same reply routing, same `ready` wait, same `quit`). It shares the spawn code
  with `spawn` (one reader loop, not a copy). `App::home` for such an app is the empty path; no
  helper used on Bob reads Bob's files from this side.
- AC2 `two_machines::ac1_j3_two_machines` (`#[ignore = "vm: J3 between two machines"]`), with
  `WATANE_VM_BOB`, `WATANE_VM_ALICE_HOME` and `WATANE_VM_SITE_BASE` set: Alice = `App::start` on
  `WATANE_VM_ALICE_HOME` (an existing, empty folder) with her site URL set to
  `WATANE_VM_SITE_BASE` (`site_set_url`); she sets her name "Alice" and publishes
  `fixture("reading-list")`, approving her consent as j3.rs does. Bob = `App::over(bob, ".watane")`:
  `install_link` with her link; his consent text contains "Alice", her fingerprint and
  "signature verified"; after approve, `mods_list` has one mod with publisher name "Alice" and her
  release; `mod_open` opens `mod-<local>` and its text contains "Reading". The test adds a book
  through the mod page (as an existing journey test does) and reads it back from the page.
- AC3 Same test, after AC2: the package file under `<alice home>/dist/site/packages/<id>` gets one
  byte flipped (as j3.rs does). A second Bob, `App::over(bob, "bob-tamper")`, runs `install_link`
  with the same link; the result's error message contains "hash mismatch" and
  `<site base>packages/<id>`, and its `mods_list` is empty. All three apps quit with success.
- AC4 Without `WATANE_VM_BOB` (any of the three unset), the test runs on one machine: Alice's home a
  temp folder, the site `Site::serve(<alice home>/dist/site)`, Bob an `App::over` of a local
  command that starts `CARGO_BIN_EXE_watane-app --home <temp>/<home_name> --port 0` (with
  `WATANE_DRIVER_SCREEN=hidden`). It passes with
  `cargo test --features driver --test it -- --include-ignored two_machines::`.
- AC5 The test prints nothing secret and leaves no file outside its temp folders and
  `WATANE_VM_ALICE_HOME`.

## Interface
Provided to s55-2 (fixed): the test `two_machines::ac1_j3_two_machines` in the `it` binary of
`watane-app` with feature `driver`, and the environment variables
- `WATANE_VM_BOB`: a shell command; `sh -c "$WATANE_VM_BOB <home_name>"` starts Bob's driver app
  with home `~/<home_name>` on the other machine and connects its stdin/stdout to the driver
  channel; it exits when its stdin closes and the app quit. Home names used: `.watane`,
  `bob-tamper`.
- `WATANE_VM_ALICE_HOME`: an existing empty folder on this Mac; Alice's home.
- `WATANE_VM_SITE_BASE`: the URL, ending in `/`, at which a web host serves
  `$WATANE_VM_ALICE_HOME/dist/site` to Bob's machine.
