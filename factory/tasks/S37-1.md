## Goal
The consent view knows step 5. A `pick` request shows the consumer, the missing provider, the
cause and the candidates (name, version, publisher name and fingerprint, "made from", installed,
check age), and the participant answers with one choice or deny. The install view shows each
mod's `made from <origin> (the publisher says so)` and each new bind line; the `release` sign
view has a `Made from` detail. Grant lines of a bound provider read `... of <slug> by <to's
party> (in place of <slug> by <provider's party>)`. This task builds the model, the broker
rules, `consent_answer`'s `choice`, the words and the page; it is tested through the driver's
`ask` (stage A), with no dist or network.

## Interface
Provides to S37-3 (fixed, as TECHNICAL 6.1/6.2):
- `Request::Pick { consumer: String, provider: String, cause: String, candidates: Vec<Candidate> }`
- `pub struct Candidate { pub choice: String, pub name: String, pub summary: String, pub version: String, pub publisher: Party, pub origin: Option<String>, pub installed: bool, pub checked_at: Option<u64> }`
- `Answer::Pick { choice: String }`; `ConsentError::{WrongAnswer, UnknownChoice(String)}`.
- `PlanMod { .., origin: Option<String>, binds: Vec<String> }`.
- `words::grant_line_bound(grant, binds: &[watane_host::Bind], parties, granted, new) -> GrantLine`
  (`grant_line` is it with no binds; TECHNICAL 4)
  and `words::bind_line(bind: &watane_host::Bind, parties) -> String` (pub(crate)).
`consent_answer` takes `choice: Option<String>`; the consent page sends `choice: null` for
install and sign.
