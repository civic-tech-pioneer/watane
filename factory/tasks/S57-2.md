## Goal
Two log leftovers, re-checked against main on 2026-11-14 (both still as the ledger says).

(1) `Error::NotPlain` always adds "(a symbolic link is refused)" (src/lib.rs:29), also when the
entry is a plain type mismatch (raised at src/identity.rs:23), so a regular file where the log
directory should be is blamed for being a link. After this task the text names what is there.

Decided here (not by you):
- `NotPlain` gains a field `link: bool` (true when `symlink_metadata` says the entry is a link).
- Display: link -> `<path> is a symbolic link; a <expected> is required (a link is refused)`;
  otherwise -> `<path> is not a <expected>`.
- No other subsystem matches `NotPlain` (grep of app, host, dev, dist: none), so the shape change
  stays inside log.

(2) A bad backup magic shows U+FFFD: `found` is `String::from_utf8_lossy(&backup[..8])`
(src/identity.rs:212). After this task `found` shows the 8 bytes with non-printable or non-ASCII
bytes escaped (`<[u8]>::escape_ascii`, inside double quotes), e.g. `"\xffatanek1"`. The only magic
test corrupts into valid ASCII (log/tests/backup.rs:82, `b[0] ^= 1`), so non-UTF-8 has no test:
write that case.
