## Goal
After S72-1, node/tests/light.rs without its reconnect workaround still fails about 1 run in 10:
in `s6_the_light_laptop_searches_and_installs_through_the_server` the server (full) does not hold
Alice's new entry and package within 15 s of the laptop's publish (`keeps`, light.rs:69; 18 of 20
runs passed). The foreman's hypothesis, to confirm or refute first: in the three-machine topic
(laptop anchor, server full, light laptop light) the server sometimes gets the hint delivered by
the light laptop, which does not hold Alice's channel and never will (a light machine drops hints
for channels it does not hold), so S72-1's retry asks a machine that will never reach the seq for
5 s and then drops the hint. If so, the fix: when the delivering machine is behind (or has no head
of the channel), also ask the other trusted machines this machine has a live link to (or the
machines of the device list it can reach), with the same retry bound and the same forged-id and
forged-seq rules; whatever is simplest and keeps every hint bounded. If the cause is another
(a lost first broadcast, the topic not yet joined, a package fetch that is not retried), fix that
instead and say what it was, with evidence (an event log or a count, not a guess).
