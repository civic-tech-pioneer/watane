## Goal

Check the key's Windows ACL with the operating system's command-line
tools and give the node's Windows storage callers one way to create and
pin a checked private directory.

## Acceptance

1. AC1. A newly created key passes an independent DACL check from
   `icacls /save` against the current SID from `whoami /user`, and
   retains its existing owner check and identity on reopen.
2. AC2. The shared helper creates missing components with the private
   ACL, returns a handle to a checked directory, and refuses exposed
   or non-directory paths. Verify this in the Windows platform crate.
3. AC3. The technical specification names the helper and the
   `publish` replacement flag used for the identity.

## Spec

- `log/TECHNICAL.md` sections 4.7, 8.1 and 10.
- `spec/TECHNICAL.md` section 6, Verification.

## Interface

For net on Windows, `watane_log_windows_fs::private_dir(path: &Path) ->
Result<File, PrivateDirError>`. The error distinguishes operating-system
failures (`Io(io::Error)`) from refusals of the final directory
(`Invalid(io::Error)`).
