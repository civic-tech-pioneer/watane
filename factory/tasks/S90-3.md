## Goal
Two small truths. A mod or agent posting a wrong shape to `/api/fetch` (`[]`, `{"link":5}`)
gets a plain cause instead of serde's "data did not match any variant of untagged enum
FetchQuery". The Linux test runner names each version it prints and sets `NO_AT_BRIDGE=1` so ~17
AT-SPI warnings stop burying its output.

## Acceptance
- AC1 `/api/fetch` bodies, each a 400 `bad_input` JSON error, message:
  non-object (`[]`, `5`, `"x"`) → `give link or release: the body must be a JSON object`;
  `{"link":5}` / `{"release":true}` → `give link or release: link must be text` / `... release must be text`;
  an unknown key → `give link or release: unknown field <key>`; both or neither → exactly
  `give link or release` (as today); non-JSON → `give link or release: <serde_json syntax cause>`
  (as today). No message contains `untagged` or `variant`. Valid shapes behave as today.
- AC2 `app/scripts/linux-test.sh` prints one line per library: `glib-2.0 <v>`, `libsoup-3.0 <v>`,
  `webkit2gtk-4.1 <v>`; `docker run` gets `--env NO_AT_BRIDGE=1`. linux_runner.rs's stubbed run
  asserts both (the pkg-config stub prints a version).
- AC3 `cargo test -p watane-app --test it api:: linux_runner::`, clippy, `cargo +nightly fmt --check`.
