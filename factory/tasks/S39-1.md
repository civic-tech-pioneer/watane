## Goal

Every error that a maker's coding agent meets in `fetch`, `install`, `test`,
`serve` and `check` carries a code and a `fix`/`next` that names the real next
action, so the agent recovers by following them without reading dev's code.
And the cache of released packages is crash-safe: `store` never leaves a half
provider folder that a later run reuses. Outcomes 1 and 2 of S39, plus the
own-package texts of outcome 4.

## Acceptance

AC1 `store` (TECHNICAL 10.1): the provider folder is unpacked to
`<cache>/providers/<id>.<pid>.tmp` (any leftover of that name removed first) and
renamed to `<cache>/providers/<id>`; when the rename finds `<id>` already present,
the temp folder is removed and the present one is used. A leftover
`<id>.<other>.tmp` (a killed run) is never read and does not stop a store.
`fetch_providers` reuses only `<id>` folders. Unit tests in `build_on`: a store
with a leftover partial temp folder yields the full folder; a store when `<id>`
exists keeps it and leaves no temp.
AC2 `Client::fetch` error answers: 409 `fetch_refused` keeps `host.refused`
`[fetch_refused] <message>` with the fix `Check the link or release with the
person who shared it: the watane app found no release to fetch for it`;
502 `fetch_failed`: fix `Check the link and that its publisher's site is
reachable, then run this command again`. No fix of fetch says to check the app
except 503 and 5xx (AC4). Loopback unit tests.
AC3 The answer checks of 10.1 (missing or unparseable `Watane-Release` or
`Watane-Package`, a release not matching the request, a package id not matching
the body, a body that is not a package or has a WIT slug/version not matching the
release) are `host.refused` `[bad_answer] <detail>` (not `internal`) with the fix
`The watane app answered with a package that does not match the request; ask the
person to update the watane app, then run this command again`. Nothing is stored.
Update the S36 loopback tests that assert `Code::Internal`.
AC4 App 5xx in `Client::request` (install, publish, search, releases) and in
`fetch`: 503 `unavailable` is `env.host_not_running` with message `the watane app
of <home> runs but could not open its data: <app message>` and fix `Ask the person
to restart the watane app, then run this command again`; any other 5xx is the new
code `host.failed` (class Refused, exit 4) with message `[<code>] <message>` and fix
`The watane app failed on this request; ask the person to read the watane app's
log, then run this command again`. 4xx keeps `host.refused` and its current fixes.
Add `host.failed` to 2.2 and the `Code` enum (12).
AC5 `install` `missing_providers` (9.6): when `.watane-dev.json`
`release_providers.<slug>` has a `link`, the fix is `Install <ReleaseRef> in the
watane app from its link <link>, then run install again`; with no stored link the
current text stays. Unit test.
AC6 A failed `test` (and `serve`, whose pipeline runs `test`): when the first error is
`test.unit` or `test.unit_limit`, `next` is `Fix the unit test <test name>, then
run: watane-dev <test|serve> --json`; for `test.contract`, `Fix <file> step <n>
(<call>), then run: watane-dev <test|serve> --json`; else the first error's fix when
it has one (as now), else the plain rerun. A local provider's failure keeps its
`--dir` rerun (S29). Exact-text tests in the default suite.
AC7 `check` fixes for own-package violations (2.2 last paragraph): (a) a
`deps.json` entry `mods:<own slug>` gets `Ask before deleting wit/deps/<slug>/ and
mods:<slug> from deps.json: a mod cannot depend on itself`, never `Import the
provider's interface`, also when pkg reports it as an unused provider (deps.json
only, no `wit/deps/` folder): dev compares the slug with the mod's own slug;
(b) `wit/deps/<folder>/ holds this mod's own package mods:<slug>` with `<folder>` ≠
`<slug>` gets `Ask before deleting wit/deps/<folder>/: a mod cannot depend on
itself` (the folder from `file`, the slug from the message). Tests in `tests/check.rs`.
AC8 TECHNICAL 2.2, 9.6, 10.1 and 15.2 say all of the above; FUNCTIONAL only if a
scenario's text changes.
