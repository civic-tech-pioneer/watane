Subsystem: node
Effort: medium
Depends on: none
Slice: S80 — Alice's server says what is wrong (node, net).

## Goal
`watane-node` answers Alice plainly: `--help` shows the usage; `status` while `run` runs on the
same home answers (from net's files) instead of failing "home is locked"; a second `run` (or
`relay`/`dht` while `run` runs) says another watane-node is running on this home; the y/N answer
gets its own line when standard input is not a terminal; `dht on|off` and `relay add|remove`
confirm what is now set; the program's error texts print each node key once.

## Acceptance
Tests in node/tests/program.rs on `env!("CARGO_BIN_EXE_watane-node")`, unit tests in the bin.
- AC1 `watane-node --help`, `watane-node -h`, `watane-node help`, and `--help` after any command
  (`watane-node --home h run --help`) print the usage on stdout and exit 0, with no home needed.
  Anything else unknown still exits 2 with `unknown flag <flag>` and the usage.
- AC2 `status` while `watane-node run` runs on that home exits 0 and prints the lines it prints
  today for node, machine, anchor, devices, relays and dht (read without the dist lock: open net
  only, e.g. `watane_node::net::Net::open` on `<home>/net` with net off and a holder that holds
  nothing, or a small read-only function in node's lib; it must write nothing to the home), and in
  place of the two dist lines one line `channels and packages: watane-node run is running on this
  home`. With nothing running, `status` prints exactly what it prints today.
- AC3 a second `run` on a home where `run` runs exits 1 with stderr
  `watane-node: another watane-node is running on this home (<home>); stop it first`
  (map `DistError::Locked`). `dht on --yes`, `relay add <url> --yes` and `join` while `run` runs
  give the same text and change nothing.
- AC4 a question whose standard input is not a terminal (`std::io::IsTerminal`): after
  `Turn this on? [y/N] ` the program writes the answer it read (trimmed, possibly empty) and a
  newline, so the next output starts on its own line. Test: stdin `y\n` -> stdout has a line
  `Turn this on? [y/N] y`; empty stdin -> a line `Turn this on? [y/N] ` followed by a newline.
- AC5 after a change, the command prints the line `status` prints for it: `dht on`, `dht off`,
  `relays <list|none>` (after `relay add` and `relay remove`); nothing when the answer was no.
- AC6 every stderr text and `run` line of the program names a node's short key at most once
  (`chain` already drops repeated causes; extend the unit test `a_cause_is_printed_once` with a
  nested net error whose cause repeats the key, e.g. `NetError::Unreachable { node, cause:
  format!("node {} refused: not_allowed", node.short()) }`, and make the line say it once).
- AC7 `cargo test -p watane-node` passes (with `-- --include-ignored` once); clippy
  (`--all-targets -D warnings`) and fmt clean.
