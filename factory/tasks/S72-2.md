## Goal
node stage 3 (node/TECHNICAL.md 9, row 3): the program `watane-node`. Alice runs her server as a
program with no window and no identity: `watane-node --home <dir> join <code>` pairs it with her
laptop (it shows its short key and waits for her yes), `run` keeps it running as her full or light
machine and prints one line per network event, `status` shows where it stands with no network,
`run --relay 127.0.0.1:<port>` also runs a relay for her machines, and `relay add` / `dht on` turn
on reach only after printing the same consent text as the app.

## Acceptance
Tests in node/tests/program.rs run `env!("CARGO_BIN_EXE_watane-node")` and read its stdout,
stderr and exit code; the anchor is a `Node` in the test process (`Node::open` on an app home, net
on, 127.0.0.1, mDNS off, as tests/support does) which answers `JoinAsked` with `answer_join`.
Expected texts come from `watane_node::words` / net calls or literal strings of TECHNICAL 6, not
from the program's own code. Each scenario is one test named `s<n>_...`.
- AC1 (S10) `watane-node --home <h> join <code>` (code from the anchor's `pair_code(Role::Full)`)
  prints `this machine: <short>` (equal to the short key the anchor sees in `JoinAsked`) and
  `waiting for your answer on the anchor`; after `answer_join(.., true)` it prints
  `joined as full; machines: ...` naming both machines and exits 0; the anchor's device list names
  it full. After `answer_join(.., false)` (another home) it exits 1 with stderr
  `watane-node: declined`.
- AC2 (S11) `watane-node --home <h> run --relay 127.0.0.1:<p>` (p a free port the test picks)
  prints `running as full, node <short>` and `relay on 127.0.0.1:<p>; add http://127.0.0.1:<p>/ to
  the relays of your other machines`; two other homes that have only that relay (as
  net/tests/reach.rs `s11_...` sets it up: stale direct addresses) connect through it.
  `--relay 127.0.0.1:0` exits 2 with the usage.
- AC3 (S12) `watane-node --home <h> dht on` with an empty standard input prints the DHT consent
  text (`words::dht_on`), exits 1 with `watane-node: not changed`, and `status` still says DHT off;
  `dht on --yes` prints the text and `status` says DHT on; `dht off` turns it off with no question.
  Same for `relay add <url>` / `--yes` / `relay remove <url>` with `words::relay_add`.
- AC4 (S13) a trusted machine (paired by the anchor; its holder answers `entries` with a changed
  byte, like the `Liar` of tests/light.rs) is pulled from by `watane-node run`; the program prints
  exactly one line `refused <short of that machine>: <cause>` for it.
- AC5 `run` on a home never paired exits 1 with `watane-node: not paired: run watane-node join
  <code> first`; a home with `home.json` is refused (exit 1, the `HostHome` text) for every command;
  bad arguments exit 2 with the usage; `WATANE_NODE_HOME` stands in for `--home`.
- AC6 `run` ends on SIGTERM and SIGINT with exit 0 and `net` turned off (book.json on false; a test
  sends `kill -TERM <pid>` with the `kill` command, which exists on macOS and Linux). `status`
  prints node key, machine, anchor, device list (seq, expiry, each machine), relays, DHT on or off,
  the number of held channels and of missing packages, and makes no network contact.
- AC7 (unit, in the bin or a private module) the line of 6.2 for each `Event` variant, and the
  hand-written argument parser (each command, `--home`/env, port 0 refused, unknown flag).
- AC8 `cargo test -p watane-node` passes; program.rs adds at most ~10 s to node's ~15 s (tests in
  parallel, short waits; report the time); clippy (`--all-targets -D warnings`) and fmt clean.

## Interface
Takes from node's lib only what exists today (`Node::open_keyless`, `join`, `machine`, `net()`,
`dist()`, `close`, `words::*`). Provides the binary `watane-node` with the commands, lines and exit
codes of TECHNICAL 6 (fixed; app stage G and the product owner's J8 read them).

## Decisions made for this task (by the foreman)
- Signals: use tokio's `signal` (already in the workspace through workspace-hack and host) on a
  small runtime on the main thread that only waits for the signal, not `signal-hook` (no new crate;
  `unsafe` stays forbidden). Add `tokio = { version = "1", features = ["rt", "signal"] }` to node's
  `[dependencies]`; Cargo.lock then changes only in watane-node's dependency list; commit it.
  Update node/TECHNICAL.md 2 to say so. Never call a node/net method inside that runtime.
- A question (`dht on`, `relay add`) reads one line from standard input; only `y` or `yes` counts.
