## Goal
host's messages name a provider's publisher the way dist does: by the 10-character fingerprint
of the key (`watane_log::PublicKey::fingerprint`, dist TECHNICAL 3.1), not the full 52-character
key. The `ambiguous_provider` message lists its candidate mods in natural order (shelf, shelf-2,
shelf-10, not shelf, shelf-10, shelf-2). The flaky `api::ac5_extra_api_receives_one_mib...` test
(in the `preview` target) no longer fails at `send().unwrap()` with a broken pipe. host TECHNICAL
2.2 shows the variant shape S45 introduced.

- AC1 Unit test (`host/src/error.rs` tests or `catalog.rs`): a provider with a publisher key
  displays in `AmbiguousProvider`'s message as `<fingerprint>/<slug>` where the fingerprint is
  the first 10 characters of the key text, computed in the test without host code (e.g.
  `key_text[..10]`); a local provider stays `local/<slug>`. Literal expected message.
- AC2 Same for `MissingProviders`: its message names each provider as `<fingerprint>/<slug> at
  <version> needed by <mod>`; the JSON `missing` array keeps the full provider (unchanged shape

- AC3 Unit test: candidates `shelf-10`, `shelf-2`, `shelf` give `shelf, shelf-2, shelf-10` in the
  message (natural order: digit runs compare by number, the rest by bytes; equal numbers with
  different leading zeros keep a fixed order). The `candidates` field holds the same order.
- AC4 `host/tests/binds.rs::plan_of_second_shelf_for_installed_unbound_recs_is_ambiguous`: its
  expected literal uses the fingerprint (it builds the key text itself). This test binds
  loopback; it cannot run in the cloud (no IPv6): compile it, and list it as not run (cloud).
- AC5 `host/tests/api.rs::ac5_extra_api_receives_one_mib_unchanged_under_common_guards`: keeps
  proving that 1 MiB passes the common guards unchanged to an extra route, and that the guards
  answer 403 (Origin), 421 (Host), 404 (unknown mod host) and 413 (over the /api body limit).
  Decision (the foreman's): the guards stay as they are (they must not read a hostile body they
  refuse); the test sends the 403/421/404 requests with a small body (a few bytes) and makes the
  413 step immune to a broken pipe, e.g. a raw `TcpStream` request whose declared and sent body is
  just over the /api limit (64 KiB + 1, see `host/src/api.rs`), reading the status line; or a
  reqwest send whose transport error is accepted only if a 413 status was already read. No
  assertion is weakened. This test binds loopback too: compile it; not run (cloud).
- AC6 Nothing else changes: every host test that can run here passes (`cargo test -p watane-host
  -- --include-ignored`); the tests that bind `::1` fail here with `PortInUse(0)` at the base
  commit too (S45 found 67): show the same set fails before and after your change, and list them
  as not run (cloud). clippy (`--all-targets -D warnings`) and fmt clean.
