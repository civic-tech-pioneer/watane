Effort: medium
Depends on: s105-fix2
Slice: S105 — a listed base cannot lead dist into the local network

## Goal

This task closes the adversary's round-3 breach. Here is the attack:
1. A followed record from before S105 holds a base it learned from a listing. That base is unknown under DD-47.
2. A search hit's link carries that base. Installing the hit runs `follow(hit.link)`, and `learn_base` then marks the base given.
3. From then on its redirects into the local network are followed.

dist cannot tell a link the participant typed from a link built out of a record's own base, such as a hit link or `Fetched.link`.

Foreman decision: this is the stricter option, cheap to undo and inside dist. A base already in a record that is not given stays unknown. No `follow`, `choose_index` or `learn_link_base` (`open_link`) at that base marks it given. Only a base new to the record, which the participant's link adds, is marked given. So is the link's base when a listed-only record turns followed or chosen (DD-46, `adopt_given_base`). To trust an unknown base again, the participant unfollows the channel and follows it again by a link. This is stricter than the deputy's "until the participant gives it again" (DD-47). Loosening it later is cheap.
