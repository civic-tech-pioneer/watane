## Goal
One net leftover (S87's adversary), re-checked against main `ec744f4` on 2026-11-20: still open. In
`need_blob` (net/src/light.rs:158-229) every `Failed::NotFetched` error other than `BadObject` and a
`not_allowed` refusal goes into `last` and comes out as `Unreachable { node: <the full machine>,
cause: "package <hex8> was not fetched: <cause>" }`, plus an `Event::Unreachable` for that machine in
Machines. A local error is among them: `blobs::download` (net/src/blobs.rs:248-310) returns
`NetError::Io { path: <temp file>, .. }` when this machine cannot create, write, sync or re-read its
own temp file, and `sync::holder` returns `Io` when the holder task fails. So Alice reads
"unreachable <full machine>" for her own disk. Also, `download` discards the holder's
`store_blob` error (blobs.rs:303-306), so `need_blob` says `Ok` for a package the holder did not keep.

After this task a local failure during `need_blob` is reported as this machine's own: the error is
`NetError::Io`, names no other machine, emits no `Event::Unreachable`, does not mark the full
machine in `blob_unreachable`, and stops the tries (the next machine would hit the same disk). A
holder that does not keep the package is such a local failure in `need_blob`.

Decided here (not by you):
- A holder `store_blob` error becomes `NetError::Io { path: <the temp file's path>, cause:
  "package <hex8> was not stored: <holder's cause>" }` returned from `download`. The temp file is
  still removed in every case (5.8).
- The background sync (`sync::fetch_wanted`, sync.rs:686-707) keeps its behaviour: it already
  ignores every error but `BadObject`, and still does (the next sync asks again).
- `need_blob`: a `Failed::NotFetched(NetError::Io { .. })` is returned at once, as it is. Nothing
  else in its order changes (bad object first, then a refusal, then `last`, then `NoFullMachine`).
- `NetError` keeps its variants and texts.
