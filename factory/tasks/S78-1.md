Slice: S78 — A full test run leaves nothing behind in the temp folder: the number of
`$TMPDIR/.tmp*` folders is the same before and after a full run of pkg, host, dev, log, dist, net
and node.

## Goal
After this task, `cargo test -p watane-dev -- --include-ignored` leaves no `.tmp*` folder in
`$TMPDIR`. Measured in the cloud (TMPDIR set to an empty folder, `--no-fail-fast`), dev leaves 5
folders (2.4 GB) per full run; pkg, log, net, node, host and dist leave none. The two causes:

1. `dev/tests/support/mod.rs`: `cache()` keeps the warm template cache in a
   `static OnceLock<tempfile::TempDir>`. A `static` is never dropped, so every test binary that
   uses it (`build_on`, `contract`, `serve`, `unit_tests`) leaves a folder with `build`,
   `cargo-home`, `counter`, `target`, `tmp` (and `packages`, `previews`, `providers` from
   `build_on`). On the Mac these were 359 of the 186 GB.
2. `dev/src/builder.rs`, `tests::ac1_release_and_unit_build_progress_stays_on_stderr`: the child
   run calls `std::process::exit(0)` while `root` (a `TempDir` holding `copy/`) is alive, so its
   drop never runs (the 124 `copy` folders on the Mac).

Decision taken by the foreman (cheap to undo, inside dev's tests): the warm cache moves out of
`$TMPDIR` to a fixed folder per test binary under Cargo's `CARGO_TARGET_TMPDIR`
(`<target>/tmp/watane-dev-warm-<CARGO_CRATE_NAME>`), removed and rebuilt at its first use in each
run. It stays at one original path for the run (the S13 fingerprint rule, dev/TECHNICAL near line
2084), is bounded to one folder per test binary, and `cargo clean` removes it. Do not reuse a
previous run's cache (a template change would make it stale) and do not add a dependency (no
`libc`/`atexit`): no `Cargo.toml` changes.

## Acceptance
- AC1 `dev/tests/support/mod.rs::cache()` returns a path under `env!("CARGO_TARGET_TMPDIR")`
  whose last component is `watane-dev-warm-<crate name of the test binary>`; at first use in a
  process it removes that folder if present, then builds the template there as today. Every test
  that uses `support::cache()` passes unchanged.
- AC2 New regression test binary `dev/tests/regress_s78.rs` (pattern: `net/tests/regress_s60.rs`):
  a parent test runs its own binary (`std::env::current_exe()`) with `--exact <child test>`,
  `TMPDIR` set to a fresh `tempfile::tempdir()` and a child env var; the child test calls
  `support::cache()` (it is `#[ignore]`d with a reason only if building the template is slow —
  then the parent is `#[ignore = "slow: ..."]` too, and the child runs with `--include-ignored`).
  The parent asserts the child succeeded and that the given TMPDIR is empty afterwards (list the
  names on failure). Red before the fix, green after.
- AC3 `builder::tests::ac1_release_and_unit_build_progress_stays_on_stderr`: the child drops
  `root` before `std::process::exit(0)` (e.g. a block). Add a unit-level check in the same module
  that runs that child with `TMPDIR` set to a fresh temp folder and asserts it is empty afterwards
  (or extend the existing parent half to do so). Red before, green after.
- AC4 `TMPDIR=<empty dir> cargo test -p watane-dev --no-fail-fast -- --include-ignored` leaves
  `<empty dir>` empty. Tests that cannot run in the cloud (IPv6 loopback, macOS sandbox) still
  fail there as before; they are not this task's concern, but do not let a test you touch start
  failing.
