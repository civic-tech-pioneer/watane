## Goal

Carol and Eve use find, install, pick and publish in the app, and every person
shows as a name (or "you"), every error as one plain sentence. No raw
52-character key or 10-character fingerprint alone where dist's log holds the
party's profile; no doubled cause, no Debug or serde text; find's empty and
error states read right; a fast retry never leaves a stale error. App only:
dist, host and the other subsystems are not edited.

## Acceptance

AC1 Names. Every party the app shows (pick candidates, bind lines, grant lines,
"Made from" in details/consent/release sign, "Made from this", list/include/
unlist sign consent, index rows, `included`/`skipped`, hit `via`) carries the
profile name whenever dist's local log holds that channel's profile, also for a
channel that is not followed (a pick candidate's publisher, an origin's
publisher read through a listing, a fetched release's channel). The parties
cache is filled from every channel the app shows, through `dist.channel(key)`
(no network; it never blocks HostConfirm on dist). Test: unit tests in
`words.rs`/`core.rs` with a parties cache filled from a not-followed channel's
view; one integration test (as `tests/build_on.rs`) where the pick view names
Frank's not-followed publisher by name.
AC2 You. The own key shows as "you" everywhere AC1 lists, also in own index rows
and own-index hits ("listed by you", never "listed by <own fp>"). Test: unit
tests for `words::party`/`provider`/`bind_line` with the own key; the words.js
node test for `partyLabel`/`viaLabel`.
AC3 Causes print once. A dist error whose source repeats in its text shows "X",
never "X: X" (find the case in dist's `DistError` texts that `cause_chain` misses,
e.g. a `#[error("...: {0}")]` wrapping a `#[source]`, and fix it in `cause_chain`);
the publish 422 (`invalid_package`) message and every URL in an error read
plain (Display, no Debug quoting or struct text). Test: unit tests on
`cause_chain` with the real dist variants, and an `/api/publish` 422 test on
the message text. If the doubled text can only be fixed in dist's error type,
stop and report BLOCKED with the variant: do not edit dist.
AC4 `/api/fetch`. A body with both `link` and `release`, or neither (or null
for both), answers 400 `bad_request` with the message `give link or release`
(no serde text). `GET /api/fetch` (and any other wrong method on an `/api/*`
route) answers 405 with a JSON error body `{"error":{"code":"method_not_allowed",
"message":...}}`. Test: `tests/api.rs`.
AC5 Find. A search with no hits shows "No mods found" (not an empty list). An
include refused as `AlreadyListed` says the channel is already in the index,
with no "at seq <n>" (list keeps a plain "already listed" text, also without
the seq). A failed index read (`index_choose`, and an index row's `cause`)
names the index (its name, else its link's fingerprint): "Could not read
<index>: <cause>". A hit listed by Ivy and through Alice by Ivy shows one line
"listed by Ivy through Alice" (no second "listed by Ivy"). "Made from this"
shows "Installed" (no install button) for a mod that is installed. Test:
words.rs / words.js unit tests for each text, and the find window test for the
empty search and the collapsed via line.
AC6 Stale error. In the main window, when a slow failing call ends after a
newer call started (or succeeded), its error does not show; the error line
shows only the result of the latest action. Test: a words.js-style pure helper
(or the window test) where call 1 fails after call 2 succeeded: the error line is
empty.
AC7 TECHNICAL (9.2, 9.6, 9.7, 8.3, 13) and FUNCTIONAL say the above; NOTES.md
records changed facts.
