## Goal
A coding agent on a new machine runs `watane-dev doctor --json` first and learns, in one
object, what it has and what it lacks: the Rust toolchain, the `wasm32-wasip2` target, the
crate allowlist, the program `watane` and the home host. Every gap is an error with a `fix`
that is a command to run; `doctor` reports all gaps, not only the first. The template's
`AGENTS.md` tells the agent to run `doctor` first.

## Acceptance
- AC1 On this machine with a vendored allowlist (`WATANE_DEV_VENDOR` set to a vendor folder the
  test checks exists, or the source-tree `allowlist/vendor`), `WATANE_BIN` set to an existing
  executable file the test creates (`#!/bin/sh`, mode 0755), `WATANE_HOME` set to an empty temp
  folder and `WATANE_DEV_CACHE` a temp folder: `doctor --json` exits 0, `command` is `doctor`,
  `dir` is null, `errors` is empty, and `result` has the shape of TECHNICAL 2.4 **doctor**:
  `toolchain.{cargo,rustc,sysroot,version}` are strings (`version` starts with `rustc `),
  `toolchain.wasm32_wasip2` is true; `allowlist.vendor` is the vendor path,
  `allowlist.direct` equals the literal `["serde 1.0.229", "serde_json 1.0.154", "wit-bindgen 0.63.0"]`,
  `allowlist.crates` equals the number of `[[package]]` entries with a `checksum` that the test
  counts in `dev/allowlist/Cargo.lock` (the registry crates; the test counts, not dev);
  `watane` is the canonical path of the test's file; `home` is
  `{"path": <WATANE_HOME>, "running": false, "app": false}`. `next` is
  `watane-dev new <slug> --json`.
- AC2 Same, with `WATANE_BIN` naming a missing file: exit 3; `watane` is null; one error
  `env.watane_missing` whose message names the path and whose `fix` is
  `Install watane, or set WATANE_BIN to the program`; the other parts are still reported.
- AC3 Same as AC1, with `WATANE_DEV_VENDOR` naming a missing folder: exit 3; `allowlist` is null;
  error `env.allowlist` whose `fix` contains `scripts/vendor.sh`. A missing vendor folder found at
  the source-tree fallback path (`<CARGO_MANIFEST_DIR>/allowlist/vendor`) has the fix
  `<abs dev folder>/scripts/vendor.sh` (unit test on the fix builder; `test`/`serve` get the same
  fix, since they share `allowlist::vendor_dir`).
- AC4 All gaps at once: `WATANE_DEV_TOOLCHAIN` names a temp folder with no `bin/cargo`, the
  vendor and `WATANE_BIN` are missing: exit 3, `errors` holds `env.toolchain`,
  `env.allowlist` and `env.watane_missing` (in that order), each with a non-null `fix`;
  `toolchain`, `allowlist` and `watane` are null.
- AC5 A toolchain without the target: `WATANE_DEV_TOOLCHAIN` names a temp folder whose
  `bin/cargo` and `bin/rustc` are shell scripts (`rustc --print sysroot` prints a temp sysroot
  with no `lib/rustlib/wasm32-wasip2/lib`, `rustc --version` prints `rustc 9.9.9 (fake)`):
  `toolchain` is an object with that version and `wasm32_wasip2` false, and the error is
  `env.no_wasm_target` with fix `rustup target add wasm32-wasip2`. No cargo runs (the fake
  `cargo` writes a marker file if it does; the test checks the marker is absent).
- AC6 Home host: with `WATANE_HOME` holding a `run.json` whose port answers nothing,
  `home.running` is false and there is no error (a home host that does not run is no error).
  With `WATANE_HOME` the home of a real running preview (`#[ignore = "needs WATANE_BIN"]`: start
  it with `serve --json` on a template mod and use `result.home`), `home.running` is true and
  `home.app` is false.
- AC7 Text mode: `doctor` without `--json` prints one `error[<code>]` line per gap and a
  `fix:` line for each, then `doctor: ok` or `doctor: failed` (TECHNICAL 2.3).
- AC8 The template's `AGENTS.md` "Order of work" starts with `watane-dev doctor --json` and says
  to run each error's `fix` before going on; `new` renders it (the envelope test's template file
  list does not change).
- AC9 `cargo test -p watane-dev`, clippy `-D warnings --all-targets --all-features`,
  `cargo fmt --check` pass. Existing tests stay green.

## Interface
Provides: the command `watane-dev doctor` and its result (TECHNICAL 2.4, fixed as written
there). `next`: `watane-dev new <slug> --json` when ok, `watane-dev doctor --json` when a gap.
Takes from host (exists): `watane_host::{default_home, RunInfo}`; `GET /api/status` on the
`run.json` port answers `{"watane":1,"mode",...,"app":bool}`. `running` is true when `run.json`
reads and `/api/status` answers with `watane: 1` within 2 s; `app` is the answer's `app`.
S6-2 (sibling, parallel) edits `cli.rs` only in the `serve` branch and adds a warning code to
`outcome.rs`; keep your `cli.rs` change to the `Command` enum, its name match and one new arm.
