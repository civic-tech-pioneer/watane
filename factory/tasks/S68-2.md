## Goal

Reach, the rest of stage N4 (net/TECHNICAL.md 5.1, 5.10, 4.5, the N4 row of 9). Alice's own
machines find each other the ways NET-F-27 lists: mDNS on the local network, the addresses each

reached says so: "no direct path; choose a relay or turn on the DHT". A net with `relay_server`

switches live in `book.json` as node Q1 decided. Outcome: S11 passes, and the default endpoint

Do not edit `workspace-hack` (the product owner runs hakari). Write them into TECHNICAL 2 (replace

AC2 The switches (5.1, node Q1, 4.5). `set_options` writes `on`, `relays` and `dht` into
`book.json` (temp, fsync, rename, keeping other fields as `pairing.rs` does). At `open`:
`Options.on` false keeps the endpoint off whatever `book.json` says; with `Options.on` true,
`book.json` decides `on`, the relays and the DHT, and a new home's `book.json` has all three off,
so a fresh home opened with `on: true` stays off until `set_options` turns it on. `close` does not
write the switches (a closed node reopens as it was). `limits`, `bind` and `relay_server` come
from `Options` only. `Net::open` on a home whose `book.json` says `on: true` with `Options.on` true
turns on with the book's relays and DHT. Unit tests in `src/` for each rule. Test helpers in
`tests/support` (and the few direct `Net::open` calls in tests that expect a running node) call
`set_options` after `open`; keep their names and signatures.

AC3 Services by configuration (5.1, 5.10, 7). One pure function decides the endpoint's services
from the effective switches and the bind address (for example
`services(on, relays, dht, bind) -> Services { mdns: bool, relays: Vec<Url>, dht: bool }`):
mDNS is on when the endpoint is on and the bind address is not loopback (a loopback-bound node has
no local network to find machines on; tests bind 127.0.0.1); relays are exactly `relays` (no
default relay); the DHT exactly when `dht`. The endpoint builder applies it: the mDNS lookup of
`iroh-mdns-address-lookup` when `mdns`; `RelayMode::Custom` with those URLs when non-empty, else
`Disabled`; the mainline lookup (publish and resolve) when `dht`; still no portmapper, no
probes, no n0 DNS or pkarr-relay services. Unit tests of the function for each case (bind
`0.0.0.0:0` gives mDNS; `127.0.0.1:0` does not; `dht` and `relays` pass through), and
`no_default_services` keeps its assertions for a default node (no relay URL, no lookup beyond the
two in-memory ones, no mDNS, no DHT) and adds that a node with `relays` set has exactly those
relay URLs and still no DHT. No test builds an endpoint with mDNS or the DHT on: they are tested
by configuration only (no multicast or DHT traffic from a test). A real-DHT test, if you write
one, is `#[ignore = "internet: ..."]`.

AC4 Stored addresses (4.5 `addrs`, 5.10). After a connection to an own machine is made (dialed or
accepted, the address that worked), its address is stored in `book.json` `addrs` under the
machine's node key (text form), at most 4 per machine, newest first, only for machines of the
device list. At open they are the first known addresses of each machine (as `add_addrs` gives).
Unit test of the book round trip; an integration test that a reopened node redials its paired
machine with no `add_addrs` call (in `tests/sync.rs` or a new `tests/reach.rs`).

AC5 Addresses in `devices` answers (4.2 `devices`: `[list, addrs: [[node: bytes(32), [text]]]]`).
The callee passes on the addresses it knows of the machines of its list (other than the caller),
at most 4 each; the caller checks them (node in its list, each text a socket address, at most 32
machines, else `BadObject`) and adds them after its own known addresses. Codec unit tests in
`wire.rs` (round trip, each refusal).

AC6 Relay server (5.10, NET-F-29). With `Options::relay_server = Some(addr)` and on, net runs an
iroh-relay server on `addr` (HTTP, no TLS: the relay forwards only QUIC that is end-to-end
encrypted, and a self-run relay on an IP has no certificate a client would accept; no QUIC
address discovery, no metrics server, no ACME), stopped when net turns off or closes. New public
method `Net::relay_url(&self) -> Option<url::Url>`: `http://<bound addr>/` while it runs (with
port 0 the bound port), else `None`. Write it into TECHNICAL 3, and 5.10 (the URL the participant
adds to `relays` on the others is this one).

AC7 Unreachable (NET-F-28, 3 `Event::Unreachable`, 3.2). When a dial to an own machine fails (no
known address works) and neither relays nor the DHT are on, the error of the call
(`NetError::Unreachable`) and the keeper's `Event::Unreachable` carry the cause "no direct path;
choose a relay or turn on the DHT", with the machine's short key in the event or the error text as
S67 made the rule. With a relay or the DHT on, a failure has a cause that does not say so. A dial
gives up within the request deadline (no wait longer than 5 s in a test). The keeper emits the
event once per machine until that machine connects again (no flood each tick). Unit test of the
cause choice.

AC8 S11 (`tests/reach.rs`, `s11_machines_on_different_networks_connect_through_the_servers_relay`).
A laptop (anchor) and a second machine are paired on loopback, then both are closed and reopened
on new ports (so each one's stored addresses of the other are stale: two networks), no
`add_addrs`. A server (a third net, `relay_server` on `127.0.0.1:0`, on) gives `relay_url()`.

relay or turn on the DHT"; within 5 s an `Event::Unreachable` for the second machine says the same.

other within 10 s, and `hello` answers. The relay is an in-process iroh-relay on 127.0.0.1; nothing
reaches the internet.
