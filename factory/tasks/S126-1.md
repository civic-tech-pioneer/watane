Slice: S126 — Host removal, restart, HTTPS stream, and timer upkeep

## Goal

Removing a busy mod returns a diagnostic after a bounded wait. Restart cleans up timers left behind by interrupted removal. Regression checks observe the state that matters for timer origin, HTTPS backpressure and resume, and restart. The host handbook records the accepted home lock and judge limits.

## Acceptance

1. AC1. Hold the mod call lock through a short removal deadline. Removal reports that it timed out waiting for the named mod and leaves it installed. Release the lock and remove it successfully (unit test).
2. AC2. Reopen a home with a committed catalog that omits a former timer owner and origin. Delete the absent owner's rows, rebind a remaining owner's rows to itself when their origin is absent, and keep rows whose origin remains installed (unit test with disk-backed state, written before the fix).
3. AC3. A pending timer commit uses the original install generation to decide whether it can retain the origin. A replacement under the same identity gets no timer attribution from the old generation (unit test).
4. AC4. A loopback HTTPS writer pauses when its consumer defers. After resume, the consumer gets every event in order and sees the close (integration test). Restart preserves the linked provider and its state after the old home is released (integration test).
5. AC5. Run 20 repetitions of AC3 and HTTPS AC4 on Windows CI and 20 of restart AC4 on macOS CI. The build lead integrates the workflow.
6. AC6. Add a successful control firing to the timer cancellation test. Separate an incomplete response head from a parse error and pin the SSE parser's size boundary (unit test and loopback integration test).
7. AC7. Record the S125 rulings in host TECHNICAL 3.1 and 19.4. Confirm the S118 r2 comment and bounded readiness check are present.
