## Goal
dev ships `ScriptedResponses`: a local HTTPS server for tests that stands in for OpenAI's
Responses API (`api.openai.com`) and for a judge (`judge.test`), each origin on `127.0.0.1` with
a certificate from a test authority made for the run. A test scripts its replies (SSE events,
statuses, usage limits, redirects, resets, stalls, raw replies), sets the bearer token or key it
expects, and reads back every request it received. The same server runs as the program
`scripted-responses`, which prints one JSON line with its addresses and CA and serves until
killed. No real OpenAI call is ever needed in CI.
## Acceptance
Tests in `dev/src/scripted.rs` (unit) and `dev/tests/it/scripted.rs` (a new module of the `it`
binary; `mod scripted;` in `tests/it/main.rs`). The client side of a test is `reqwest` (rustls,
the CA from `ca_pem()` as its only added root, a resolver override of `api.openai.com` and
`judge.test` to the addresses). Oracles are literals.
AC1. `start()` binds two free ports on `127.0.0.1`; `responses_addr()` and `judge_addr()` differ;
     `judge_origin()` is exactly `https://judge.test`; `ca_pem()` is one PEM certificate. A TLS
     connection to `responses_addr` for the name `api.openai.com` verifies against `ca_pem` alone;
     for `judge.test` on `judge_addr` too; the system roots do not trust it.
AC2. Responses origin: `POST /v1/responses` with no script answers the default: status 200,
     `content-type: text/event-stream`, the events `response.output_text.delta` with `"delta":"ok"`
     and `response.completed` with a usage, each as `data: <json>\n\n`. `script(vec![..])`
     consumes replies in order, the last repeats. `GET /v1/models` answers the slugs of
     `models(..)` (a JSON object as dev 18.3 states; write the exact shape into 18.3). Any other
     method or path: 404, and it is recorded.
AC3. Each `Reply`: `Sse(events)` sends each `SseEvent` as one write (`Delta`, `ToolCalls(n)` with n
     parallel `function_call` items each with a distinct call id, `Completed{..}` with the usage,
     `Failed{code}`, `Raw(line)` verbatim, `Cut` ends the body without `response.completed`);
     `Status{code,body}`; `UsageLimit{resets_in_s}` is 429 with an error body whose code is
     `usage_limit_reached` and that names the reset; `Redirect(url)` is 307 with `Location`;
     `Reset` closes before the first byte; `Stall` keeps the connection and sends nothing (a client
     with a 1 s read timeout times out); `Raw{..}` as given. A test per variant.
AC4. `expect_token("t")`: a request without `Authorization: Bearer t` (missing, or another token)
     is answered 401 and recorded. `requests()` returns every Responses request in arrival order
     with method, path, every header as received, and the body bytes whole (a 2 MiB body is
     recorded whole).
AC5. Judge origin: `judge().script(plays)` consumed in order, last repeats; `Safe/Unsafe/Unsure`
     answer `{"verdict":"safe"|"unsafe"|"unsure","reasons":[..]}`; `Down` reads the request then
     resets; `Slow{ms,then}` waits then plays `then`; `Unreadable` is 200 with a non-JSON body;
     `Redirect` 307; `Raw` as given; `expect_key` answers a wrong or missing key 401.
     `count()` counts every request that reached the judge origin whatever the play;
     `requests()` records them.
AC6. The program `scripted-responses` (a `[[bin]]` with `required-features = ["fake-claude"]`, as
     dev 18.1 says): with no arguments its first stdout line parses as
     `{"scripted":1,"responses_addr":"127.0.0.1:<port>","judge_addr":"127.0.0.1:<port>","judge_origin":"https://judge.test","ca_pem":"<PEM>"}`
     and the default script serves. `--script <file>` reads
     `{"token"?,"models"?,"replies"?,"judge_key"?,"plays"?}` with `Reply`, `SseEvent`, `Play` in
     their serde form (externally tagged, kebab-case); a test scripts a `usage-limit` and reads it
     back. `--log <dir>` writes `<dir>/responses/<n>.json` and `<dir>/judge/<n>.json` from 1 as
     `{"method","path","headers","body_b64"}`. The test kills the program at the end (no
     process left behind; on Windows the same test kills it with `Child::kill`).
AC7. The server never listens on any address but `127.0.0.1` (a test reads both addresses), and
     the crate's release build of `watane-dev` builds it (it ships, 18.1); clippy with
     `--all-features` and nightly fmt clean. Every test also runs on Windows (no Unix-only API).

## Interface
Provides, exactly as dev TECHNICAL 18.3 states: `watane_dev::scripted::{ScriptedResponses, Reply,
SseEvent, Recorded, Judge, Play}` with the methods listed there, all `Send + Sync`, and
`Reply`/`SseEvent`/`Play` `Serialize + Deserialize` (kebab-case, externally tagged). The program
`scripted-responses` and its first line. s111-3 uses both against the host's `test-net`
(`TestNet { routes: [("api.openai.com", responses_addr), ("judge.test", judge_addr)], root_pem:
ca_pem }`). Takes nothing from s111-2.
