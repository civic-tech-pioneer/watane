Subsystem: pkg
Effort: medium
Depends on: none
Slice: S91 — a maker or a mod hits an edge and gets a named cause, not raw I/O text.

## Goal
When a mod folder changes under watane while `add_provider` writes or `pack` reads it, the maker
reads one of pkg's own causes (`changed while the mod was read; read it again`, a link, a special
file, "expected a regular file or a content directory") with the path relative to the mod, never
raw OS text such as "wit/deps: File exists" or "No such file or directory". A directory swapped in
where pack listed a file is named as a directory, not as a FIFO/socket/device.

## Acceptance
AC1. `add_provider` under a swap race: an entry of the consumer's `wit/deps` (or the provider's
     `wit`/`wit/deps`) that is created, removed or replaced between preflight and write (use the
     existing `#[cfg(test)] hook` in pkg/src/add.rs) gives `ModError::Invalid` with rule `path`
     and the `CHANGED` text (pkg/src/refusal.rs) at the relative path, not `ModError::Io` with
     "File exists"/"No such file or directory". Cover at least: a name created at the target
     after preflight (EEXIST on mkdirat/openat CREAT|EXCL) and a directory removed after
     preflight (ENOENT).
AC2. `pack`: a file listed by the walk and gone before it is opened for reading gives
     `PackageError::Mod(ModError::Invalid([path, <file>, CHANGED]))` (or a `PackageError::Path`
     with the CHANGED reason; pick one, write it in TECHNICAL 6.4), never `PackageError::Io`.
AC3. `pack`: a regular file listed by the walk and replaced by a directory before it is opened
     gives a refusal that names a directory (e.g. "expected a regular file, found a directory"
     or CHANGED), not `refusal::SPECIAL`. A real FIFO or socket still gives SPECIAL (the
     existing s57 tests stay green).
AC4. `pack_error` no longer maps every `InvalidInput` to SPECIAL: `open::file` reports a
     non-regular final handle with a cause the caller can tell apart (directory vs special).
AC5. Tests are deterministic (a test hook or a fixture state, not a timing race), at the lowest
     level that shows them: unit tests in pkg/src/add.rs/package.rs or modules in pkg/tests/it.

## Spec
pkg/TECHNICAL.md 4.7 (rules, CHANGED), 4.8 (`add_provider`), 6.4 (pack; the list-then-open
paragraph at its end), 8 (errors). Update 4.8 and 6.4 to say which cause each race gives.

## Interface
None to siblings. Public signatures of pkg stay as they are (TECHNICAL 8); only error values and
texts change.
