Subsystem: node
Effort: medium
Depends on: s124-1
Slice: S124 — a failed fetch blames the true cause (net, node, dist), and net's budget flake
## Goal
On a light machine, a failed fetch, follow or install tells the person the true cause instead of
dist's "channel ... is not followed; follow the publisher's link": with every full machine off it
says no full machine is reachable; when the full machine's copy is bad it says so; when the cause
is this machine (holder refusal, local I/O) it names this machine; and `DistError::Io`'s top line
names the party, not a bare "the server".
## Acceptance
AC1. With every full machine of the device list off (net on, list present, none reachable), a
     light `fetch`/`follow`/`open_link` whose dist call then fails for a missing source
     (`NotFollowed`, `NoRelease`, `UnknownRelease`, `StaleBases`) returns an error whose top line
     names a full machine and whose chain contains `no full machine is reachable`, not
     "is not followed". `Off` is still dropped (net off: dist's own error stands). A web-host
     success still wins: if dist finds the release from a link location, the fetch succeeds.
AC2. A light install/fetch whose real cause is the full machine's bad copy (net's
     `NotServed`, or `BadObject` for a cut stream) returns that cause (in the chain:
     `node <short> did not serve package ...` or `sent a bad object`), not "is not followed".
     If node drops the blob error before dist's no-base fallback anywhere
     (`need_release`, `need_latest`, `need_package`, the install path), fix it so the package's
     error comes before the channel's (5.3).
AC3. net's `NotTaken` and `Io` (and `Corrupt`, any non-remote error) become `DistError::Io`
     with path `this machine`; `Refused`, `Unreachable`, `Timeout`, `TooLarge`, `BadObject`,
     `NotServed` and `NoFullMachine` become `DistError::Io` with path `your full machine`
     (replacing "the server"). The chain then reads e.g.
     `your full machine: node <short> refused: not_allowed` (keep the substring
     `node <short> refused: not_allowed`: app/tests/it/j8.rs asserts it) and
     `this machine: this machine did not take channel ...` is acceptable but prefer no
     repetition: for `NotTaken` use the cause as it is.
AC4. A local I/O or holder error during a download reads as local: no "unreachable", no node's
     short key, no temp path anywhere in the chain (net s124-1 gives `Io` without the path; node
     must not add one).
AC5. Tests at the lowest level that shows each: unit tests in `node/src/calls.rs` for the
     mapping, and an integration test in `node/tests/it/` (e.g. `causes.rs`, `light.rs`) on real
     `Node`s for AC1 (full machine off) and AC2 (a bad copy on the full machine, as
     app/tests/it/j8.rs AC5 makes one: corrupt the full machine's package file after it is
     referenced). If `watane-node`'s program output (TECHNICAL 6.2) prints these, a `program.rs`
     test covers one.
AC6. `node/TECHNICAL.md` 5.3 (and NO-14 / section 14 if it states the old rule) says the new
     mapping; `NoFullMachine` is no longer dropped when dist then finds no source.
AC7. `cargo test -- --include-ignored` for touched files, clippy (`-D warnings`) and nightly fmt
     pass in node/; `factory/check.sh s124-3 <base>` passes.
