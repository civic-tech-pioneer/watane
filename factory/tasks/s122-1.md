## Goal
The installed provider can use its judge key through the existing HTTPS stream interface. The host enforces identity, method, origin, grant and revocation at the points specified by A5.

## Acceptance
1. AC1. The provider's granted POST arrives at the scripted judge with its bearer key. No redirect is followed.
2. AC2. Without a key for the exact identity, and in preview, a judge request ends no-account with zero requests. A mismatched destination or method is refused. Other account values retain their existing results.
3. AC3. The shared parser folds case and drops port 443 and a lone slash. Paths, queries, fragments, userinfo and non-HTTPS origins return bad_request.
4. AC4. At apply the host rechecks binding. An account change ends the affected provider's live streams gone without ending other accounts' streams.

## Spec
Host TECHNICAL 19.4, 19.7, 19.9 and HOST-F-72. W39 in spec/TECHNICAL section 6.

## Interface
Export `watane_host::judge_origin(text: &str) -> Result<String, HostError>`. The existing `AccountSource::judge(&self, provider: &str) -> Result<JudgeAccount, AccountError>`, `JudgeAccount { key: String, origin: String }`, `Account::Judge { provider: String }` and `Host::account_changed(&self, account: &Account)` are the app contract. No WIT change.
