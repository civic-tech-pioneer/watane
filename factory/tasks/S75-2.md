## Goal
`app/tests/j8.rs` runs J8 (spec/FUNCTIONAL.md) on the real programs on one Mac, on loopback
homes: Alice's laptop app is the anchor, `watane-node` her server (full), a second laptop app
(light), and a restored laptop app. It passes against S75-1's app, and J2 to J5, J9 still pass.

## Acceptance
`app/tests/j8.rs` (`#![cfg(feature = "driver")]`), one `#[ignore = "slow: ..."]` journey test
`ac1_journey_j8` like `j2.rs`'s, quiet (never `front:`), with these checks in order:
- AC1 Alice's app turns own machines on (`machines_on(true)`), asks a full code; `watane-node
  join --bind 127.0.0.1:0 <code>` prints its short key; the consent DOM shows that same key and
  `full`; approve; `watane-node run --bind 127.0.0.1:0` runs; both list each other.
- AC2 A second `watane-node join` with the same code (a fresh node home) is refused (exit 1).
- AC3 Alice publishes a release through `POST /api/publish` (the committed `reading-list`
  fixture, as J3 does): the server's `<home>/dist/packages/` holds that package byte-equal within
  5 s (poll, no fixed sleep beyond the deadline), and no static host (no `tower-http` server, no
  site served) exists in the test up to this point.
- AC4 A second app home (signed nothing) joins as light; Alice approves. Ivy (a home made with
  `watane_dist` in the test, as j4.rs and find.rs do) lists `reading-list`; Alice's app chooses
  Ivy's index, so the server holds it. The light app searches `reading`: the hit's `from` names
  the server's short key and `verified: true`; it installs and the mod runs (its window opens).
- AC5 The server's stored package gets one changed byte (in its `<home>/dist/packages/` file);
  the light app's fetch of it is refused and its `machines` `problems` names the server's short
  key (`refused <short>: ...`).
- AC6 Alice removes the light laptop; the server then refuses it (its next fetch through the
  server fails; the server's `run` prints its event).
- AC7 A restored laptop app (Alice's backup restored on a fresh home) joins with a full code and
  `replace`; its identity view lists the server's hint with its seq; `POST /api/publish` is
  refused until it confirms the hint (`identity_confirm_hint`); the next publish has the next seq.
- AC8 Every machine's `<home>/net/book.json`: `relays` empty, `dht` false.
- AC9 `cargo test -p watane-app --features driver --test j8 -- --include-ignored` passes, and
  `--test j2 --test j3 --test j4 --test j5 --test j9` with `--include-ignored --skip front:`
  still pass; clippy and fmt clean. Never run `front:` tests.
