## Goal
The new `log` crate exists (package `watane-log`, lib `watane_log`) with stages L1 and L2:
a public key and an entry id have exactly one text form each; `Log::open(dir)` creates or reads
the identity key file with the strict modes and refusals; `Entry::decode` accepts an entry only
under the deterministic encoding and the strict signature rule, and names the first failed check.
The workspace builds it as a member.

## Acceptance
- AC1 (S1) Fresh temp dir: `Log::open` makes the dir mode 0700 and `identity.key` 0600, 32 bytes;
  a second open gives the same `identity()`.
- AC2 (S2–S4) Key file 0640 -> `Error::Exposed` naming path and mode 0640, bytes and mode
  unchanged; key file a symlink to a valid key -> `NotPlain`; 31 bytes -> `CorruptKey`. Each
  message contains the words of the scenario ("exposed"/mode, "not a regular file", "corrupt key file").
- AC3 (S5) RFC 8032 test 1 seed written by the test: `identity()` equals the RFC public key, and
  its `to_string()` equals the oracle `zbase32()` (bit-by-bit, in the test) and
  `47pjoycnsrfmxikm95jh13y88e8qnhzu5kungjpxyepgt7a8krpy`; `fingerprint()` is its first 10 chars.
- AC4 (S6) `PublicKey::from_str` refuses 51 and 53 chars (`Length`), upper case and a char outside
  the alphabet (`Alphabet`), non-zero unused bits (`UnusedBits`), a small-order point (`SmallOrder`),
  a non-canonical encoding (`NotCanonical`). `EntryId` text: 64 lower hex round-trips; upper case
  and other lengths are `IdTextError`.
- AC5 (S16) Both golden vectors of section 4.4 decode with the listed fields, lengths and ids; an
  entry built by the oracle `cbor::` builder and signed with `ed25519-compact` decodes with every
  field equal and `id()` = BLAKE3 of the bytes.
- AC6 (S17) Each refusal listed for `entry_codec.rs` in section 8.2 gives the `DecodeError` of
  section 4.6 for that case.
- AC7 (S18) Each case listed for `strict_verify.rs` in section 8.2 is refused; a valid `sign()`
  entry is accepted.
- AC8 `cargo test -p watane-log`, `cargo clippy -p watane-log --all-targets -- -D warnings`,
  `cargo fmt --check` pass; `cargo build` of the whole workspace still passes.
