## Goal

Stage N3 of net/TECHNICAL.md 9. Own machines keep a connection to each other while both are on;
on connect, on a hint and every 10 minutes each pulls what its role needs and its holder lacks
(5.6). After an own append the holder's caller calls `Net::told`, which broadcasts a hint on the
own-machines iroh-gossip topic (5.7); a machine that gets a hint pulls that channel from the
machine that delivered it, so Alice's server has her new entry within seconds. Packages move over
iroh-blobs, added to `<home>/net/blobs/` by reference, fetched for `holdings.wanted_blobs(role)`,
checked by hash and size, and handed to `holdings.store_blob` (5.8). Everything another machine
sends is checked before the holder sees it; a machine that sends a bad object is reported
(`Event::Refused`) and dropped for the session. The iroh-blobs and iroh-gossip handlers sit in the
`Gate` N2 built, so only trusted nodes reach them. The holder is still `tests/support::MemHoldings`
(node 1 builds the real one); the `Holdings` trait of 3.1 does not change.

## Acceptance

AC1 API (net TECHNICAL 3). `Net` gains `told(&self, channel: &PublicKey, seq: u64, id: &EntryId)`.
N3 emits `Event::Pulled`, `Event::Refused`, `Event::PeerUp` and `Event::PeerDown` (variants exist
since N2). The public types and the `Holdings` trait are otherwise unchanged. `need`, `need_blob`,
`query`, `own_heads` stay unbuilt (N4); `query` stays `unknown_op`.

AC2 Kept connections and sync on connect (5.2, 5.6, replaces ND-13). When `on` and an own machine
is reachable (its address known through `add_addrs` or the hints of a code, or it connected to us),
a node keeps one connection to it, calls `hello` on it, emits `PeerUp(node)`, and runs one sync
(5.6 steps 1 to 4); when the connection ends it emits `PeerDown(node)` and redials (bounded backoff,
at most every few seconds; never an unknown node). Only one sync per pair of machines runs at a
time. A sync also runs every 10 minutes per own machine (`Limits` or a private constant; a test may
shorten it through `Limits` only if you add a field that `hello` does not send — say so in 9).
Unit or integration test: two paired nodes, B's holder lacks a channel A holds; within 5 s of the
pairing (or of B's open with A's address) B's holder has the same entries (byte for byte), and B
got `Pulled { channel, seq, from: A }`.

AC3 Sync rules (5.6, NET-F-21, NET-F-22, NET-F-23). A full machine asks `heads` with an empty list;
a light machine asks for the channels of `holdings.heads(None)` only. For each channel whose
remote seq is above the holder's, `entries` from own seq + 1 in pages until the remote seq; each
page passes ND-14's checks before `holdings.ingest(channel, page, Kept)` (full) or `Asked`
(light); `NotWanted` stops that channel; a `forked` channel also gets `fork`, both entries
ingested. Then the packages of `holdings.wanted_blobs(role)` (AC5). Tests: a light machine does
not pull a channel it does not hold; a holder that answers `NotWanted` gets no second page.

AC4 Hints (5.7, node/TECHNICAL.md 13 Q3). Every own machine joins the iroh-gossip topic
`BLAKE3("watane/own/1\0" ‖ anchor node key bytes)`, bootstrapped from the machines of its device
list it can reach, and rejoins when the device list changes. `told(channel, seq, id)` broadcasts
the CBOR array `[channel: bytes(32), seq: uint, id: bytes(32)]` (72 bytes; a unit test checks the
bytes against a hand-built expectation). A received message that does not decode exactly is
dropped. A hint is acted on only when its seq is above the holder's head for that channel, and:
on a full machine for any channel; on a light machine only for a channel in `holdings.heads(None)`
(write this rule, node Q3, into net/TECHNICAL.md 5.7 and mark node Q3 answered in net 12 if it is
listed there). Acting is step 2 of 5.6 for that channel with the machine that delivered the hint;
a failed or empty pull changes nothing. Write the Q3 rule into 5.7 yourself; it is decided.

AC5 Blobs (5.8, Q1 answered in N1). The iroh-blobs store lives in `<home>/net/blobs/` (persistent,
0700). Serve: a trusted caller can fetch a package by hash when `holdings.blob(id)` gives a path;
`net` adds that file by reference (`ImportMode::TryReference`, no second copy) and does not serve
a hash the holder does not give (any more). Choose how net learns the ids to add — the trait has
no list of held blobs, so add on request (an iroh-blobs provider event or request hook, checking
`holdings.blob` before the transfer) or another way that keeps 3.1 unchanged — and record it in
the N3 notes of 9. If no way exists without changing 3.1, stop and report `BLOCKED` with the
options. Fetch: for each `(id, size)` of `wanted_blobs(role)`, download by hash from the own
machine being synced, verified by iroh-blobs while it streams; refuse more than `size` bytes and
more than `limits.blob` (64 MiB); apply the blob deadline; export to a temp file under
`<home>/net/`; check BLAKE3 and size again in net; `holdings.store_blob(id, temp)`; then the
store keeps only a reference to the holder's file (or nothing). The temp file is removed in every
case.

AC6 Gate around the other protocols (5.4, 4.2 allowances). The router accepts `watane/1`,
iroh-blobs' ALPN and iroh-gossip's ALPN, each in `Gate`; an unknown node is closed on the blobs and
gossip ALPNs before the inner handler sees it (extend `allowed` in `allow.rs`; a unit or
integration test: an unknown node's blob download and gossip join fail, and its gossip message
never reaches a hint).

AC7 S5 (`tests/sync.rs`, `s5_alice_publishes_and_the_server_has_it_within_seconds`). Laptop
(anchor) and server (full), paired, both on, connected. The test appends a new entry (signed with

AC9 S7 (`tests/sync.rs` or `tests/faults.rs`, `s7_bad_objects_are_refused_and_the_machine_dropped`).

node field); after the refusal the fake is dropped for the session: no further sync with it and its
hints are ignored, until the `Net` is reopened.
