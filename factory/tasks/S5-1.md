Slice: S5 — The agent works the mod through MCP: it runs `serve --json`, points an MCP client at `result.mcp` with its token, lists the counter's calls, calls `add`, and Alice's open page shows the new count by itself.

## Goal
A preview host serves MCP at `/mcp/<toolset>` (host stage 4). The program `watane --preview`
issues one token for the implicit toolset `preview` and prints `mcp` and `token` in its ready
line. An agent with that token lists every callable function of every enabled mod as a tool
(name, WIT doc comment or signature, input schema) and calls them as `Caller::Agent(<handle>)`;
a successful call that changes state reaches the mod's open pages as `changed`, as a page call
does. Every request that is not exactly right is refused as host 10.3 says.

## Acceptance
- AC1 (S14) A toolset `t` set to `["counter:api"]` with `set_toolset`, a token for `t`:
  `tools/list` names exactly `counter_api_add`, `counter_api_add-then-fail`, `counter_api_get`,
  `counter_api_who`, sorted (update S14 in FUNCTIONAL.md: it predates `who`). Each tool has
  `inputSchema` `{"type":"object","properties":{},"required":[],"additionalProperties":false}`
  for these no-param functions (literal), and a `description`: the WIT doc comment when the
  function has one (give the fixture's `add` a `///` doc comment in both `wit/` copies and
  compare with that literal), else the signature literal `get: func() -> u32`. An entry
  `counter:api.get` gives only `counter_api_get`. A function with params (e.g. the `echo`
  fixture) gets a schema whose properties and `required` the test writes out literally.
- AC2 `Host::functions(&local)` returns the counter's four functions as `FunctionInfo` with
  interface `mods:counter/api@0.1.0`, name, params, result `Some("u32")` for `add`, and docs;
  a page-only mod gives an empty list; an unknown local gives `no_mod`.
- AC3 (S15) On `/mcp/t`: no `Authorization` 401 with `WWW-Authenticate: Bearer`; a token after
  `end_token` 401; a token of another toolset 403; any `Origin` header 403; `GET` and `DELETE`
  405 with `Allow: POST`; a content type other than `application/json` 415; a body over 1 MiB
  413; a JSON array body 200 with error code `-32600`; a notification (no `id`) 202 with an
  empty body. `end_token` returns true once, then false.
- AC4 `initialize` with `protocolVersion` `2025-03-26` answers `2025-03-26`; with `1999-01-01`
  or none answers `2025-06-18`; `capabilities` `{"tools":{"listChanged":false}}`, `serverInfo`
  name `watane`. `ping` gives `{}`. An unknown method gives `-32601`. `tools/call` of a name not
  in the toolset gives `-32602` with message `unknown tool <name>`.
- AC5 `tools/call counter_api_add` (no `arguments`) returns
  `{"content":[{"type":"text","text":"1"}],"isError":false}`; an `/events` stream open on
  `counter` receives `{"type":"changed"}` after it. `counter_api_who` returns text
  `agent:<handle>` for the token's handle. `counter_api_add-then-fail` returns `isError: true`
  with text starting `trap: `. A `result<A, B>` return gives `A`'s text or `B`'s text with
  `isError: true`, and a JSON string's text is the string: cover it with a fixture function if
  one exists, else unit tests of the text function on literal values.
- AC6 The program: `watane --preview <dir> --install <counter>` prints a ready line whose `mcp`
  is `http://localhost:<port>/mcp/preview` and `token` matches `^wt_[A-Za-z0-9_-]{43}$`; that
  token lists the counter's tools on `/mcp/preview` and is refused (403) on `/mcp/other`. No file
  under the home contains the token text. Update the existing `"mcp":null,"token":null` literal.
- AC7 `set_toolset("preview", ..)` is `bad_name`; a bad name or entry (`Counter:api`,
  `counter`, `counter:api.`, `counter:api.add.x`) is `bad_name` / `bad_toolset_entry`;
  `toolsets.json` on disk holds the set toolset (read back as literal JSON). A tool name over 64
  bytes is left out (unit test of the name rule).
- AC8 `cargo test -p watane-host`, clippy `-D warnings --all-targets`, `cargo fmt --check` pass.
  Existing tests stay green.

## Interface
Provides to S5-2 (dev; fixed): the ready line in a preview has `mcp` =
`"http://localhost:<port>/mcp/preview"` and `token` = `"wt_..."`; `watane_host::Ready` keeps its
fields and types. The token goes in `Authorization: Bearer <token>`.
Public on `Host` (exactly 2.1's signatures): `functions`, `set_toolset`, `issue_token`,
`end_token`. Types `ToolsetName`, `Handle`, `Token` (`as_str()`, `id()`), `TokenId`,
`FunctionInfo` (2.5). `Caller::Agent(Handle)`; `who()` gives `agent:<handle>`.
`Served::mcp_url(&ToolsetName)`.
