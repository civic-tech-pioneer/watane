## Goal

`consent::ac5_a_consent_given_through_one_provider_is_not_used_through_another` and
`https_stream::ac5_a_refused_consent_ends_the_stream_consent_refused` pass every time on
ubuntu, macos-26 and windows-latest. Each race is named; neither is one a person can hit, so
both are fixed in the tests.

Races, from the attempt-1 logs:
- PR #30 run 45481401334 (ubuntu) and PR #29 run 45487544428 (macos-26):
  `consent.rs:533` saw `[]` where the `consent-pending` item was due. The host pushes the item on
  the stream before it asks the app (run.rs `consents`), but the stream's consumer (the fixture
  mod `claude`) receives items on the host's delivery thread, after the question may already be
  recorded. Items reach a consumer asynchronously by design (19.1); a person sees the item a
  moment later. Test: wait for the item (`wait_items`) instead of reading it once.
- PR #29 run 45487544428 (windows-latest): `https_stream.rs` `answer(0)` panicked with "index out
  of bounds: the len is 0" and then poisoned `held`. The test app pushed the question to `asked`
  before its sender to `held`; `wait_asked` saw the question and `answer` read an empty `held`.
  Test: push `held` first. The same order is fixed in `consent.rs` and `agent_tools.rs`, whose
  test apps had the same window.

## Acceptance

AC1: both tests green 20 times in a row on each of the three OSes, run with their modules for

`#[cfg(unix)]` (tests/it/main.rs), so on windows-latest only the https_stream test exists.
AC2: nothing in `host/src` changes.
