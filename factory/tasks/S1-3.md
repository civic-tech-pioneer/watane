Effort: medium
Slice: S1 — Hello page: a coding agent runs `watane-dev new hello`, then `watane-dev serve --json`, opens `result.pages[0].url` and sees the template page.

## Goal
The program `watane-dev` exists with `new`, `check`, `serve` and `serve --stop`. A coding agent runs
`watane-dev new hello --json`, `watane-dev check --json`, then `watane-dev serve --json`, and opens
`result.pages[0].url` to see the template page served by the real `watane --preview`. Every command
prints the result envelope of 2.1 and exits with the status of 2.2. The template of this slice is
page-only; logic, tests and the builder join in later slices.

## Acceptance
- AC1 (DEV-S-1, page-only) In an empty folder, `watane-dev --json new hello` exits 0; stdout is one
  envelope (`schema` 1, `command` "new", `ok` true, `dir`, `result`, `errors` [], `warnings` [],
  `next`); `result.slug` is "hello"; `result.files` is exactly
  `[".gitignore","AGENTS.md","CLAUDE.md","mod.toml","ui/app.js","ui/index.html","wit/world.wit"]`;
  `wit/world.wit` starts with `package mods:hello@0.1.0;`.
- AC2 (DEV-S-2, S-3) `new hello` where `hello` exists exits 2 with `usage.exists` and changes
  nothing; `new Hello --json` exits 2 with `usage.slug` and creates nothing.
- AC3 In the new folder, `check --json` exits 0 with `result` = `{"slug":"hello","version":"0.1.0",
  "name":"Hello","page":true,"logic":false,"grants":[],"exports":[],"events":[],"calls":[],
  "subscriptions":[],"providers":[]}`. Outside a mod folder `check --json` exits 2 with
  `usage.not_a_mod` (DEV-S-32 stage 0). A pkg `Violation` (e.g. `mod.toml` without `summary`) is
  `mod.invalid` with its `file`, exit 1. A symbolic link in the folder is `mod.symlink`, exit 1.
- AC4 (DEV-S-21, page part) `serve --json` in the new folder exits 0; a GET of `result.pages[0].url`
  (`http://hello.localhost:<port>/`) returns the bytes of `ui/index.html`, with the
  `Content-Security-Policy` header of host 8.3; `result.reused` is false, `result.mcp` is null,
  `result.home` is `<cache>/previews/hello-<h8>/home`, `result.log` is that folder's `watane.log`.
  The page loads its script from `app.js` (no inline script).
- AC5 (DEV-S-22, page part) After an edit of `ui/index.html`, `serve --json` again exits 0 with
  `reused` true, the same port, and the GET returns the new bytes.
- AC6 (DEV-S-23) `serve --stop --json` exits 0 with `{"stopped":true,"home":...}`; a TCP connect to
  the port then fails; the preview folder is gone. A second `serve --stop` gives `stopped` false, exit 0.
- AC7 (DEV-S-24) With `WATANE_BIN` naming a missing file, `serve --json` exits 3 with
  `env.watane_missing` and its fix.
- AC8 `cargo test` passes; the tests that need the real host (AC4 to AC6) read `WATANE_BIN` and
  are `#[ignore = "needs WATANE_BIN"]`; they pass with
  `WATANE_BIN=$PWD/../host/target/debug/watane cargo test -- --include-ignored` (build host first:
  `cargo build --manifest-path ../host/Cargo.toml`). Integration tests run the binary with
  `WATANE_DEV_CACHE` in a temp folder and parse stdout with `serde_json`. Clippy `-D warnings` and
  `cargo fmt --check` pass.

## Interface
Takes from `watane-pkg`: `Slug::from_str`, `Mod::read`, `Mod::{slug, version, name, page, logic,
world, grants, deps}`, `World`, `Grant` (`Display`), `ModError::{Invalid, Io}`, `Violation`, `Rule`.
Takes from `watane-host` (task S1-2, on this branch): `Ready`, `ReadyMod`, `RunInfo::read`,
`InstalledMod`; the program `watane --preview <dir>` (ready line on stdout, then stderr only; SIGTERM
removes `run.json`); `GET /api/status` → `{"watane":1,"mode","home","port","app"}`;
`POST /api/install {"folders":[abs]}` → `{"installed":[InstalledMod]}`, errors
`{"error":{"code","message"}}`. In S1 the ready line's `mcp` and `token` are null.
Provides: the envelope of 2.1, the exit statuses of 2.2, the results of 2.4 for `new`, `check`,
`serve`, `serve --stop`. `serve`'s `mcp` is null while the ready line has no token.
