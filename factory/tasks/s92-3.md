## Goal
One node leftover (S87's user-sim), re-checked against main `ec744f4` on 2026-11-20: still open. On a
light machine, `Node::fetch` calls `net.need`/`net.need_blob` first and keeps only a
`NetError::Refused` (node/src/calls.rs:10-38, `refusal`, `refused_or`; TECHNICAL 5.3, NO-14). When Alice's
full machine holds a bad copy of the package (its file no longer matches the hash), `need_blob` fails
with `Unreachable { node: <full>, cause: "package <hex8> was not fetched: not served: ..." }` or
`BadObject { node: <full>, .. }` (net 5.9, "which one is timing (S87)"); node drops it, dist then has no
base for a held, unfollowed channel and answers `NotFollowed` ("channel ... is not followed; follow the
publisher's link"). Alice is told to do something that does not help, and the real cause shows only in
Machines.

After this task, on a light machine, node keeps every `need`/`need_blob` error except `Off` and
`NoFullMachine` (those mean net had nothing to say about any machine), and when dist's call then fails
with no source (`NotFollowed`, `NoRelease`, `UnknownRelease`, `StaleBases`), that error is returned in
its place, as today for a refusal. So the failed install names the full machine and its cause.

Decided here (not by you):
- Kept: every `NetError` but `Off` and `NoFullMachine`. Precedence as today: the package's error
  (`need_blob`) before the channel's (`need`).
- The wrapper stays `DistError::Io { path, source: std::io::Error::other(net) }`, with `path`
  `"the server"` when the net error names another machine (`Refused`, `Unreachable`, `Timeout`,
  `TooLarge`, `BadObject`) and `"this machine"` for any other (`Io`, `Corrupt`, ...: net task s92-2
  makes a local failure `Io`; do not wait for it, a unit test can build `NetError::Io` directly).
- Every other rule of 5.3 stays: dist still reads first; a dist error that is not "no source" stands.
- Rename `Refusal`/`refusal`/`refused_or` to fit (e.g. `NetCause`/`kept`/`cause_or`); keep it one small
  function each.
