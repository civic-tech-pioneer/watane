## Goal

The `watane-net` crate exists in the workspace (stage N1 of net/TECHNICAL.md 9). A home gets a
node key on first open with no network contact, and keeps it. With net on, two local nodes
(loopback, no relay, no discovery) connect over QUIC with ALPN `watane/1`, and a node that the
other trusts can ask it `hello`, `heads`, `entries` and `fork`, answered from that node's holder
(`Holdings`), with every byte limit and deadline of 4.2 enforced on both sides. An unknown node
gets `hello` only. The pairing code text parses and formats. The one signed form of 4.3 (the
device list's bytes) encodes, signs and verifies, pinned by golden vectors made with
`ed25519-compact`. Two library checks (net Q1) are tests against the pinned iroh releases.

AC2 Node key and S1 (`tests/node.rs`, `s1_new_home_net_off`). `Net::open(dir, holdings, Options
{ on: false, .. })` on an empty dir creates `dir` (0700) and `dir/node.key` (0600, exactly 32
bytes, the seed), with the rules of log's key file (log/TECHNICAL.md 4.7: wrong length or mode
is `Corrupt`, the file is not changed). A second open gives the same `node_key()`. With `on`
false, no socket exists: on Linux the test counts socket fds in `/proc/self/fd` before and after
open (in a test binary with this one test, so no other test opens sockets meanwhile) and finds
no new one; `Net::addrs()` is empty. Then `set_options(on: true)` binds; `set_options(on:
false)` closes the endpoint and `addrs()` is empty again. The key text is 52 z-base-32 chars, the
same as log's `PublicKey` (NodeKey may convert through it); `short()` is the first 8.

AC3 Pairing code text (`ticket.rs`, unit tests or `tests/code.rs`). `PairCode { anchor: NodeKey,
secret: [u8; 16], hints: Vec<Hint> }` with `Hint::Relay(Url)` (https only) and
`Hint::Addr(SocketAddr)`; `Display` and `FromStr` per 4.1. Round trip of a code with 0, 1 and 8
hints. Refused (`NetError::BadCode`): a wrong prefix, a 25- or 27-char secret, a secret whose
unused last bits are not zero, a non-z-base-32 char, 9 hints, more than 1024 bytes, an `http://`
relay, an unknown hint name, an empty hint. Expected strings are built in the test, not with
`watane_net`. `Ticket` is D2: do not build it.

AC4 Wire codecs (`wire.rs`; tests of each refusal). Requests and answer items of 4.2 for `hello`,
`heads`, `entries`, `fork`, and the `["err", code, message]` item, in deterministic CBOR (arrays
only). The decoder refuses: trailing bytes, a map or other major type where an array is
expected, a non-shortest length or integer head, an indefinite length, and anything that does
not re-encode to the same bytes (`bad_request`). A request over `Limits::request` (256 KiB) is
refused by the callee before decoding (`too_large`), and the caller refuses to send one. Test
inputs are hand-written bytes (a small CBOR byte builder in `tests/support`), not
`watane_net`'s encoder. Fix in 4.2 the `limits: [uint]` order of the `hello` answer and the
answer byte limit of each op (the stream as a whole, including CBOR framing), and write it there.

AC5 `hello`, `heads`, `entries`, `fork` between two nodes (`tests/serve.rs`). Two `Net`s in temp
dirs, each `on: true`, bound to `127.0.0.1:0` (never `::1`), relays off, address lookup off,
portmapper off, captive-portal and HTTPS probes off; B learns A's address with
`add_addrs(&a_key, &[a_addr])`. A `tests/support::MemHoldings` holds entries that
`watane_log::Log` signed in a temp dir before the test (two channels; one with a fork, made by
signing two entries at the same seq; see how log's tests make one). Expected values come from
those entries, not from `watane_net`:
- `hello` from a trusted and from an unknown node: version 1, the ops of N1, the limits;
  `devices_seq` null (no device list until N2).
- `heads(&[])` (all) and `heads(&[c1, absent])` equal the holder's heads; an absent channel is
  `None`.
- `entries(c1, 1, 1000)` returns the original bytes of every entry, equal byte for byte;
  `entries(c1, 3, 2)` returns seq 3 and 4; an answer of entries over 4 MiB in total is cut to fit
  (`Holdings::entries`' `max_bytes`) and never more than 1000 entries.
- `fork(c_forked)` returns both entries; `fork(c1)` is `None`.
- From an unknown node, `heads`, `entries`, `fork` are `Refused { code: not_allowed }`, naming
  A by its short key, and the holder is never called (MemHoldings counts calls).
- An op of a later stage (`query`, `devices`, `pair`) and a made-up op are `unknown_op`.
Trust in N1: `Options::trusted: Vec<NodeKey>` lists the nodes `class_of` rates `Trusted` (plus
the own node). It stands in for the device list and N2 removes it; write that into 3 and 13.

AC6 The caller checks answers before returning them (NET-F-23, NET-F-24), and the callee's faults
are caught. Test with a node whose `MemHoldings` serves bad data (a holder can return anything):
an entry with a changed byte (does not decode, or its id differs: `BadObject`), an entry of
another author than the channel, entries out of seq order or not starting at `from`, more entries
than `limit`, a `heads` item for a channel not asked, a duplicate channel, a `fork` pair at two
different seqs or with equal ids. Each is `NetError::BadObject { node, cause }` naming the node.
An answer stream over its byte limit is `TooLarge` and is not read past the limit. A callee that
does not answer within the deadline is `Timeout` (use a holder that sleeps; set a short
`Limits::deadline` in the test).

AC7 Signed form of 4.3 (`devices.rs`, encode, sign, verify only; no device list behaviour yet).
`DeviceList` of 3 encodes to the CBOR array of 4.3 with prefix `watane/devices/1`, a zero byte,
the CBOR of the unsigned items, signed with the node key (ed25519-dalek, verified with
`verify_strict`). Golden vectors in `tests/vectors.rs`: the seed of RFC 8032 test 1 as anchor,
a list of the anchor (full) and one other key (light), seq 1, a fixed time; the expected bytes
are written by hand in the test, and the signature is computed with `ed25519-compact` over the
hand-written signed bytes. Refused: unsorted devices, a duplicate, a list without the anchor, a
role of 2, a flipped signature bit, a signature over `watane/entry/1` of the same items. The node
key signs nothing else: no general `sign` (AGENTS rule 5).

AC8 Net Q1, against the pinned releases (`tests/q1.rs`):

## Interface

Public (lib.rs), as in TECHNICAL 3, plus the N1 client calls (write them into 3):
```rust
impl Net {
    pub fn open(home_net: &Path, holdings: Arc<dyn Holdings>, options: Options) -> Result<Net, NetError>;
    pub fn set_options(&self, options: Options) -> Result<(), NetError>;
    pub fn close(self);
    pub fn node_key(&self) -> NodeKey;
    pub fn class_of(&self, node: &NodeKey) -> Class;
    pub fn addrs(&self) -> Vec<SocketAddr>;                     // bound local addresses; empty while off
    pub fn add_addrs(&self, node: &NodeKey, addrs: &[SocketAddr]); // where to dial a node (N4: the address book)
    pub fn hello(&self, node: &NodeKey) -> Result<Hello, NetError>;
    pub fn heads_of(&self, node: &NodeKey, channels: &[PublicKey]) -> Result<Vec<(PublicKey, Option<HeadInfo>)>, NetError>;
    pub fn entries_of(&self, node: &NodeKey, channel: &PublicKey, from: u64, limit: u64) -> Result<Vec<Entry>, NetError>;
    pub fn fork_of(&self, node: &NodeKey, channel: &PublicKey) -> Result<Option<(Entry, Entry)>, NetError>;
}
pub struct Hello { pub version: u64, pub ops: Vec<String>, pub limits: Limits, pub devices_seq: Option<u64> }
```
The whole `Holdings` trait of 3.1 is defined now (node implements it later); N1 calls only
`heads`, `entries`, `fork`. Other methods of 3 (`pair_code`, `join`, `told`, `need`, ...) are not
built in N1.
