Subsystem: dist
Effort: medium
Depends on: none
Slice: S124 — a failed fetch blames the true cause (net, node, dist), and net's budget flake
## Goal
dist's fetch errors name the true party when the failure is on this machine: a local failure
while unpacking or checking a downloaded package is not reported as `BadPackage` (which says the
web host sent an invalid package), and the full-disk (or any local write) text names the temp
path once, not twice.
## Acceptance
AC1. A package fetched from a web host whose bytes match its hash but whose local unpack/check
     fails for a local reason (an I/O error writing or reading this machine's temp or cache file:
     e.g. the cache directory made read-only, or a write that fails) returns `DistError::Io`
     (or `Corrupt` for a local file), never `BadPackage { url, .. }`. A package that is truly
     invalid (bytes that do not parse as a package) still gives `BadPackage` naming the URL.
     First find where the local failure becomes `BadPackage` (`dist/src/fetch.rs`, `http.rs`,
     `body.rs`; search for `BadPackage`), and pin it with a failing test.
AC2. When a write of a downloaded body or package fails because the disk is full (or any local
     I/O error on a temp file), the error's whole chain (Display, then each `source()`, as
     `app/src/lib.rs` prints it and `dist/src/error.rs`'s chain helper joins it) names the temp
     path exactly once. A test asserts the count, using an injected or simulated write error
     (e.g. a path where the write fails; no real full disk needed). Linux and macOS must both
     work; if the only practical injection is Unix-only, gate it with `#[cfg(unix)]` and a reason.
AC3. `DistError::Io`'s Display keeps its shape `<path>` with the `source` as its cause (node
     builds it with a party name as the path; that stays readable: `<party>` then the cause).
     No other variant's text changes except where AC1/AC2 need it; list each change in the report.
AC4. dist TECHNICAL (3.1 errors and the fetch section, 5.7) says which failures are local
     (`Io`/`Corrupt`) and which name the web host (`BadPackage`, `HashMismatch`, `Network`, ...).
AC5. `cargo test` (with `-- --include-ignored` for touched files), clippy (`-D warnings`) and
     nightly fmt pass in dist/; `factory/check.sh s124-2 <base>` passes.
## Spec
dist TECHNICAL 3.1 (DistError), 5.7 (fetch), AGENTS rules 2 and 4.
## Interface
none new; `DistError` variants keep their names and fields.
## Files
`dist/src/*.rs`, `dist/tests/it/*.rs` (new tests as modules of `tests/it/main.rs`),
`dist/TECHNICAL.md`. Never `host/`, `app/`, `dev/`, `net/`, `node/`.
## Changed tests
Search `dist/tests/it/` and `dist/src/` (unit tests) for asserts on `BadPackage`, "invalid package
from", and on temp-path text; update only those whose case is a local failure. Grep `app/`,
`host/`, `node/` tests for the texts you change and keep their assertions true (you may not edit
app/ or host/; if one would break, stop and report it).
## Out of scope
net and node error handling (s124-1, s124-3); app words.
