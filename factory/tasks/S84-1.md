## Goal
Host tells its embedder, once, after every install that wrote the catalog, which mods it added new and
which it updated, whoever asked (the app, a local program over `POST /api/install`, or a managing mod).
The app uses this to make a `main = true` mod main however it was installed (W37, app 5.4).

## Acceptance
- AC1 `Confirm` gains `fn installed(&self, report: &Installed) {}` (default body does nothing) and
  `Installed { requester, new, updated }` is public (`Debug, Clone, PartialEq`), re-exported where
  `InstallRequest` is.
- AC2 `Host::install` calls it exactly once after `installed.json` is written and before it returns,
  for every requester: `new` the local names of `New` plan entries in install order, `updated` those
  of `Update`; `Unchanged` entries in neither. Never called for a denied install, a failing plan, or an
  install that fails before the commit point.
- AC3 `tests/api.rs` W37 row: a `POST /api/install` of two new folders calls `Confirm::installed` once
  with `requester` `LocalApi` and both names in `new` in install order; a denied install and a failing
  plan call it never. A unit or integration test shows an update gives the name in `updated`, not `new`.
- AC4 Every earlier host test passes unchanged; `cargo test -p watane-host` (with `--include-ignored`
  for the slow ones), clippy and fmt clean.
