## Goal
The `node` crate exists as a workspace member and builds stage 1 of node/TECHNICAL.md 9: a home is
opened through `Node` (dist and net of one home, net opened first with an empty holder, then dist
keyed or keyless by the device list), and `DistHoldings` answers net's `Holdings` questions
(net/src/lib.rs `trait Holdings`) only from what dist stored and verified. A node home
(`Node::open_keyless`) holds no identity and refuses to sign; an app home opened with `Node::open`
keeps its identity as before. With net off, every dist function works through `node` as it does
without it. After this task, a keyless node opens and holds a channel it was given.

## Acceptance
Tests at the lowest level that shows each: the conversions of 4.3 as unit tests in `convert.rs`;
the scenarios as integration tests in `node/tests/`. Each scenario is one test named `s<n>_...`.
- AC1 (S1) `s1_*` in tests/open.rs: an empty home opened with `Node::open_keyless`: `<home>/log/`
  holds a store and no `identity.key`; `node.publish(..)` gives dist's `NoIdentity`; `machine()` is
  `Alone`; `node.dist().identity()` is `None`. An empty home opened with `Node::open` (approving
  `Confirm`) has an identity, `identity.key` exists, and a publish signs (seq 0). A home that has
  `home.json` gives `NodeError::HostHome` from `open_keyless`, and a home with an identity key gives
  an error from `open_keyless` (dist's mapping of log's `HasIdentity`) and keeps its key file.
- AC2 (S2) `s2_*` in tests/open.rs: Alice's channel and mod are signed by a keyed `Dist` of another
  home (the test makes it without `watane_node`) and served by `tiny_http` on `127.0.0.1`. Bob's home
  opened with `Node::open` and `Options::default()` (net off) follows Alice's link with
  `node.follow(&link)` and fetches her mod with `node.fetch(..)` (the package bytes equal Alice's);
  while the node is open, the process has no UDP socket more than before the open. Count sockets as
  net/tests/node.rs does (stat of `/dev/fd/<n>`; never `/proc`).
- AC3 (S3) `s3_*` in tests/holdings.rs, calling the `Holdings` methods of `DistHoldings` directly
  (no network): a home holding Alice's channel (followed through `tiny_http`) answers `heads(None)`
  with her channel and the head seq and id that Alice's home reports, `heads(Some(&[c]))` likewise,
  `entries(c, 0, 100, usize::MAX)` with entries whose bytes equal Alice's stored entries, `fork(c)`
  `None`; `blob(id)` gives the path of a package of a live release it fetched, and `None` for an id
  it does not hold and for a withdrawn release's package. A second, keyless home: `ingest(c,
  entries, Why::Kept)` gives `Ingested::Stored(head)` and `follows.json` gets a `kept` record;
  an entry list with one changed byte gives no `Stored`, and nothing of that channel is stored
  (`heads(Some(&[c]))` is `None` for it). `is_anchor()` is false on the keyless home and true on a
  keyed one; `store_blob` of a file with the right package stores it, of a changed file gives `Err`.
- AC4 a `DistHoldings` before its `Dist` is set answers as an empty holder (TECHNICAL 4.1 last

## Interface
Provides (fixed; the app and node stage 2 build on these names):
- `pub use watane_dist as dist; pub use watane_net as net;`
- `pub struct Options { pub dist: watane_dist::Options, pub net: watane_net::Options }` deriving
  `Clone, Debug, Default`.
- `pub enum Machine { Alone, Anchor, Full, Light, Removed }` deriving `Clone, Copy, Debug,
  PartialEq, Eq`.
- `pub struct Node` (Send + Sync) with `open(home: &Path, confirm: Arc<dyn watane_dist::Confirm>,
  options: Options) -> Result<Node, NodeError>`, `open_keyless(home: &Path, options: Options) ->
  Result<Node, NodeError>`, `dist(&self) -> &Arc<Dist>`, `net(&self) -> &Net`, `machine(&self) ->
  Machine`, `close(self)`.
- The wrappers of TECHNICAL 3 with net off, each a plain call of dist's method of the same name
  and dist's signature and result: `set_name`, `publish`, `withdraw`, `list`, `include`, `unlist`,
  `confirm_own`, `follow`, `refresh`, `refresh_channel`, `choose_index`, `fetch`, `fetch_for`,
  `open_link`, `read_link`. Where dist's real signature differs from TECHNICAL 3, follow dist and
  fix TECHNICAL 3. No `told` or `need` yet: `Net` has neither until net N3/N4 (stage 2 adds them).
- `pub enum NodeError` as TECHNICAL 3 (all five variants).
- `DistHoldings` stays crate-private behind `Node`, but tests/holdings.rs needs it: expose it as
  `pub struct DistHoldings` with `pub fn empty() -> Self`, `pub fn set(&self, dist: Arc<Dist>)`,
  and `impl watane_net::Holdings`, and note this addition in TECHNICAL 3.
Takes: `watane_dist` as on this branch (S61: `open_keyless`, holder methods, `HeadState`,
`Reason`, `Ingested`); `watane_net` as on this branch (`Net::open`, `devices`, `node_key`,
`close`, `Holdings`, `Options`). Do not change dist, log or net code.
