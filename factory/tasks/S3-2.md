Slice: S3 — An edit keeps the data: the agent changes the counter's logic and page while Alice has it open; `serve` again shows the new revision with the same count, and the page updates by itself when the count changes.

## Goal
The counter template's page listens to its mod: `ui/app.js` subscribes with `watane.on`, shows the
count carried by each `counted` event, and re-reads the count on `changed` (which also arrives when
the stream opens, so no separate first read is needed). `serve` again after an edit of the logic
and the page reuses the running preview, installs the new revision as an update of the same mod,
and the count survives. A build that fails leaves the running preview alone.

## Acceptance
- AC1 Template `ui/app.js` is exactly (test compares `new`'s output with this literal):
  ```js
  const count = document.getElementById('count');
  const alert = document.getElementById('error');
  const show = (value) => { count.textContent = String(value); alert.textContent = ''; };
  const fail = (error) => { alert.textContent = error.message; };
  const read = () => watane.call('api.get').then(show, fail);
  document.getElementById('add').addEventListener('click', () => watane.call('api.add').then(show, fail));
  watane.on((message) => {
    if (message.type === 'event' && message.function === 'counted') show(message.args.count);
    else if (message.type === 'changed') read();
  });
  ```
  dev TECHNICAL 4.1 shows the same text.
- AC2 (real host, `#[ignore = "needs WATANE_BIN"]` like the S2 tests) Edit keeps the data: `new`,
  `serve`, `api.add` twice; replace `next`'s body in `logic/src/lib.rs` so `add` adds 10
  (`count.saturating_add(10)`), and change the `<h1>` in `ui/index.html`; `serve --json` again:
  exit 0, `reused` true, the same `local`; `GET /` returns the new `<h1>` bytes; `/call api.get`
