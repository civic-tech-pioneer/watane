## Goal
When a publish or a follow is refused, the person (in the app) and the maker's agent (through
`/api/publish`, which dev prints as `host.refused [<code>] <message>`) read one clean sentence:
no cause printed twice ("X: X"), no Debug text in the 422 message, URLs and paths without Debug
quotes. S21c-1 fixes dist's own texts; this task makes the app's cause chain safe against any
library that prints its source in its own text too (pkg and log still do), and pins the results.
It also pins that a release without source says so in Bob's consent view.

## Acceptance
- AC1 `cause_chain` (`src/lib.rs`) appends a cause only when the text so far does not already end
  with that cause's text. Unit test: an error whose text is `"a: b"` and whose source's text is
  `"b"` gives `"a: b"`; one whose source's text is `"c"` gives `"a: b: c"`.
- AC2 `core.rs` `ac4_dist_error_keeps_whole_cause_chain` changes: today it expects
  `format!("{outer}: disk broke")`, where `outer` already holds the Debug of the io error (the
  doubled text). New expectation: the message is exactly `/home/dist/site/head` + (S21c-1's fixed
  `Io` suffix, if any) + `": disk broke"`, written as a literal, and "disk broke" occurs once.
- AC3 `/api/publish` with garbage bytes (the 422 `invalid_package` row of 8.1, `tests/api.rs`):
  the message contains no `{`, `(`, or `"` and no Debug variant name; assert it in the existing
  422 test (name it in your report). A unit test is enough if that test runs only with
  `--features driver`; then add one in `src/api.rs` that maps a `DistError::Package` through the
  same function the route uses.
- AC4 `confirm.rs`: the existing mapping test gains a release with `source: false`, whose details
  show `("Source included", "no")` (DEV-S-31's consent side).
- AC5 `cargo test` (default), `cargo clippy --all-targets --features driver -- -D warnings`,
  `cargo fmt --check` pass. One line under the spec-gap list in `app/AGENTS.md` for AC1;
  `app/TECHNICAL.md` 13 says the chain rule in one sentence.
