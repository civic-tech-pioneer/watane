## Goal

This task answers Codex review r2 of PR #19 (F2.1 to F2.5) and builds the product owner's decision on
S105-CHURN, "(a) Fail closed". After it, a listed read (a base of unknown origin, or a seen base never given)
is refused before its first request when the base itself is local, not only at its redirects; the
"is this base given" decision reads one consistent snapshot; `read_link` gives a cached package where
`fetch` does; a failed save leaves the tombstones as they were; and once tombstones have overflowed, a
link for a channel whose record and tombstone are gone gives nothing, while a link for a channel dist never
knew still gives its base.

Work test-first. Commit all the red tests first in one commit `red: S105 r2 (F2.1-F2.4, churn)`, each
failing for the reason the finding names (check this: run them and keep the failure lines for the report).
Then one commit per fix, in this order, each message starting with its id:
`s105-fix6 F2.1: ...`, `s105-fix6 F2.2: ...`, `s105-fix6 F2.3: ...`, `s105-fix6 F2.4: ...`,
`s105-fix6 churn: ...`, `s105-fix6 F2.5: ...` (spec text only). Each fix commit turns its red tests green
and keeps every other test passing.

## Acceptance

1. AC1 (F2.1, dist/src/follow.rs `read_channel_mode`/`read_channel_entries`, dist/src/index.rs
   `choose_index`). A listed read checks its first base with `check_listed_base` before any request, as it
   checks redirect targets. Red tests (it or unit, in the style of `http::tests`): a pre-S105 follows.json
   whose followed record has a local base `a` (not in `test_local_ok`); `follow(link at a)` fails with
   `BadUrl` "local address" and `a` gets no request. The same for `choose_index(link at a)` on a chosen
   record. A link at a base the participant gave (in `given`) still reads a local base (LAN mirror).
2. AC2 (F2.2, `Dist::held_ungiven`). It classifies from one snapshot: it holds the `follows` lock through
   the tombstone lookup (lock order follows, then tombs, as `save_follows` already takes them). Red test:
   deterministic (no sleep-based race that passes by luck). A `#[cfg(test)]` hook between the two lookups
   is fine (for example a barrier or a callback set in a test-only field), used to run a `keep` of the
   channel, which moves the tombstone into a record, between them; before the fix `held_ungiven` returns
   false for a seen, never-given base, after it true. If the hook cannot exist after the fix (no gap), the
   test asserts the result through the same scenario run sequentially and the red run is recorded with the
   hook in the red commit; say which in the report.
3. AC3 (F2.3, dist/src/fetch.rs `read_link`). When the record's base is a listed read and
   `check_listed_base` refuses it, `read_link` gives the verified cached package with no link and no
   request, as `fetch` does (DD-47); on a cache miss it returns the address refusal. Red test: the
   assertion Codex named, `read_link` of the release link right after the successful `fetch` in
   `http::tests::ac1_an_unknown_local_base_gives_a_cached_package` (or a new test copying its setup):
   it returns the package, and `a` gets no request. After the cache is removed it fails `BadUrl`.
4. AC4 (F2.4, dist/src/index.rs `prune_listed_channels`, dist/src/holder.rs `take_back_kept`). Neither
   changes `self.tombs` before the save succeeds: build the next tombstone map on a copy, pass it to the
   save, and publish records and tombstones together after `site::write_equal` succeeds (change
   `save_follows` to take the staged tombstones, or add a sibling; keep one write path). Red tests: make
   the save fail (for example a read-only `dist/` directory, or a directory where `follows.json` should be;
   skip on root as other tests do, or use a test-only failure switch) during a prune that creates a
   tombstone and during a failed kept ingest that takes its record back; after the failure, the in-memory
   tombstones equal the ones before (also when 1024 were held, so none was evicted), and the file is
   unchanged.
5. AC5 (S105-CHURN, "(a) Fail closed"; dist/src/follow.rs `add_tombstone`, `new_record`, `held_ungiven`,
   dist/src/lib.rs `Follows`). When `add_tombstone` evicts a tombstone, the evicted channel key is added to
   a fixed-size filter of gone keys, kept in `follows.json` as the top-level `"gone": text` (lower-case hex
   of 4096 bytes = 32768 bits; default absent, omitted while no tombstone was ever evicted, so the version
   stays 1). A key sets 3 bits: bytes 0..2, 2..4, 4..6 of BLAKE3 of the key's 32 bytes, each read as a
   little-endian u16, modulo 32768. A key "may be gone" when all 3 of its bits are set. A false positive
   only makes a channel fail closed. Rule: for a channel with no record and no tombstone that may be gone,
   `held_ungiven` returns true (its first read is listed), and `new_record` starts the record with
   `seen_full: true` and empty `given`, so no link gives its base (a hit's install, a `Fetched.link`, or a
   pasted link at that channel: until S107 the participant cannot give a base of a gone channel). A
   channel dist never knew (bits not set) is unchanged: a link gives its base. The filter is
   read and written with the tombstones (staged with them, AC4); a malformed `gone` reads as all bits set
   (fail closed), and a wrong length is the same. Red test, `http::tests::adv_s105_churn_tombstone_overflow_then_stale_hit_gives_nothing`:
   the churn route of the DELIVERED RISK (a listed record for the channel whose base `a` redirects to a
   local `b`; prune it so it becomes a tombstone; push 1024 more tombstones so it is evicted (add them
   through the real `add_tombstone` path; a test may call it directly with throwaway keys, or churn a
   listing as the adversary's r5 test does if that runs in a few seconds); then `follow(hit)` and
   `refresh_channel`): `b` gets no request. Red before the fix, green after. A second test: after
   overflow, a link for a fresh channel key never seen still gives its base (a given local base reads with
   `test_local_ok` cleared: no `BadUrl`). Unit tests for the filter: bits set, membership, hex round trip,
   malformed reads as full.
6. AC6 (F2.5, spec only, in the `F2.5` commit). Align dist/TECHNICAL.md 4.4 (around lines 615-650: `given`
   is no longer "a subset of `base` and `bases`" since it keeps bases no longer held; "the participant
   gives such a base again by ... following or choosing it by a link" must say only a base not in `seen`,
   or in `given`, can be given; the rule reads: a link gives its base when the base is in `given`, or is not

   until S107), the 6 table row for A35 if it needs it, and dist/FUNCTIONAL.md A35 (line ~319: a listed or
   unknown base that is itself local gets no request, at follow and choose too; "until a link at it is
   given" becomes the DD-48 rule). Add the `"gone"` field to 4.4 where the tombstone map is described.
   Also F2.3 in 5.9 or wherever `read_link` is described: a cached package is given for a refused listed base.
