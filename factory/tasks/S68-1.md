## Goal

net's default `cargo test` runs well under its 120 s limit, so that S68-2 (reach, S11) and node 2
can add tests. Measured in the cloud on main (254cadf, 4 cores, built beforehand): 121 s wall, the
sum of the binaries: `serve` 24.1 s, `faults` 16.3, `budget` 16.1, `pair` 15.9, `sync` 15.6,
`regress_s60` 12.6, `regress_s62` 12.6, `light` 4.3, the rest under 2 s. S67 named two causes:
`support::settle`'s window (it sleeps 300 ms and needs 3 equal readings, so at least about 1 s per
call) and `Net::close` / `set_options(on false)` taking about 3 s while connections are open
(likely `Router::shutdown` waiting for peers to close gracefully). Find the real causes by
measuring, fix them in `src/` where the product is slow (a close that waits seconds is a product
defect: watane-node's SIGINT and the app's quit both go through it) and in `tests/support` where a
test waits longer than it must. No behaviour of the product changes except how fast it closes.

## Acceptance

AC1 `cd net && time cargo test --no-fail-fast` (after `cargo test --no-run`, with
`CARGO_PROFILE_DEV_DEBUG=0`) passes in at most 60 s wall in this cloud container (4 cores), and no
test binary takes more than 15 s. Give the before and after per-binary times in your report.

AC2 `Net::close` and `set_options` with `on` false return within 1 s with kept connections open
(two paired machines, synced, a third connected): a test asserts it (an integration test in
`tests/node.rs` or `tests/sync.rs`, with the bound well above the measured time, e.g. 1 s). The
other side sees the connection end (`PeerDown`) as before. If the slow part is iroh waiting for a
graceful close, close the connections (application close code) and bound the wait for the
endpoint with a timeout; the endpoint and router must still be shut down, no task left running
(the keeper, the blobs hook).

AC3 `support::settle` and `support::wait_for` wait only as long as the condition needs: poll at
50 ms or less; settle's "quiet" rule keeps its meaning (the holders' call counts did not change
over a window), with the window as short as keeps the tests deterministic (say 3 readings 100 ms
apart, or a quiet window of 300 ms total). No test sleeps a fixed time above 200 ms unless the
time is what it tests (a deadline, a timer, a backoff); where a test waits for a timer of the
product, it shortens that timer through `Limits` (as `sync_interval` already is) rather than
waiting for the default.

AC4 No test is removed, merged away, renamed without its assertions or moved to `#[ignore]`.
Every assertion keeps its meaning. Tests may share nodes within a file (one fixture of paired
machines for several tests) where that keeps each test's meaning; a shared fixture must not let
one test's state change another's result.

AC5 The default run is stable: run `cargo test --no-fail-fast` in `net/` three times in a row;
all three pass. Also `cargo test -- --include-ignored` passes once. `node/` still builds and its
tests pass (`cd ../node && cargo test`).

AC6 `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` are clean in `net/`.
net/TECHNICAL.md 9 gets one line under the N4 notes: how close is bounded (what is closed and
the timeout).
