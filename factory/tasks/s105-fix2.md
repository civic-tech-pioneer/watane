## Goal

This task closes the Codex review r1 of PR #19, findings F1.1 to F1.4, at a911383.
The deputy decided F1.1. A base whose origin is unknown is read under the listed-address rule,
redirect targets included, until the participant gives that base again by a link. Any base in
a followed or chosen record saved before S105 counts as unknown. After this task, an
old home can no longer read a listing-learned mirror with redirects it does not check.

Also:
- The guarded redirect path follows a 300 that has a `Location`, as the earlier transport did.
- Tests pin the single deadline and the body limit across hops.
- FUNCTIONAL A37 states the redirect rule.

## Acceptance

1. AC1 (F1.1). A followed or chosen record keeps track of which of its bases the participant
   gave. Use an additive field with a serde default, for example `given: Vec<String>`, in
   `Follow`. `follows.json` stays at `version: 1`; an old file without the field loads, and
   every base in it is then unknown.
   - `follow`, `choose_index` and `learn_link_base` mark a base as given when the participant
     names it by a link. DD-46 still drops listing bases on the listed-to-followed transition.
   - Every read of a base that is not given uses the listed rule, as `listed = true` does
     today: the base itself is skipped when local (`check_listed_base`), and each redirect
     target is checked. The record's channel read, refresh and fetch package GET all apply it.
   - Given bases keep today's behaviour.
   - Test: a hand-written old-format `follows.json` with a followed record whose `bases` holds
     a base that redirects to a local target. Refresh and fetch make no request to the target.
     After `follow` by a link at that same base, the redirect is followed (AC3 of s105-1).
2. AC2 (F1.2). `get_hop` treats 300 with a valid `Location` as a redirect, like 301, 302, 303,
   307 and 308. Change `ac1_get_guarded_follows_a_checked_target_over_http`, or add a case, so
   that a 300 at `/a` to `/b` gives `b"ok"` after requests to `/a` and `/b`. Without a
   `Location`, a 300 is still `Http`.
3. AC3 (F1.3). Unit tests in `dist/src/http.rs`:
   - A chain of hops whose total time passes the read's timeout gives `Timeout`, although each
     hop alone is under it.
   - A final response after a redirect that is larger than the limit gives `TooLarge`.
   - Each test must fail if the deadline or the limit were applied per hop or dropped.
4. AC4 (F1.4). dist/FUNCTIONAL.md A37 says that provider and `read_link` redirect targets get
   the same address check as the base, and that a provider fetch tries the next eligible base
   after a refused redirect. A35 says the same for index reads if it does not already.
5. AC5. Every dist test passes, clippy and fmt pass, and `factory/check.sh` passes.

## Interface

There is no public signature change. `Follow` gains a serde-default field. The listed decision
per read goes from per-record (`!followed && !index`) to per-base: listed when the record is
listed-only, or when the base is not in the given set.
