## Goal
A gossip hint reaches the machine that can serve it. Today (net/src/gossip.rs `received`, then
`sync::request(.., Want::Hint)` and `sync_channel`) a hint is acted on with the machine that
*delivered* it (iroh-gossip's `delivered_from`), which in a topic of three is often a neighbour that
relayed the hint before it pulled the head itself. That neighbour answers its old head, nothing is
pulled, and the update waits for the next connect sync or the 10-minute timer (S70's finding,
node/TECHNICAL.md 12). After this task, when the delivering machine's head is below the hint's seq,
net asks it again shortly after (it is pulling the same head because of the same hint), a bounded
number of times, until its head reaches the hint's seq; then it pulls as today. The hint's wire
form (72 bytes, `[channel, seq, id]`) does not change: the original teller is not on the wire and
must not be trusted from a field (AGENTS rule 1).

## Acceptance
- AC1 (integration, net/tests/sync.rs, `MemHoldings`) three machines: the laptop (anchor), the
  server (full) and a light machine that holds the channel (so it acts on hints). The light
  machine reaches the laptop only through the server on the gossip topic (it is given the server's
  address only, not the laptop's), and the server's holder answers `ingest` slowly (a `Faults`
  delay of about 1 s on ingest, or the nearest existing knob: add one to `support` if needed), so the
  hint reaches the light machine before the server holds the head. The laptop appends and `told`s:
  the light machine holds the new head within 5 s, without any reconnect, `set_options` or timer.
  Run it in a loop of 20 rounds in one test (append and tell 20 times, each must arrive within 5 s);
  the whole test stays under ~10 s on loopback. It fails on today's code (see it fail first).
- AC2 the retry is bounded: a hint whose seq the delivering machine never reaches (a forged seq, as
  in `s5_alice_publishes_and_the_server_has_it_within_seconds`) makes at most a few `heads` calls to
  it over a few seconds and then stops; no ingest. Choose the bound (for example every 250 ms for at
  most 5 s), write it into net/TECHNICAL.md 5.7, and prove the stop with a test at the lowest level
  that can (a unit test of the retry decision if you factor one out, else count the holder's
  `heads`/calls of the laptop's `MemHoldings` after the window).
- AC3 a hint whose head at the hint's seq has another id still pulls nothing and is not retried
  (the forged-id rule of 5.7 is unchanged); a hint for a channel a light machine does not hold is
  still dropped (`acts_on`, unchanged).
- AC4 net/TECHNICAL.md 5.7 says how a hint is acted on now (the retry and its bound) and why
  (gossip relays; the teller is not known); node/TECHNICAL.md 12's net row says the gap is fixed in
  S72 (one line; that is the only node file this task touches).
- AC5 `cargo test -p watane-net` passes; its wall time stays near today's ~39 s (report before and
  after); `cargo clippy -p watane-net --all-targets -- -D warnings` and `cargo fmt --check` clean.
