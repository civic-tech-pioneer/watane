## Goal
Four S24 user-sim leftovers in dev's publish and check texts. After this task: a publish whose
app has no site URL yet does not print `link: missing`; the rerun that the publish `next` asks for
reports the release and the current link instead of only "raise the version"; the
`publish.local_dependency` `next` keeps the `--home` the agent passed; and the unused-provider
`check` error does not tell the agent to "remove" what the fix says to ask before deleting.

## Acceptance
- AC1 Null link in text mode: a successful `publish` whose app answers `"link": null` prints
  `link: none yet` (not `link: missing`) in text mode; JSON keeps `"link": null`. Do it in the
  publish text only (e.g. text printing of a null `link` key, or the result value written for
  text), not by changing the global `null -> missing` rule of TECHNICAL 2.3 for other keys.
  Test at the lowest level that shows it (an `outcome.rs` or `cli.rs` unit test, or one
  `dev/tests/publish.rs` case with `fake-watane`).
- AC2 Rerun after "run publish again to get the link": `publish` of a slug and version that
  `GET /api/releases` already lists stays `publish.version_exists`, exit 1 (contract unchanged),
  but now also sets `result` to `{"home", "release", "link"}` from that release entry (TECHNICAL
  2.4 publish: "That rerun checks existing releases and reports the release and current link";
  `result` is allowed on a failure, 2.3). In text mode that shows as `release: ...` and
  `link: ...` lines (`link: none yet` when null, as AC1). Its fix and `next` become
  `This version is already published. To publish changes, raise the version in wit/world.wit, then run publish again`
  (same text in api.rs where POST returns 409 `version_exists`; there `result` stays as it is
  today). Update the TECHNICAL 2.2 table row and every existing test asserting the old fix literal
  (`dev/src/api.rs` tests ~line 340, `dev/tests/publish.rs`, any `journey*.rs`; search for
  "Raise the version"). Integration test in `dev/tests/publish.rs` with `fake-watane` listing the
  release: exit 1, code `publish.version_exists`, `result.release` and `result.link` equal the
  listed ones, the app received no POST.
- AC3 `publish.local_dependency` `next` with `--home <h>`: the next command is
  `watane-dev publish --json --dir <abs provider> --home <abs h>` (quoted as the existing `quote`
  does), and without `--home` it stays as today. The host still receives no request (DEV-S-30):
  do not query releases here. The fix becomes
