## Goal
dev's tests follow the test pyramid of `factory/README.md`. The default `cargo test` (no
`--ignored`) of `watane-dev` finishes in under 2 minutes on a quiet machine. Today nearly every
integration test pays a cold mod build of about 30 s in its own fresh `WATANE_DEV_CACHE`. After
this task each test binary builds the template once and its tests reuse that warm cache; rules
that only a command test proves today (check rules, error texts, `json_eq`, classifications such
as libtest parsing and exit classes) get unit tests in their module, and the command test stays
only where it proves wiring; cold builds, the preview life cycle and J1 are `slow` with a reason.
No scenario loses its proof.

Check first, before you change the fixtures: whether a copy of a warm cache at another path
stays warm. TECHNICAL 6.4 puts the cache path into the rustflags (`--remap-path-prefix`), and
rustflags are part of cargo's fingerprint, so expect a copy to rebuild cold. If it does, the
tests of one binary share the one warm cache folder itself (the builder's per-slug lock already
serializes builds of one slug) instead of copying it. Record what you found and chose in one
line of TECHNICAL 15. Do not change product code to make a copy warm.

## Acceptance
- AC1 Budget: with the test binaries already compiled, `time cargo test -p watane-dev` (from
  `dev/`, default run) finishes in under 120 s wall time. Report the measured time and each
  test binary's `finished in` time in your final message. If your sandbox is under load, say so
  with the numbers; the validator measures again.
- AC2 Warm cache: a helper in `tests/support/mod.rs` (`mod support;` in each binary that uses
  it) builds the template once per test binary (`std::sync::OnceLock`/`Mutex`, no new
  dependency) and hands tests a `WATANE_DEV_CACHE` that is warm. No default-run integration test
  builds a mod in a fresh cache unless the cold build is what it tests (README rule: "An
  integration test never builds a mod from scratch unless the build is what it tests"). Tests
  that need their own cache (two caches for DEV-S-12, a stale cache, a missing vendor folder)
  keep one, and are `slow` if they then need a cold build.
- AC3 Unit tests for rules: each rule that a command test is the only proof of today gets a
  unit test in its module's `#[cfg(test)] mod tests`: at least the check rules of `tests/check.rs`
  (DEV-S-5 to 8: each code and its file/line/fix), the error texts and fixes asserted in
  `tests/doctor.rs`, `tests/serve.rs` and `tests/add.rs` that a pure function produces, `json_eq`
  cases used by `tests/contract.rs`, and the libtest/failure classifications asserted in
  `tests/unit_tests.rs`. Oracles stay literal (TECHNICAL 15: never call the code under test for
  the expectation). Then the command test keeps only what proves wiring: one command test per
  command and per error class still shows the exit status, the envelope and the code end to end.
  THE TASK overrides the implementer rule "never delete an existing test" here: you may remove a
  command test or an assertion once a unit test proves the same rule; every removed assertion
  has a named replacement in the AC5 table.
- AC4 Slow: every test that needs a cold build, the real `watane` preview life cycle (serve,
  reuse, stop), or a journey (J1 in `journey.rs`, S11 in `journey_s11.rs`) carries
  `#[ignore = "slow: <what only this test proves>"]` (a test that also reads `WATANE_BIN` says
  so in the reason, e.g. `"slow: needs WATANE_BIN; preview life cycle: ..."`). Every `#[ignore]`
  in `dev/tests` and `dev/src` starts with `slow:`, `timing:`, `red:` or names the OS refusal
  (DEV-S-13). Leave `regress_s16_missing_vendor_says_missing` in `tests/doctor.rs` exactly as it
  is (`red: S17 fixes it`); do not try to make it pass.
- AC5 No proof lost: TECHNICAL 15.2 (and 15.1 where unit tests moved) list each scenario
  DEV-S-1 to DEV-S-32 and J1/S11 with the test name(s) that prove it now and their level (unit,
  integration, slow, journey). A scenario that had a test before has one after.
- AC6 The slow set still passes: `cargo build -p watane-host && WATANE_BIN=$PWD/../target/debug/watane
  cargo test -p watane-dev -- --include-ignored --skip regress_s16_missing_vendor_says_missing`
  passes, except DEV-S-13 where your sandbox refuses `sandbox-exec` and `timing:` tests under load.
  Report its time.
- AC7 `cargo clippy --all-targets --all-features -- -D warnings` and `cargo fmt --check` pass.
