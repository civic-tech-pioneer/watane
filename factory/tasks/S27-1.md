## Goal
Every place below shows a person what happened and what they can do, in words from `words.rs`
(Rust) or one line of `ui/` (JS) where the text is only UI. No host, dist or pkg change: host's
`HostError::PortInUse(u16)` (code `port_in_use`), dist's `DistError::BadReason { cause }`,
`watane_pkg::Release::grants` and host's `refused` code already carry what is needed.

## Acceptance
Unit tests in `src/` for the rules and texts; window tests (`--features driver`, default, not
ignored) where a criterion is about what the window shows.
- AC1 Busy port. A second `watane-app --home B --port P` while something else holds loopback
  port P (test: a `std::net::TcpListener` on 127.0.0.1 in the test, then the driver app with that
  port) opens its main window, and the window's `main` text and `status.error` are
  `words::port_in_use(P)`:
  `Port P is in use, maybe by another watane app. Start this one with --port <n> or WATANE_PORT=<n> to use another port, or --port 0 for any free port.`
  The same line goes to stderr once. No `run.json` is written (as now). Any other serve error
  keeps today's `cause_chain` text. Find out first why the demo saw no message (the PLAN note
  says the window stayed empty); the window test must fail on today's code if that is the bug,
  and the cause goes in your final message. The driver support (`tests/support/`) gets a way to
  pass a port instead of `0`; existing callers keep `0`.
- AC2 Own releases. In the identity section a withdrawn own release reads
  `Withdrawn: <reason>` (not "by the publisher"). Carol's view of another publisher keeps
  `Withdrawn by the publisher: <reason>`.
- AC3 Withdrawal reason. `release_withdraw` checks nothing itself; it maps dist's
  `BadReason { cause }` to code `bad_input` with `words::bad_reason(cause)`:
  `"invalid character count"` -> `Give a reason of 1 to 280 characters.`; any other cause ->
  `This reason cannot be used: <cause>.` Empty, 281-character and leading-space reasons each give
  their text. Unit test over the mapping (no window). `NotOwnRelease`, `AlreadyWithdrawn` and a
  refusal still pass through with their cause.
- AC4 Consent heading (`ui/consent.js`). Install request with one mod whose `replaces` is set:
  `Update <name> to <version>`; one mod without: `Install <name>`; n > 1 mods: `Install n mods`.

- AC5 Declined update. When the automatic update or `release_install` fails with host's
  `refused` code (a decline in the consent view), the mod's notice is
  `words::update_declined(version)`: `You declined the update to <version>.`; other failures keep
  `Update to <version> failed: <cause>`. Priority of AC2 of S25 is unchanged (compromised,
  withdrawn, then this). Unit test.
- AC6 Offer names its new grants. `ModView` gains `offerGrants: [GrantLine]`: the grants of the
  offered release (`ReleaseInfo.release.grants` of the offer from the followed `ChannelView`)

  `words::grant_line(.., granted: false, new: true)`; `[]` with no offer. The offer button reads

  So after a restart (the decline notice is gone, it is kept in memory only) the offer still says
