## Goal

Two RISKs the S137 adversary reported (HELD otherwise). The foreman settled them by choosing the
stricter option, which keeps the others open:
- `--status` tells Alice to run `sh ~/.local/share/watane/install.sh` only when that file is
  watane's own, meaning a readable receipt (published, or staged when there is none) lists it.
- The uninstall says the files of the interrupted install were removed only when none was left
  behind.

## Acceptance

1. AC1: `--status` with a stale lock or leftovers, and a regular (not linked)
   `~/.local/share/watane/install.sh` that no readable receipt lists. Planted case: a real
   `share/watane` with `install.sh`, an empty `receipt.new.<dead pid>`, `journal.<dead pid>` and
   a stale lock. Its `Next:` line does not name the script; it says `run the install command
   again`. When a readable receipt lists `~/.local/share/watane/install.sh`, the script is named
   as today.
2. AC2: after a killed fresh install whose `.new` cleanup skips an install folder (for example one
   relinked inside the home, so a `<entry>.new.<n>` name stays), `--uninstall` does not print
   `The files of the interrupted install were removed.` Either it says nothing about removal, or
   it says that some were left; choose one and say it in TECHNICAL 8.4 step 1. When nothing was
   skipped, the line prints as today.
3. AC3: TECHNICAL 8.1 (the `Next:` rule) and 8.4 step 1, then FUNCTIONAL INST-S-33, state these
   rules. Every earlier test stays green; no guard weakens.
4. AC4: each new test fails when its new check is removed.
