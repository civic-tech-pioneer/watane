## Goal

A host can immediately reopen its home after shutdown. The stream hand-off and timer cancellation checks synchronize with the work they observe. A judge origin follows the host's HTTPS origin rules, and the provider's own identity determines which key its request uses.

## Acceptance

1. AC1. While the host is open a second open reports Busy. Immediately after drop a second open succeeds even if a Unix file descriptor for the previous lock remains open. Keep the existing state-before-lock drop assertion. Repeat the reopen check 20 times in the default suite.
2. AC2. The hand-off test sees the delivered payloads and the last acknowledged sequence number 3, in 20 default-suite rounds.
3. AC3. A due firing that has started waiting on the mod call lock does not run after its timer is cancelled while it waits. Exercise 20 explicit interleavings in the default suite.
4. AC4. Confirm that S118 already ensures the consent pending item is awaited and that the sender is stored before the question is recorded.
5. AC5. At the parser unit level, an IPv4 judge origin is canonical, and a trailing dot (including encoded and Unicode dots) or a control character is refused.
6. AC6. When a sibling mod calls the provider, the provider's key authorizes the judge POST, without an account associated with the calling mod. Represent allocating a judge binding at the call explicitly so parsing does not fabricate an account outcome.
