## Goal
A dist error reads like a sentence. Today `DistError`'s `Display` shows URLs, paths and causes in
Rust Debug form (`"http://..."` with quotes, `PackageError` as `Truncated(..)`-style Debug text) and
repeats its source: `Io` prints `{source:?}` and also exposes it as `#[source]`, `Log` is
`#[error("{0}")]` with `#[from]`, so a caller that walks `source()` (the app does) prints "X: X".
After this task each variant's text has no Debug quotes and no Debug rendering of a typed cause,
untrusted text is still escaped (control characters never appear raw), and a variant never prints
the error it exposes as its `source()`.

## Acceptance
- AC1 Rule: untrusted text (a URL, a path, a host's cause string, a name) is written with
  `escape_debug()` (as `pkg/src/package.rs` does: `{}`, `x.escape_debug()`), never `{:?}`; a path
  as `path.display()` escaped the same way. No variant uses `{..:?}` in its `#[error]`.
- AC2 Rule: a field marked `#[source]`/`#[from]` (or named `source`) is not in that variant's
  text. `Log`, `Package`, `Release` become `#[error(transparent)]` or a short prefix without the
  inner text (pick per variant; transparent where the inner text already says what it is).
  `SiteNotWritten`'s `cause: Box<DistError>` is printed in its text and is not a `source()`;
  keep it that way.
- AC3 Unit test in `src/error.rs`: for `Io { path: "/h/dist/site/head", source: other("disk broke") }`
  the text is exactly `/h/dist/site/head` (or `/h/dist/site/head: io error`, your choice, stated in
  3.1) and the full chain (text + ": " + each `source()` text) contains "disk broke" exactly once;
  for `NotFound { url: "http://x.invalid/a" }` the text is exactly `not found: http://x.invalid/a`;
  for `Package(<a PackageError>)` the chain contains no `{` `(` Debug shape of the cause and
  equals the cause's own text with at most a prefix.
- AC4 The existing escape tests stay as they are and pass: `src/error.rs` test near line 128
  (`http://example.invalid/\u{1b}\nentries/2` escaped), `tests/own.rs` near line 110,
  `tests/restore.rs` lines 21 and 59 ("this link is not your channel"), `tests/j3_dist.rs` near
  line 38 ("hash mismatch" and the package URL). If any assertion in them must change, name it
  and say why in your report.
- AC5 `dist/TECHNICAL.md` 3.1's first paragraph says the two rules (escaped, unquoted; no source
  repeated). One line under the spec-gap list of `dist/AGENTS.md`.
  `cargo test -p watane-dist`, `cargo clippy -p watane-dist --all-targets -- -D warnings`,
  `cargo fmt --check` pass.
