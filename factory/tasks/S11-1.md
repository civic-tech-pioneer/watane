## Goal
pkg stage 6: `add_provider` makes a provider's WIT usable by a consumer mod folder. It copies
the provider's top-level `.wit` files into `wit/deps/<slug>/`, copies the provider's own
`wit/deps/` entries the consumer lacks, refuses a conflicting entry without writing anything,
and records the provider in `deps.json`. dev's `add` calls it.

## Acceptance
- AC1 (A20) Folders: a copy of fixture `reading-list` as provider, and a consumer whose
  `wit/world.wit` does not import it yet. `add_provider(consumer, &Mod::read(provider)?, None)`:
  `wit/deps/reading-list/` holds exactly the provider's top-level `.wit` files, byte-equal;
  `wit/deps/watane-host/` is copied byte-equal; `deps.json` is exactly
  `{\n  "mods:reading-list": null\n}\n`.
- AC2 Run twice: the second run succeeds and leaves the same bytes (idempotent).
- AC3 The consumer already has `wit/deps/watane-host/host.wit` with different bytes:
  `Err(ModError::Invalid)` with one violation rule `provider`, file `wit/deps/watane-host`;
  no file of the consumer changed (compare a snapshot of the whole folder before and after) and no
  `deps.json` was created.
- AC4 An existing `deps.json` with another member keeps it; the new member is added; text is
  canonical (4.3), keys sorted.
- AC5 A publisher `Some(key)` writes the key text as the value.
- AC6 After AC1, a consumer whose world then imports `mods:reading-list/books@0.1.0` and
  exports `mods:reading-list/events@0.1.0` passes `Mod::read` (the `recommendations` shape).
