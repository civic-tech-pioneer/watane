## Goal
The builder finishes dev stage 2. After a build or a unit-test build, dev reads the compiler's
dependency files (`.d`) of the mod's crate and refuses the build when the compiler read any file
outside the copy, the vendor folder, the sysroot or `<cache>/target` (DEV-S-10): no `logic.wasm`
is written, and the error names the file. The same mod folder built at two paths with two caches
gives byte-equal `logic.wasm` that holds none of those paths (DEV-S-12). A secret in the maker's
shell never reaches the build (DEV-S-11). The `ponytail` in `builder.rs` goes.

## Acceptance
- AC1 (DEV-S-10, build) A template mod whose `logic/src/lib.rs` adds
  `const X: &[u8] = include_bytes!("<abs path of a temp file outside the mod>");` (used, so it is
  not optimised away, e.g. its length returned by an export or kept with `#[used]`/`black_box`)
  → `test --json` exits 1; `errors` holds `build.reads_outside` whose message is
  `the build read <path>, outside the mod` naming that file (2.2); no `<mod>/logic.wasm` exists
  afterwards; the file's bytes (a distinctive marker string) occur in no file under the mod folder.
  Same for `include_str!` and for a relative path that climbs out (`"../../outside.txt"`).
- AC2 (DEV-S-10, unit build) The same `include_bytes!` used only inside a `#[cfg(test)]` module →
  `test --json` exits 1 with `build.reads_outside` from the unit-test build (7.1 step 1); no unit
  test runs.
- AC3 Before each scan dev deletes the old `<crate>-*.d` files (6.4 step 4; for unit tests the
  `debug/deps` ones), so a fixed mod builds again: removing the `include_bytes!` makes `test`
  exit 0. A `.d` path with an escaped space (`\ `) parses (unit test of the `.d` parser on literal
  text, including a path under each allowed root and one outside).
- AC4 (DEV-S-11) `env!("SECRET")` in `lib.rs`, with `SECRET=abc` set in the environment of the
  `watane-dev` process → `test --json` exits 1 with `build.compile`.
- AC5 (DEV-S-12) One template mod copied to two different parent folders (different path
  lengths), each built with its own `WATANE_DEV_CACHE`: `test` exits 0 in both, the two
  `logic.wasm` are byte-equal, and neither contains (as bytes) the mod path, the cache path or
  `$HOME`. If they differ, fix the builder (6.5), not the test.
- AC6 `cargo test -p watane-dev`, clippy `-D warnings --all-targets --all-features`,
  `cargo fmt --check` pass; existing dev tests stay green. Integration tests that need the real
  toolchain follow the existing pattern in `dev/tests/builder.rs`.
