## Goal
The program `watane` runs both kinds of home of TECHNICAL 12.2, so FUNCTIONAL S1 to S3 hold on
the real program: `watane --home D` opens (or creates) a participant home with no app, serves
its installed mods and refuses every install that needs a confirmation; on a preview home it
prints `mode_mismatch` and exits 1 (S2). The library gets `Mode` and
`Host::open(home, mode, limits)` (2.1). This slice's cut: `Mode::Home` has no `app` field yet
(the `Confirm` trait joins with confirmation in step 2); a home host always behaves as "no app".

## Acceptance
- AC1 (S2) Given D is a preview home (made by `watane --preview D`, then stopped): `watane
  --home D --port 0` prints one stdout line `{"watane":1,"error":{"code":"mode_mismatch",...}}`
  and exits 1; `D/home.json` is unchanged. And the reverse: a home made by `--home` refused by
  `--preview` with `mode_mismatch` (existing test keeps passing with a written marker).
- AC2 `watane --home D --port 0` on an empty D creates `home.json` with exactly
  `{"watane_home":1,"mode":"home"}` and prints the ready line with `"mode":"home"`, `"mcp":null`,
  `"token":null`, `"mods":[]`; `run.json` has `"mode":"home"`; `GET /api/status` has
  `"mode":"home","app":false`; SIGTERM exits 0 and removes `run.json`.
- AC3 In that home, `POST /api/install` with the `hello` fixture -> 403 `refused`, message
  "no app is attached to confirm the install"; `mods/` stays empty, `installed.json` is
  unchanged or absent. `--home D --install x` is a `usage` error (exit 2).
- AC4 `watane` with no arguments, or `--home` without `--port`, uses `default_home()`
  (`$WATANE_HOME` if set and not empty, else `$HOME/.watane`) and port 47341: tested with
  `WATANE_HOME` set to a temp dir and a check that the port is 47341 when it is free (skip
  the port assertion, not the test, when 47341 is taken). `default_home()` is public (2.1).
- AC5 (S1) `watane --preview D --install <counter>`: the ready line's `mods` is exactly
  `[{"local":"counter","page":"http://counter.localhost:<port>/"}]`, `mcp` ends in
  `/mcp/preview`, `token` starts with `wt_`.
- AC6 (S3) A second `watane --home D` while the first runs -> `busy`, exit 1 (as for preview).
- AC7 `Host::open(path, Mode::Preview, limits)` everywhere the tests opened a preview before;
  `Host::is_preview()` reflects the mode. `cargo test -p watane-host`, clippy `-D warnings
  --all-targets --all-features`, `cargo fmt --check` pass; dev still builds
  (`cargo build -p watane-dev`).
