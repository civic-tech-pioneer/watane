## Goal
The new `dist` crate exists (package `watane-dist`, lib `watane_dist`, no binary) on the real
`../log` and `../pkg` (no stubs), with build stages S1 and S2 of `dist/TECHNICAL.md` 8: links
parse and print in one form; profile and withdraw bodies encode as strict CBOR and text rules
refuse names that could mislead; `Dist::open` makes an identity with no network and holds the
home; Alice can set her name only after the app approves it, through the single signing path
`sign_and_append`; the statement rules derive a channel view from stored entries. The workspace
builds it as a member.

## Acceptance
- AC1 (`link_table`, unit in `link.rs`) 12 valid and 14 invalid link strings of 4.2: parts,
  normalized base (a `/` added), `parse(display(l)) == l`; each invalid one gives `BadLink` or
  `BadUrl` with a cause (userinfo, query, fragment in base, other scheme, no host, bad key,
  bad slug, over 2048 bytes, missing `watane:` prefix, ...).
- AC2 (`body_vectors`, unit) the two hex vectors of 4.1 encode and decode; each changed form
  (array length, indefinite length, trailing byte, non-shortest head, other major type) is refused.
- AC3 (`text_rules`, unit) each refused character class of 4.1 and lengths 0, 1, 64, 65 (name)
  and 280, 281 (reason).
- AC4 (`derive_rules`, unit in `view.rs`) rules 1 to 8 of 4.1 on hand-built entries signed by a
  real `watane_log::Log` in a temp folder (append is allowed in this unit test only through a
  `Log` the test owns, never through a `Dist`); expected views written as literals.
- AC5 (`open_*`, A1) an empty home opens with no network; a second open of the same home while
  the first lives is `Locked`; after drop, a reopen gives the same key; `<home>/dist` and its
  subfolders are mode 0700.
- AC6 (`own_refuse_set_name`, A2 for set_name) `RecordingConfirm` refuses: `set_name` is
  `Refused`; a second `Log::open(<home>/log)` after drop shows no own head.
- AC7 (`own_request_set_name`) approve: the recorded `SignRequest` has Alice's key,
  fingerprint and `Statement::Profile`; the stored body equals `81 65 41 6c 69 63 65` for
  "Alice"; `own().name == Some("Alice")`.
- AC8 (A20) `set_name("Al\u{202E}ice")` is `BadName` and `confirm` was never called.
- AC9 (corrupt chain refused) after an approved `set_name`, drop the Dist, flip one byte of the
  stored row in `<home>/log/channels.db` the way `log/tests/corrupt.rs` does (rusqlite as a
  dev-dependency), reopen: `set_name` fails with `DistError::Log(CorruptStore ..)` and
  `confirm` was never called. This proves `sign_and_append` calls `log.status(own)` first.
- AC10 `withdraw` of a `ReleaseRef` that the own channel does not hold is `NotOwnRelease`
  before any confirmation (the release path itself is S21a-2).
- AC11 `error_text_escapes_controls`: a `BadUrl` whose url holds `\u{1b}` prints `\u{1b}` escaped.
- AC12 `cargo test -p watane-dist`, `cargo clippy -p watane-dist --all-targets -- -D warnings`,
  `cargo fmt --check` pass; `cargo build --workspace` still builds.

## Interface
Provides, exactly as `dist/TECHNICAL.md` 3: `Dist`, `Options` (Default), `Confirm`, `Decision`,
`SignRequest`, `Statement`, `Profile`, `Withdraw`, `Link`, `ChannelView`, `ReleaseInfo`,
`Withdrawal`, `BadStatement`, `Status`, `DistError` (all variants of 3.1, even if unused yet),
and the re-exports of 3. Methods now: `open`, `identity`, `fingerprint`, `set_name`,
`withdraw`, `own`, `channel`, `latest`, `site_dir`. Private: `own.rs::sign_and_append(guard,
kind, body) -> Result<Entry, DistError>`, the only caller of `Log::append`; `view::derive`.
Takes: `watane_log` and `watane_pkg` as they are now in `../log` and `../pkg`; change neither.
`tests/support/mod.rs` provides `RecordingConfirm` (queue of decisions, records requests).
