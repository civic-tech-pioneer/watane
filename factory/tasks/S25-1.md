## Goal
The app builds the half of stage D that needs no index (APP-F-37 compromised mods, APP-F-39,
APP-F-40). After a refresh that reports a new release of an installed mod, the app updates it:
host installs it with no question when it asks for no new grant (HOST-F-27, already built in
host: `Plan::needs_confirmation` is false for such an `Update`), and with the consent view when it
does. Each published mod in the mods list carries a notice (withdrawn with the reason, channel
compromised, last update failed with its cause) and an offer of the newest release that is not
withdrawn, which Carol can install with one button. Alice sees her own releases in the app and
withdraws one with a reason after signing it in the consent view (DistConfirm already shows a
withdrawal, APP-F-33). host and dist need no change.

## Acceptance
Unit tests (`core.rs`, no window) for the pure rules, one window journey for the whole story.
- AC1 Offer rule, a pure function over an installed mod (publisher, slug, version) and the
  `ChannelView` of its publisher: `offer` is the `ReleaseRef` text of the release of that slug
  with the highest version whose `withdrawn` is `None`, or `null` when that is the installed
  version or none exists. Withdrawn 0.3.0 installed, 0.2.0 live: offer 0.2.0. 0.1.0 installed,
  0.2.0 live: offer 0.2.0. Unit test with `ChannelView`s built in the test.
- AC2 Notice rule, same inputs plus the last update failure: `notice` text is, in this priority,
  `The publisher's channel is compromised` (status `Compromised`), `Withdrawn by the publisher:
  <reason>` (installed release withdrawn), `Update to <version> failed: <cause>`, else `null`.
  Local mods and mods whose publisher is not followed: both `null`. Texts live in `words.rs`.
  Unit test.
- AC3 Update rule: `Core::refresh` returns, besides the rows, the `ReleaseRef`s to update: for each
  installed mod with a release, when that refresh's report for its publisher has a
  `Change::Release` of its slug and the AC1 offer is a higher version than the installed one,
  that offer (one per mod; 0.2.0 and 0.3.0 in one refresh give 0.3.0). A `Change::Release` of a
  mod not installed, or of a lower version, gives nothing. Unit test of the pure part.
- AC4 Updates never block the refresh: `channels_refresh` and the 600 s loop (`lib.rs`) spawn one
  task per update that plans it (`dist.fetch` of the ref, then the same provider resolution as
  `install_link`; share the code, do not copy it) and runs `host.install(plan, Requester::App)`.
  An error (a decline is host's `refused`) is kept per local name and shown by AC2 until the next
  successful install of that mod. `channels_refresh` returns as before (`[ChannelRow]`).
- AC5 New command `release_install(release)` (main; `release` is a `ReleaseRef` text, parse error
  is `bad_input`): plans and installs that release as AC4 and answers `{installed: [local]}` like
  `install_link`. The mods list shows the offer as a button `Install <version>` that calls it.
- AC6 New command `release_withdraw(release, reason)` (main): `dist.withdraw` in
  `spawn_blocking` (DistConfirm asks; dist's `BadReason`, `NotOwnRelease`, `AlreadyWithdrawn`
  and a refusal pass through with their cause). `Status.identity` gains
  `releases: [{release, version, slug, withdrawn: null | reason}]` from `dist.own()`; the
  identity section lists them, each live one with a reason field and a `Withdraw` button.
- AC7 `ModView` gains `notice: null | string` and `offer: null | string` (ReleaseRef); the mods
