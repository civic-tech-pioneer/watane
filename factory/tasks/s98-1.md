## Goal
The app quits within its time bound even when every tokio worker holds a `tauri://` request.
Diagnosed on the macos-26 runner (S98 diag run 44891209774, a `sample` of the stuck app): at
`RunEvent::Exit` the main thread runs `block_on(served.shutdown())`; the runner's 3 tokio workers
are each inside wry's `RequestAsyncResponder::respond` for the main window's `tauri://` assets,
which waits for the main thread; with no free worker, tokio's timer never fires, so the
shutdown's own 4 s / 5 s bounds never end it. The app hangs until the test kills it ("app did
not quit", `gui_shell::ac2_background_screen_is_visible_without_focus`,
`manager::ac2_s38_choose_unset_remove_and_stale_name`). After this task the shutdown runs while
the main thread keeps serving its event loop, as app TECHNICAL 3 step 7 now says.
