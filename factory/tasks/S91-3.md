Effort: medium
Depends on: none
Slice: S91 — a maker or a mod hits an edge and gets a named cause, not raw I/O text.

## Goal
The host's local server says what happened in its own terms, and its tests prove what they
claim: an unknown `/api` route answers 404 with code `not_found`; the 413 guard either drains
the refused body (so the client reads the 413 without a reset) or its test and TECHNICAL say why
draining is not needed; a client that drops mid-`/call` is tested, and `Served::shutdown`'s
documented bound matches what the code does; the default-port test does not probe the port and
then bind it again.

## Acceptance
AC1. `GET /api/missing` (and any other path under `/api/` or on the API host outside `/api/`
     and `/mcp/`) answers 404 `{"error":{"code":"not_found","message":"unknown API route"}}`.
     All three places in host/src (server.rs fallback, server.rs middleware, api.rs) agree.
     With an `Origin` header it is still 403 `forbidden` (hostile.rs unchanged).
AC2. 413: a raw-socket POST of 64 KiB + 1 to `/api/plan` (and 1 MiB + 1 to `/call`) gets
     `HTTP/1.1 413` with its JSON body readable to the end, either because the server drains a
     bounded amount of the refused body before closing, or the test keeps tolerating a reset
     and host TECHNICAL 8.1 states why (one sentence: what a client sees and why it is enough).
     Pick one and say which in TECHNICAL.
AC3. A test opens a `/call` to a mod function that runs for a while (an existing slow fixture
     or a fuel/loop fixture already in host/tests/fixtures), drops the connection mid-call, then
     the server still answers a new request, and `Served::shutdown` returns within the bound the
     spec states (measure it; give the test a margin and say so).
AC4. `Served::shutdown`'s bound in code (server.rs, now 4 s for routers then 5 s total) and in
     host/TECHNICAL.md (2.1 "the shutdown bound of 12.2", 12.2 "up to 5 s") say the same thing.
AC5. `ac4_program_defaults_to_environment_home_and_port` (host/tests/it/program.rs) no longer
     binds 47341 to probe it: it starts the program without `--port` once; if the program reports
     `port_in_use` (the named error of 12.2), the test checks that error and then checks the home
     defaults with `--port 0`; else it asserts port 47341.

dev code matches `bad_request` for an unknown route (searched app/src, app/ui, dev/src).
