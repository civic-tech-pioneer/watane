Slice: S54 — A real static host: Alice's channel is served from GitHub Pages over real TLS and dist fetches from it

## Goal

The real J3 (`app/tests/j3.rs::ac3_j3_real_github`, feature `real-github`, ignored) no longer serves
Alice's pushed site from `Site::serve` on `127.0.0.1`. Instead it turns on GitHub Pages for the site
repository the harness created in `minmax-fund`, waits until Pages serves it, and Bob installs Alice's
mod from `https://minmax-fund.github.io/watane-j-<r>/` over real TLS. The same test then checks two
things a loopback server could not: dist's DD-26 local-address rule does not skip a listed base that
is a real public host (Ivy lists Alice; Bob chooses Ivy and finds Alice's mod through the listing),
and a request for something Pages does not have gives the CDN's 404, which Bob sees as a clear
"not found" install error, not a timeout or a parse error.

## Acceptance

AC1 Harness (`app/tests/support/github.rs`): `RealGithub::pages(&self, name: &str) -> String` turns on
Pages for a repository the harness created or reserved (assert the `PREFIX` guard first), serving
branch `main` at `/` (`gh api --method POST repos/<name>/pages -f 'source[branch]=main' -f
'source[path]=/'`), and returns its base URL with exactly one trailing slash, from the answer's
`html_url` (expected `https://minmax-fund.github.io/watane-j-<r>/`; assert it starts with `https://`).
Nothing new is needed on Drop: deleting the repository removes its Pages site.

AC2 Harness: `RealGithub::wait_served(&self, url: &str, expect: &[u8], deadline: Duration)` fetches
`url` over HTTPS (blocking `reqwest`, already a dev-dependency) every 10 s until it answers 200 with
exactly `expect`; on the deadline it panics with a message that says Pages did not serve `url` within
the deadline, the last status seen, and how long it waited. The deadline in J3 is 10 minutes. It sends
no token (Pages is public).

AC3 Real J3: after Alice's first `publish --push` (unchanged), the test calls `pages(&site_name)`,
waits until `<base>head` equals `main:head` of a fresh clone of the site repository, then sets
Alice's site URL to that base (`site_set_url`) instead of `Site::serve`'s. The retry still gives
`publish.version_exists` with a `link` that names the Pages base. Bob installs from that link exactly
as now (consent shows "Alice" and "signature verified"; one mod, publisher Alice, the same release,
its page opens and shows "Reading"). The test no longer starts `Site::serve` for Alice.

AC4 DD-26 against a public host, same test: Ivy is an in-process `watane_dist::Dist`
(`support::publish::dist`) with its own local `Site::serve` (a chosen index may be local, DD-6). Ivy
lists Alice's mod using the Pages link from AC3 (as `tests/find.rs` does with `ivy.list`). Bob's app
chooses Ivy (`support::publish::choose`) and searches (`search_reading` or the `find` command the
fixture uses); the result includes Alice's mod listed by Ivy, and Ivy's skipped list (the find view's
`[data-index=...]` row, or the `IndexView.skipped` the app returns) does not name Alice's channel and
contains no `local address`. `Options::listed_local` stays `false` (the app's default).

AC5 CDN 404, same test: Bob's app `install_link` with a link built from Alice's link with the release
or slug changed to one that was never published (same Pages base, same key) fails within 60 s with
the app's error for dist's `NotFound` (find the code it reports; assert that code and that the
message names a URL under the Pages base). No mod is added (`mods_list` still has one).

AC6 Compiles without the feature (`cargo test -p watane-app --features driver --no-run`) and with it
(`--features driver,real-github --no-run`); clippy clean with both; `ac2_j3_github` (fake) unchanged.
