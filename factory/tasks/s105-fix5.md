## Goal

This task closes the adversary's round-5 breach (9205190). An index moves its listing of a channel to a fresh base on each
refresh. `sync_listed` notes each fresh base in `seen`, so after 16 refreshes the 16-entry cap drops the first
base `a`. A stale hit at `a` then counts as unseen and gives it. A held base can be pushed out the same way
when one `sync_listed` runs after the index changed (adversary RISK). Foreman decision, inside DD-48 and
fail-closed: a full `seen` never drops a base. The 17th base is not noted, and the record gets
`seen_full: true`; from then on a link gives no base that is not already in `given`. The rule is in
dist/TECHNICAL.md 4.4 and DD-48, committed with this brief. The same commit also asks for tombstone bases
to be normalised on load (adversary note).

## Acceptance

1. AC1. The red test `http::tests::adv_s105_r5_listing_churn_evicts_base_from_seen_then_stale_hit_gives_it`
   (9205190) passes unchanged.
2. AC2. Unit tests in follow.rs:
   - a record with 16 seen bases that learns a 17th keeps all 16, does not note the 17th, and sets `seen_full`;
   - a link at an unseen base of a `seen_full` record gives nothing, and its first read is listed;
   - a link at a base in `given` still gives it.
   Replace `ac5_seen_and_given_hold_sixteen_oldest_first_out` where it asserts oldest-out for `seen`.
   `given` keeps oldest-out: dropping from `given` only makes reads stricter.
3. AC3. `seen_full` is serde default `false`, skipped when `false`, on records and tombstones. A tombstone
   carries it and a new record takes it back. Extend the AC6 tests.
4. AC4. Tombstone bases are normalised on load as record bases are. Test: a hand-written tombstone with a
   non-normalised spelling of `a` still blocks a hit at `a`.
5. AC5. All dist tests (also `-- --include-ignored`), clippy and fmt pass. Run `factory/check.sh s105-fix5 <base>`.

## Interface

No public signature change. Private: `Follow.seen_full: bool`, `Tombstone.seen_full: bool`. The helper that
decides whether a link gives its base becomes: `given.contains(base) || (!seen_full && !seen.contains(base))`.
The helper that notes a base in `seen` sets `seen_full` instead of evicting.
