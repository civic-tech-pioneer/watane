Slice: S4 — The agent fixes a failing test: it breaks the counter's `add`, runs `watane-dev test`, reads the result, fixes the code, and the tests pass.

## Goal
`watane-dev test` exists. It runs check, build, then the mod's unit tests as WebAssembly in
Wasmtime with no capabilities, and reports each failing test, an endless test, and the counts.
Check gains stage 6 (a logic part needs a `tests/*.json`), and the template ships
`tests/counter.json`. `mod.dependency` and `mod.cargo_key` errors carry their line in
`logic/Cargo.toml`. The contract part of `test` is null in this task (task S4-3 adds it).

## Acceptance
- AC1 On a new template mod, `test --json` exits 0; `result.unit.passed` equals the number of
  `#[test]` functions in `logic/src/lib.rs` (the test counts them with a regex on the file);
  `failed` 0, `ignored` 0, `not_run` 0; `result.check` and `result.build` are present;
  `result.contract` is null; `next` is `watane-dev serve --json` (dev 2.4 **test**).
- AC2 (DEV-S-15) Add `#[test] fn fails_on_purpose() { assert_eq!(1, 2); }` to the template's tests:
  exit 1; an error `test.unit` whose `test` text / message names `fails_on_purpose`, with `file`
  `logic/src/lib.rs` and the `line` of the assert (the test finds the line in the file it wrote);
  tests after it are counted in `not_run` (7.2). `next` is `watane-dev test --json`.
- AC3 (DEV-S-16) A unit test `loop {}` with `WATANE_DEV_UNIT_SECONDS=2`: exit 1 within 2 + 5 s
  wall clock (the test measures it), error `test.unit_limit` naming that test.
- AC4 (DEV-S-14) A unit test that tries `std::fs::read_dir("/")`, `std::env::var("HOME")` and
  `std::fs::write("<a tempdir path the test chooses>/escape", ..)`: the test asserts inside Wasm
  that each fails (so the unit run passes), and the outer test checks that `escape` does not exist.
- AC5 (DEV-S-20) A logic part and no `tests/*.json` (delete the template's file): `check --json`
  and `test --json` exit 1 with `mod.no_contract_tests` and its fix (2.2). A page-only mod needs none.
- AC6 The template: `new` writes `tests/counter.json` with exactly the text of dev 4.1; the
  envelope test's literal file list includes it; `template/AGENTS.md` gains section 7 (Tests,
  without the `deliver` and fake examples: say they arrive with links) and sections 2 and 10 say
  to run `watane-dev test --json` before `serve`. Keep AGENTS.md at most 150 lines.
- AC7 `mod.dependency` (DEV-S-6, `rand = "0.9"`) and `mod.cargo_key` (DEV-S-7,
  `[build-dependencies]`) give `file` `logic/Cargo.toml` and the `line` of the offending key; the
  test computes the line from the text it wrote.
- AC8 A compile error in a `#[cfg(test)]` part gives `build.compile` with file and line, as a
  normal build does.
- AC9 `cargo test` (and `WATANE_BIN=... cargo test -- --include-ignored`), clippy `-D warnings`
  `--all-targets --all-features`, `cargo fmt --check` pass. Existing tests stay green (a
  template-based test that now needs `tests/` gets it from the template).

## Decisions already made (foreman)
- The unit runner is the sandbox boundary of 7.1 exactly: no preopened folder, no environment,
  no network, epoch deadline, 512 MiB memory limit, unknown imports trap. Do not add a capability
  to make a test pass.
- `serve` does not run tests in this task (S4-3 does).
