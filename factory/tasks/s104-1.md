Slice: S104 — dist reads past a bad mirror and says what is stale

## Goal

A provider fetch can get its verified package from the first working mirror, and a cached fetch returns a link only when its candidate base is usable. The error distinguishes an absent mod slug from an older mirror copy.

## Acceptance

1. If a provider mirror serves the signed release but returns HTTP 404 for its package, try the next eligible base. Return the verified package and link to the base that served it. Keep verification failures terminal.
2. A cache hit with no follow record skips a dead base even if its hint ranks first. Keep the cached install available when every candidate fails. Do not request the package on the cache path.
3. Stale mirror errors use “1 base” and “2 bases”. When no verified view from any serving base contains the slug, return the existing slug-not-found error. Keep the stale result when a serving view contains the slug at another version.
