## Goal
dev/src/main.rs and dev/src/cli.rs give texts and `next` values that mislead. After this task:

1. Usage errors (main.rs ~20): the message is clap's first line without its leading `error: `
   (text mode printed `error[usage.args]: error: ...`). With no arguments at all (or no
   subcommand) the message is `no command given: watane-dev needs one of new, check, test, serve,
   doctor, add, install, publish, search` instead of the whole help text. Fix stays
   `watane-dev --help`, code `usage.args`, exit 2.
2. Failed `serve` (cli.rs ~213): `next` is rewritten from `... test --json` to `... serve --json`
   (`failed_test_next`), but each error's own `fix` still says `test --json`. Rewrite the fix of
   every `test.unit`, `test.unit_limit` and `test.contract` error the same way (only in the branch
   where `next` is rewritten, i.e. the failing mod is the served one).
3. `env.host_not_running` for a home with a missing ancestor (`--home x/../h`, cli.rs ~650): the
   fix says "Start the watane app" though no app can run there. New fix: `Pass --home the folder
   that the watane app uses (<missing> does not exist), then run this command again`. The other
   host_not_running fixes (api.rs) keep theirs.
4. `next` values that are prose, not a rerun. Rule: a `next` is a command, or a step ending in
   `then run: <command>` (or `: <command>`) where the command is complete and runnable. Exact values
   (`<dir>` = canonical mod folder, quoted with cli.rs's `quote`; `<home flag>` = see 6):
   - `add --release` success (~184): `Copy the lines that the mod needs from result.imports and
     result.subscriptions into the world in wit/world.wit (each line is a grant that the participant
     approves; contract tests use a fake of it, see AGENTS.md), then run: watane-dev test --json
     --dir <dir>`.
   - local `add` success (~198): `Copy the lines that the mod needs from result.imports and
     result.subscriptions into the world in wit/world.wit (each line is a grant that the participant
     approves), then run: watane-dev test --json --dir <dir>` (if the local add result has no such
     fields, name the fields it does have; check `AddReport`).
   - `new --from` (see 5).
   - `search` with no results (~511): no index: `Ask the person to add an index in the watane app,
     then run: <the same search command>`; else with two or more words: `Try fewer words: <the same
     search with only the first word>`; with one word: `Try other words, or search with --interface
     <name>: watane-dev search --json <other words>`. "The same search command" is built exactly as
     the host-not-running `next` at ~496 builds it (factor it out once; use it in both).
   - `publish` success, no link (~850): `Ask the person to set your site's URL in the watane app,
     then run: <rerun>` (the rerun reports the link through `publish.version_exists`).
   - `publish` success with a link and no push: `Put the site folder <abs site> on your static web
     host, then give the person this link: <link>` (nothing runs after this; it names the folder).
   - `publish --push`, raw site and no link (~881): `Ask the person to set the site URL in the
     watane app to <raw>, then run: <rerun>`.
5. `new --from` (cli.rs ~297-318): both branches end `then run: watane-dev test --json` with no
   `--dir`, though the new mod is in another folder; and for a prebuilt package (`logic.wasm`, no
   `logic/Cargo.toml` in `files`) they point at `logic/src/lib.rs`, contradicting the
   `new.prebuilt_renamed` warning. New values (all end `then run: watane-dev test --json --dir <dir>`):
   - not prebuilt: today's two texts, with the new ending.
   - prebuilt, same slug: `Edit wit/world.wit and ui/ (logic.wasm is prebuilt and keeps its
     exports), then run: ...`.
   - prebuilt, renamed: `<mentions part, if any mentions>, write the logic source under logic/
     (logic/Cargo.toml and logic/src) for <slug>, then run: ...` — the mentions part is today's
     `Replace <from> with <slug> (and <from_> with <slug_>) at each result.mentions entry`; with no
     mentions the text starts `Write the logic source ...`.
6. `--home` in `next` (cli.rs ~663 `app_client`, ~736 publish rerun, ~496 search): every rerun
   appends `--home <resolved>` even when the home came from `WATANE_HOME` or the default. Append it
   only when the command was given `--home`. (The publish local-dependency `next` at ~720 already
   does this; match it.) The resolved spelling stays as TECHNICAL 9.6 says when it is appended.
7. `publish.local_dependency` (cli.rs ~701): "it has no release" is wrong (the provider may well be
   published; deps.json just names it as local). New message: `mods:<slug> is a local provider
   (deps.json names its folder, not a release), and a published mod can depend only on released
   providers`. The code's fix stays as it is. dev/TECHNICAL.md:227 documents a different fix
   (`... then run: watane-dev add --release <that link>`) that the code no longer gives: change the
   document to the code's fix and the new message (decided by the product owner: fix the document).
