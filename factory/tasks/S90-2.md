## Goal
Core tells the window what it did and stops doing needless work. After this task: an install
that made watane follow a publisher's channel returns those channels so the window can say so;
"Deny" on a dist signing consent reads as what was denied (today dist's bare `statement refused`
reaches Alice unchanged); and `Core::mods()` no longer re-reads every related channel view from
the log on each 2 s refresh: an unchanged channel's view is reused.

## Acceptance
- AC1 `install_release` and `install_link` return `{"installed": [...], "followed": [<label>]}`:
  the party labels (as the channels list labels them, Rust `party_label`) of channels that are
  followed after the command and were not before. Empty when the channel was already followed.
  Unit test in core.rs or commands.rs with a fake/real dist: first install of a mod from an
  unfollowed channel → one label; second install from the same channel → empty.
- AC2 A `DistError::Refused` from a dist signing command reads as what was denied, ending
  `; nothing was signed.`: withdraw → `You denied withdrawing <slug> <version>; nothing was
  signed.`; profile name → `You denied setting your name to <name>; ...`; index add/remove/
  include → the matching verb and the listed party/mod; publish route (api.rs's `Refused` arm,
  ~line 232, code stays `refused`) → `You denied publishing <slug> <version>; ...`. The words
  live in app/src/words.rs, one function. Error code unchanged. Unit tests per command kind;
  no message contains `statement refused`.
- AC3 `Core::mods()` (and `cache_channels`, `followed()`, the origin lookup in `view()`) reuse a
  memoized `ChannelView` per channel key while its key holds: `dist.heads(...)` unchanged for
  that channel AND the follow records unchanged (stamp of `<home>/dist/follows.json`: mtime and
  length, or a better dist-public fact you find). A unit test counts view builds (or `dist.channel`
  calls) across two `mods()` calls with nothing changed: the second builds none; a new log entry
  for one channel rebuilds only that one; a follow/unfollow rebuilds. `host.mods()` is read once
  per `mods()`, not once per mod. Results are byte-identical to today's (existing core tests pass
  unchanged).
- AC4 `cargo test -p watane-app`, `cargo test -p watane-app --features driver --test it -- --include-ignored j4:: j3:: find::`,
  clippy `--all-targets --features driver -D warnings`, `cargo +nightly fmt --check`.
