Subsystem: install
Effort: medium
Depends on: s50b-1
Slice: S50b — the install script and its archive (install stages 1 to 3)

## Goal
`install/package.sh` assembles one release archive with the tree of install/TECHNICAL 4.2 from
built programs, the app bundle and the vendor folder, and writes its `SHA256SUMS` line (5), so a
person on a Mac or the release workflow can pack a release. `tests/package.rs` runs it over fake
programs on Linux. And the swap's kill and journal scenarios INST-S-32 to 35 run against the
script s50b-1 built; finally the script installs an archive that `package.sh` made. Stage 3 of
install/TECHNICAL 11, plus the scenarios TECHNICAL 12.5 puts in `cargo test`.

## Acceptance
- AC1 `package.sh` with its arguments of TECHNICAL 4 over fake programs, a fake `watane.app` and a
  fake vendor folder produces `watane-<v>-<target>.tar.gz` whose listing equals the tree of 4.2,
  with `share/watane/install.sh` the script with `@RELEASE@` replaced by `<v>` and `VERSION`
  holding `<v>`. Test in `install/tests/package.rs`.
- AC2 `package.sh` refuses (non-zero exit, a message naming the part) when any part is missing:
  one test per part (each program, the app, the vendor folder) or one table-driven test.
- AC3 `codesign`/`otool` steps are skipped when the tool is absent (Linux); the signature check is
  `#[cfg(target_os = "macos")]`.
- AC4 End to end: an archive from `package.sh` (fake programs), plus its `SHA256SUMS`, served by
  the fake release of `tests/support`, is installed by its own `share/watane/install.sh` copy into a
  temp `$HOME`, then upgraded to a second packed version, then uninstalled (on the pty). Exit 0 each.
- AC5 INST-S-32, 33 (all three kill tests), 34 and 35 are tests in `install/tests/script.rs`
  asserting their oracles; they pass. If one turns red because of the script, fix `install.sh`.
