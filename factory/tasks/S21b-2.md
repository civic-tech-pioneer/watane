## Goal
Three small fixes the S21a user-sim found, decided in `dist/TECHNICAL.md` 13 (DD-15 to DD-17,
already written): a reader that reads up to a new head also reads `entries/<head seq>` and refuses
it when it differs from `head` (`HeadMismatch`, naming its URL), so a damaged entry file on a host
no longer goes unnoticed; `confirm_own` with a link of another key is `NotOwnLink`, whose text says
"this link is not your channel"; and `follow`'s contract (every failure of a first follow is `Err`)
is pinned by a test.

## Acceptance
- AC1 (DD-15) Alice publishes twice (head seq 2 counting the profile, as the existing follow tests
  do); one byte of `site/entries/<head seq>` changed: Bob's first `follow` is
  `Err(HeadMismatch { url })` with `url` = the TestHost URL of `entries/<head seq>`; Bob follows
  nothing and holds no entry at that seq.
- AC2 (DD-15) same damage after Bob followed at an older head: `refresh_channel` is `Ok` with
  `Outcome::Failed { cause: HeadMismatch { .. } }`, and Bob's stored head stays the older one.
- AC3 (DD-15) an undamaged site still follows and refreshes as before (the existing `follow_*`,
  `refresh_*`, `j3_dist` tests stay green).
- AC4 (DD-16) a restored home: `confirm_own(Some(<carol's key, alice's host>))` is
  `Err(NotOwnLink { found: carol })`; its `Display` contains "this link is not your channel"; the
  head stays unconfirmed and no request was made.
- AC5 (DD-17) a first `follow` whose `entries/1` is damaged is `Err(Invalid { .. })` (not `Ok` with
  `Failed`), and `followed()` is empty.
- AC6 `cargo test -p watane-dist`, `cargo clippy -p watane-dist --all-targets -- -D warnings`,
  `cargo fmt --check` pass.

with a `Display` that escapes untrusted text like the others. No method signature changes.
