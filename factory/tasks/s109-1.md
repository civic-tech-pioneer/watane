Slice: S109 — open the log identity key without a check-then-open

## Goal

Only load a private, singly linked regular identity key owned by the current user. Reject unsafe objects at the key path before reading any seed bytes.

## Acceptance

1. A valid mode 0600 key reopens and yields the same identity.
2. A symbolic link, including a dangling one, is refused with a path-specific error.
3. A hard link to a valid seed is refused with a link-specific error.
4. A FIFO returns a clear error promptly. A device node is refused before reading.
5. A foreign-owned key or a key with a mode other than 0600 is refused with a clear error.
6. Fresh creation and restore still produce private keys that reopen.

Existing log identity operations through `Log::open` and restore. No sibling interface.
