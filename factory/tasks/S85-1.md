## Goal
On Linux, the manager window opens with its page when a mod window was opened first (the app started
in a main mod, then Mods… or Settings… from the menu). Today it stays on `about:blank`. And the
Linux test image has the tools the suite uses, so `bash app/scripts/linux-test.sh` exits 0.

The foreman found both causes (with throwaway probes, since reverted):
1. tauri-runtime-wry 2.12.3 (`src/lib.rs`, `create_webview`, around line 4706 and 5115) keeps one
   `WebContext` per `data_directory` key and, on Linux, registers each custom protocol (`tauri://`,
   `ipc://`) once per key. Our mod windows (`views::open_mod`) are `incognito(true)` and have no
   `data_directory`, so they share the key `None` with the main window. wry (`webkitgtk/mod.rs`
   `new_gtk`, line ~259) gives an incognito webview a fresh ephemeral context and registers the
   protocols there, but tauri marks key `None` as registered. A main window built later under key
   `None` gets no `tauri://` handler and never loads `index.html`. Proof: with `.incognito(true)`
   removed, `manager::ac3_s39_menu_and_last_window_exit`, `manage::ac2_s44_...` and `j10` pass on
   Linux. Do not remove incognito: it is the mods' isolation.
2. `machines::ac1_s28_off_by_default_and_publish` runs `lsof`, which the image lacks
   (`Command::output()` NotFound at machines.rs:115). With `lsof` added to `app/linux.Dockerfile` it passes.

## Acceptance
- AC1 Mod windows get a webview context key of their own, distinct from the main and consent
  windows' (e.g. `.data_directory(<a fixed path under the app's home that nothing writes>)` on the
  `open_mod` builder; choose the value; incognito stays). A comment there names the tauri-runtime-wry
  behaviour above in one or two lines, so nobody "simplifies" it away. Nothing is written to that
  path by an incognito view; check that on Linux after a run (list it) and say so in NOTES.md.
- AC2 `app/linux.Dockerfile` installs `lsof`.
- AC3 On Linux (`bash app/scripts/linux-test.sh --test <file> <name>`, Docker is running), these pass:
  `manager ac3_s39_menu_and_last_window_exit`, `manage ac2_s44_disable_closes_page_and_restart_clears_notice`,
  `j10 ac3_journey_j10`, `machines ac1_s28_off_by_default_and_publish`. Then the whole
  `bash app/scripts/linux-test.sh` exits 0 with 0 failures.
- AC4 Natively on macOS: `cargo test -p watane-app`, and with `--features driver` only the test files
  that open mod windows and the main window after them: `--test manager`, `--test manage`,
  `--test j10 -- --include-ignored` (front tests stay skipped). clippy (`--all-targets --features driver
  -D warnings`) and fmt clean.
- AC5 No test is weakened, skipped or given a Linux-only branch. The existing tests above are the
  regression tests; add no new one unless a cheaper level can show AC1 (it likely cannot).
