Subsystem: net
Effort: low
Depends on: none
Slice: S87 — a light machine reports a full machine's changed bytes again

## Goal
When a light machine's `need_blob` ends in `Unreachable` (some full machine connected and none
gave the package), net also emits that same `Event::Unreachable`, so the app's Machines view
shows why the package did not come. Today the error is returned and dropped by node, so a full
machine whose own file changed (iroh-blobs checks it and resets the stream before sending it)
leaves Machines with no problem line at all, depending on timing.

## Acceptance
- AC1 `need_blob` of a package no connected full machine has: the error is
  `Unreachable { node, cause }` as today, and a receiver from `net.events()` taken before the
  call gets exactly one `Event::Unreachable` with the same `node` and the same `cause`.
- AC2 A full machine whose held file for a package no longer matches the package's hash
  (written after the store referenced it, as `app/tests/it/machines.rs`
  `ac6_s33_corrupt_full_machine_and_no_path_name_causes` does): `need_blob` from the light
  machine gives `Unreachable` with "not served" in its cause, or `BadObject` "does not match
  its hash"; and in both cases the light machine's events carry it (`Event::Unreachable` with
  that cause, or `Event::Refused`). Nothing is handed to the holder. Run it 5 times in a loop in
  the test or by hand and say how often each branch came.
- AC3 `TooLarge`, `Refused { NotAllowed }`, `NoFullMachine`, `Off` emit no new event.
- AC4 Every net test passes (`cargo test -p watane-net -- --include-ignored`), clippy, fmt.

## Spec
net/TECHNICAL.md 5.9 `need_blob` (updated in this brief's commit), 5.8, NET-F-32.

## Interface
Provides (fixed): `Event::Unreachable { node, cause }` from `need_blob`, `node` and `cause` equal
to the returned `NetError::Unreachable`'s (`package <hex8> was not fetched: <why>`). No new type
or variant. The app task S87-2 relies on this.

holder fakes can change a referenced file (net/tests/it/light.rs or faults.rs; reuse
tests/support).
