## Goal
The Rust side of the new look. A `main = true` mod becomes the start window however it was installed
(also by `watane-dev install` or a managing mod), and an update never makes a mod main. The page gets
what the new views show: short grant words, when channels were last checked and read. The menu has
separators and the usual Edit and Window menus. Dragging files over the manager shows a drop target.
Tests can read the menu and switch light and dark.

## Acceptance
- AC1 `HostConfirm::installed` (app 5.4, host 12.1) applies the main-mod rule with `Installed.new`
  for every requester: when `<home>/app/main` is absent, the first new mod with `Mod::main()` true
  becomes main. It only writes the file (or spawns that write), never blocks. `Installed.updated`
  never sets main. The per-command adoption of stage I (`main_mod.rs` `installed` and its callers) is
  removed, so one place decides.
- AC2 `tests/manager.rs` S51: `watane-dev install` of `desk` into a running app with no main, approved
  in the consent view (which shows the start-window line), writes `<home>/app/main` = `desk\n`; a
  restart opens `mod-desk` only; with the start switch turned off (`main_set` null), an update of
  `desk` leaves the file absent. Every earlier S37 to S42 test still passes.
- AC3 Section 4 short form: `GrantLine.short` (serde default, empty from `grant_line`), `grant_short`
  in `words.rs`, set by Core for `ModView.grants` and `offerGrants` only (consent keeps the exact
  words). `words::tests` (K) row: the literal strings of app/TECHNICAL 11 (`Call books of Reading
  list by Alice`, `Receive the events of Reading list (local)`, a bound provider, `you`, a provider
  not installed (slug); storage, http and manage equal `text`).
- AC4 `Status.checkedAt` (ms, end of the last refresh, 9.5, memory only, null before the first) and
  `ChannelRow.readAt` (ms of the last refresh in this run that read that channel, memory only).
  Unit-tested in core.rs like the existing `checkedAt` of `HitView`.
- AC5 Menu (5.4): app submenu `About watane`, `-`, `Mods…`, `Settings…`, `-`, `Quit watane`; then
  `Edit` (Undo, Redo, `-`, Cut, Copy, Paste, Select All) and `Window` (Minimize, Close Window), Tauri's
  predefined items. Driver op `menu_items` (section 10) returns `[{menu, items}]` read from the
  app's `Menu`; `tests/manager.rs` S39 (W37) asserts the three submenus' items and separators in order
  (macOS labels: assert what Tauri gives and note it in NOTES.md if a predefined label differs).
- AC6 Drop target (5.3.2): the main window's drag-drop handler, on `Enter`, evaluates the constant
  `document.body.classList.add('dropping')` in `main`; on `Leave` and `Drop`,
  `document.body.classList.remove('dropping')`. No path reaches the page this way; drops still go to
  `install_paths`. Expose the two script strings as constants (e.g. `views::DROP_ENTER_JS`) so a test
  can name them; a unit test checks they are constant and carry no `{`-formatting.
- AC7 Driver op `theme` (`"light" | "dark" | null`): `set_theme` on every open window, returns `true`.
  A quiet driver test shows that after `theme dark`, `matchMedia('(prefers-color-scheme: dark)').matches`

- AC8 `cargo test -p watane-app`, and `--features driver -- --include-ignored` (front four skipped)

## Interface
Takes from S84-1: `watane_host::Installed { requester, new: Vec<LocalName>, updated: Vec<LocalName> }`,
`Confirm::installed(&self, &Installed)`.
Provides to S84-3 (the UI task, built in parallel; these names are fixed): `GrantLine.short: String`
(JSON `short`, may be empty: the page falls back to `text`); `Status.checkedAt: number|null`;
`ChannelRow.readAt: number|null`; the class `dropping` on `body` of `main`; driver op `theme` with
field `theme`, and the support client method `App::theme(&self, theme: Option<&str>)`. S84-3 also
adds `theme` if it reaches it first: keep the same op name, field and client method; on rebase the
second copy is dropped.
