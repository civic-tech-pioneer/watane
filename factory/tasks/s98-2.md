## Goal
Two window-test races that the 3-core macos-26 runner loses (S98 diag run 44891209774) end, each
by waiting on the real condition:
1. `look::windows::ac3_ac4_ac6_ac8_library_details_confirm_install_and_badges` renders literal
   `ModView` data with `page.modsView(badges)` and then checks it over several evals. The main
   page refreshes itself (`app/ui/app.js`: every 2 s when visible, every 10 s when hidden; since
   S90 the hidden main window's timers are not throttled), and that refresh re-renders the real
   `mods_list` over the literal data. On the runner the refresh lands between the render and a
   check: "DOM timed out" on the badge check, or `.notice` is null in a later eval (an eval that
   throws comes back as `""`, "native eval returned invalid JSON: EOF").
2. `manage::ac5_s45_install_denied_approved_and_unread_link_never_connects` (and any `until`)
   evaluates while the page is between documents (Core reloads it on a grant change): WebKit
   fails the eval, the driver returns `""`, and `until` panics on the JSON instead of trying
   again.

## Acceptance
- AC1 Polling helpers treat a failed eval as "not yet": `support::journey::until`, and the local
  `until` of `gui_shell.rs` and `gui_isolation.rs`, retry while the driver's eval result is not
  JSON `true`, including the empty result of a failed eval; on timeout the message still names
  the label and the script, and adds the last raw result. One helper in `support/driver.rs`
  (for example `App::is_true(label, js) -> bool`, which never panics on an empty result) used by
  all three; `App::eval` itself keeps panicking on invalid JSON for one-shot reads.
- AC2 The look test's literal-data checks cannot be overwritten by the page's own refresh: each
  check that depends on literal `ModView` data renders that data and evaluates its condition in
  the same JavaScript turn (for example keep the imported module in `window.__page`, then poll
  `(window.__page.modsView(BADGES), CONDITION)`; reopen the details or set the narrow width in
  that same turn where the condition needs it). Every assertion the test makes today is still
  made with the same values: no check removed, no tolerance widened.
- AC3 A unit test of AC1's helper's parsing (an empty result is false, `true` is true, `false`
  and other JSON are false), at the lowest level that shows it, without a window.
- AC4 `cargo test --features driver --test it -- look:: manage:: gui_shell:: gui_isolation::`
  passes; then the whole `it` binary with `--features driver`; clippy and fmt.
