## Goal
The release workflow exists: `.github/workflows/release.yml` builds the macOS archive on
`macos-14` from a tag (and, by hand, as a dry run that publishes nothing), and publishes it
from a second job that runs no repository code. `cargo test -p watane-install` checks its
rules (INST-S-29). The README shows the one-line install command.

## Acceptance
- AC1 `.github/workflows/release.yml` follows install/TECHNICAL 7.1, 7.2 and 7.3 exactly: the
  triggers (tag pattern, `workflow_dispatch: {}` with no inputs), `permissions: {}` at the
  top, job `package-macos` on `macos-14` with `contents: read`, steps 1 to 7 (checkout with
  `persist-credentials: false` and `fetch-depth: 0`; the version and origin check over the
  five files, with `git merge-base --is-ancestor "$GITHUB_SHA" origin/main` on tag runs; the
  runner's stable Rust, no cache of any kind; `MACOSX_DEPLOYMENT_TARGET=14.0 cargo build
  --release --locked -p watane-host -p watane-dev -p watane-node`; `cargo install tauri-cli
  --version '=<x.y.z>' --locked` with an exact version that builds this repo's `app` (read
  the tauri version in `Cargo.lock`), then `cargo tauri build --bundles app --config ... --
  --locked` in `app/`; `install/package.sh aarch64-apple-darwin <version> dist-out/`; the smoke
  `sh install/tests/clean_mac.sh --from "$PWD/dist-out" --fresh-home`), then upload
  `dist-out` as a workflow artifact. Job `release` on `ubuntu-latest`: `needs: package-macos`,
  `if:` a tag ref, `environment: release`, `contents: write`, no checkout, no `cargo`, no
  `sh` of the repository; downloads the artifact and runs step 8 with `gh` (`--repo
  "$GITHUB_REPOSITORY"`, draft first, `--draft=false` last; notes with the one-liner, the
  pinned line and a link to install/TECHNICAL.md 6.2). Every `uses:` is pinned to a 40-hex
  commit SHA with the tag in a comment (look the SHAs up with `gh api`).
- AC2 `install/tests/workflow.rs` (INST-S-29, install/FUNCTIONAL) passes against the file and
  fails against a copy with each rule broken (one small in-test mutation per rule: e.g.
  `persist-credentials: true`, an `actions/cache` step, a `@v4` tag, a dispatch input, a
  missing `-- --locked`, `contents: write` in `package-macos`, no `environment: release`).
  Line rules over the text; no new dependency unless the crate already has a YAML parser.
- AC3 `package.sh` writes `@RELEASE@` → the version into the `install.sh` it packs, if it does

- AC4 `README.md` gains a short "Install (macOS, Apple silicon)" section with the one-line
  command of 3.1, the `--no-toolchain` form and a link to `install/FUNCTIONAL.md`. Keep it short.
- AC5 `actionlint` (if installed: `brew list actionlint`) reports nothing on the file; say in
