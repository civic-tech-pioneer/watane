## Goal

The light-machine and restore half of stage N4 (net/TECHNICAL.md 5.9 and 5.11; the N4 row of 9).
A light own machine (Alice's second laptop) asks a full machine when it searches (`Net::query`),
when it needs a channel (`Net::need`) and when it needs a package (`Net::need_blob`); each pull
goes through the holder with `Why::Asked`, and a light machine prefers a full replica over the
anchor (node Q5). The callee answers the `query` op of `watane/1` from its holder only. After a
restore, `Net::own_heads` gives each reachable full machine's head of a channel as a hint and
changes nothing in the holder (NET-F-30). The anchor keeps only what its holder asks for, as a
light machine does (NET-F-21, node Q5). One query pulls at most 32 channels, and the cap holds per
caller over 5 s so that three calls for one participant query cannot pull 96 (node Q6). Plus
three follow-ups from S63's user-sim: a package over `limits.blob` gets a cause, a wrong-hash
cause in watane's words, and a `Refused` cause that names the short key.

## Acceptance

AC1 API (TECHNICAL 3, fixed). `Net` gains, with these exact signatures:
`need(&self, channel: &PublicKey) -> Result<(), NetError>`,
`need_blob(&self, id: &BlobId, size: u64) -> Result<(), NetError>`,
`query(&self, query: &Query) -> Vec<(NodeKey, Vec<Hit>)>`,
`own_heads(&self, channel: &PublicKey) -> Vec<(NodeKey, Option<HeadInfo>)>`.
No other public type or the `Holdings` trait changes. A new `Limits` field is allowed only if
`hello` does not send it and its `Default` is the spec value; say so in 9.

AC2 The `query` op (4.2, 4.4). `query` is now an op (no longer `unknown_op`): trusted callers
only (an unknown caller gets `not_allowed`, before the holder is called). Args: the query of 4.4,
decoded strictly (a `limit` above 200, a `mode` other than `offers`/`uses`/`sends`, a slug or
text that is not text: `bad_request`). Answer after `"ok"`: one item `[hits: [hit]]`, at most
`min(limit, hits_per_answer)` hits, from `holdings.search` only (no forwarding, NET-F-17), within
the request deadline (`busy`). The caller (`query_of`, crate-private or public as you like)
checks the answer: hit count within the limit, each hit 32-byte channel and id; else `BadObject`.
Unit tests for the codec (round trip and each refusal) in `src/`.

AC3 Choice of a full machine (5.9, node Q5, NET-F-21). For `query`, `need`, `need_blob` and
`own_heads` the candidates are the machines of the newest device list with role `Full`, other than
this node. In order: full replicas (not the list's anchor) with a kept connection, then full
replicas reachable by dial, then the anchor the same way. `need`/`need_blob`/`query` use the first
that answers; a machine that is dropped for the session (5.6) is never a candidate. None reachable:
`need` and `need_blob` give `NetError::NoFullMachine`; `query` returns the own hits only. With net
off: `need`/`need_blob` give `Off`; `query` returns the own hits only; `own_heads` returns empty.
Unit test of the ordering in `src/` (a pure function over the list, this node and the set of
connected machines).

AC4 The anchor keeps what its holder asks for (NET-F-21, 5.6). In sync (5.6 step 1 and the
`Why`), the machine that is the anchor of the list (`holdings.is_anchor()` or the list's anchor
being this node) behaves as a light machine: it asks `heads` for `holdings.heads(None)` only and
ingests with `Asked`; it acts on hints for held channels only (5.7). Only a full replica asks for
all and ingests `Kept`. Write this into 5.6 and 5.7. Test: an anchor paired with a full replica
that holds a channel the anchor's holder lacks does not pull it on connect.

AC5 `need(channel)` (5.9, NET-F-26). Asks the chosen machine `heads` for that channel, then
`entries` from the holder's seq + 1 in pages to that head (ND-14 checks on each page), ingests with
`Asked`, a forked head as 5.6 step 3, emits `Pulled` once. Returns `Ok(())` when the holder's head
equals the remote head, or when the remote has nothing newer; a refused page or bad object is
`BadObject` (and 5.6's drop and `Refused`). Works the same on a full machine (it asks another full
machine). Must not run alongside a sync with the same machine on the same channel in a way that
ingests one page twice (use the existing one-sync-per-pair rule, or make the holder's
`Stored` head the start of each page).

AC6 `need_blob(id, size)` (5.8, 5.9). Fetches the package from the chosen machine as 5.8's fetch
(size and `limits.blob` first, BLAKE3 and size again, temp file removed in every case) and calls
`holdings.store_blob`. A package over `limits.blob` is `TooLarge` with no transfer. A hash
mismatch is `BadObject`. A machine that does not have it (`not_found` / the fetch fails with no
data): try the next candidate; none had it: `Unreachable` naming the last machine and the cause.

AC7 `query(q)` (5.9, NET-F-25, node Q6). Returns `(own node key, holdings.search(q))` first,
then `(full machine, its hits)` when one answered (deadline 5 s). For each remote hit whose
channel the holder lacks (no head in `holdings.heads(Some(&[channel]))`) or holds at a lower seq
than the hit, pull it from that machine (as `need`, `Asked`), at most 32 distinct channels per
5-second window across all `query` calls of this `Net` (a counter of pulled channels with the time
of the first pull in the window; constant `QUERY_PULLS = 32`, `QUERY_WINDOW = 5 s` in net, both
written into 5.9 and node/TECHNICAL.md 13 Q6 marked answered by net). Hits beyond the cap are
still returned, not pulled. A remote hit is returned whether or not its pull succeeded; the holder
verifies (node 5.4). Unit test of the window counter with an injected clock.

AC8 `own_heads(channel)` (5.11, NET-F-30). Asks `heads` for `[channel]` of every candidate of AC3
that answers (in parallel, each within the request deadline) and returns `(node, answer)` for
each. It ingests nothing, calls no `holdings.ingest`, and emits no `Pulled`.

`Event`'s variants and `Limits`' existing fields do not change.
