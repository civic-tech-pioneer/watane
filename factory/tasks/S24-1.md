Slice: S24 — Publish and install edges: Bob's coding agent publishes and installs, and every
refusal tells it exactly what to do next, with no leaked paths or repeated text.

## Goal
The app's local API (`app/src/api.rs`, merged into the host's server) lets `watane-dev` see what
Bob has already published, so the agent learns "this version is already out, here is its link"
before it builds, and again after Bob approved a publish too late for the agent's `--wait`. A
duplicate version gets its own error code instead of the generic `publish_refused`. The 422 for a
corrupt package names its cause once and no temporary path.

## Acceptance
- AC1 `GET /api/releases` on a router whose dist has published `reading-list@0.1.0` (site URL
  set) answers 200 `{"releases":[{"slug":"reading-list","version":"0.1.0","release":"<ReleaseRef
  text>","seq":<n>,"link":"<link text with #reading-list>"}]}`, one object per own release in seq
  order. With no site URL, `link` is `null`. With nothing published, `{"releases":[]}`. Dist not
  open (`router(None)`): 503 `unavailable`, as `publish` does. Other methods on the path behave as
  the host's other API routes do for a wrong method (state what you found). Unit or `#[tokio::test]`
  in `api.rs` on the router, no window.
- AC2 Posting the same package twice: the second answer is 409 with code `version_exists`
  (was `publish_refused`) and message `release <ref> already exists at seq <n>` (dist's text).
  Other dist refusals keep `publish_refused`. Update the two existing tests that assert the old code
  for a duplicate: `app/tests/api.rs` `ac6_publish_http_rows_without_window` (line ~98) and
  `ac6_publish_through_consent_window_and_host_guards` (the `bytes, 409, "publish_refused"` row).
  Change only those assertions in that file; add new tests in `api.rs`'s own test module.
- AC3 A package that passes the header check but fails to unpack (build a real package with
  `watane_pkg::pack` on `tests/fixtures/reading-list`, then corrupt its body, e.g. flip bytes after
  the header, until dist refuses it with `DistError::Package` or the unpack error): 422
  `invalid_package`, and the message contains no path of the temp dir (no `/`-separated path
  segment from `std::env::temp_dir()`, no `.tmp`) and names each location (file name, entry) at
  most once. Assert the exact message as a literal. Fix it where the text is made: dist's error
  text (`dist/src/error.rs`, `dist/src/own.rs` `unpacked`) or the mapping in `api.rs`; if dist,
  keep each existing dist test green and add its unit test in dist.
- AC4 Spec: `app/TECHNICAL.md` section that lists `/api/publish` gains `GET /api/releases` and the
  `version_exists` code; dev's `TECHNICAL.md` 14 (what dev takes from app) names both. One line
  under "Spec gaps settled" in `app/AGENTS.md`. `cargo test -p watane-app` (default features),
  `cargo test -p watane-dist` if touched, clippy `--all-targets -D warnings`, `cargo fmt --check`
  pass.

## Spec
`app/TECHNICAL.md` (the `/api/publish` route and its error table), `app/FUNCTIONAL.md` publish
requirements; `dist/TECHNICAL.md` `own()`, `own_link`, `DistError::VersionExists`; host
`TECHNICAL.md` on extra API routes (the app's router is merged into the host server, which applies
its own guards first).

## Interface
Provides (fixed; S24-2 builds dev against it in parallel):
- `GET /api/releases` -> 200 `{"releases":[{"slug":string,"version":string,"release":string,
  "seq":number,"link":string|null}]}`; errors as `{"error":{"code","message"}}`.
- `POST /api/publish` duplicate version -> 409 `{"error":{"code":"version_exists","message":
  "release <ref> already exists at seq <n>"}}`.
Takes from dist (exists): `Dist::own()` (`releases`: `ReleaseInfo` with `release.slug`,
`release.version`, `reference`, `seq`), `Dist::own_link(Some(&slug))` (`Err(NoSiteUrl)` = null).
