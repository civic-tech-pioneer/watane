## Goal
pkg reads a mod whose world imports an interface of its own package (an outlet) and tells each
of its functions apart: no result is an event, a `list<T>` result is a collect, anything else is
refused with rule `import` naming `<interface>.<function>`. `World` gains `collects`: the outlets
that hold at least one collect (pkg stage 9).

## Acceptance
- AC1 (A26) a world importing its own `menu` with `ask: func() -> list<string>` and
  `clicked: func(id: string)` reads: `world().events == [mods:<slug>/menu@<version>]`,
  `world().collects` the same, `grants()` unchanged from a world with only `clicked`.
- AC2 (A27) the same world with `ask: func() -> string` is refused with rule `import`; the
  message names `menu.ask` (literal text of TECHNICAL 4.5).
- AC3 a world with an event-only outlet has `collects == []`; a `list<u8>` and a
  `list<record>` result both count as collects; `result<...>`, `option<list<..>>` and a tuple
  result are refused.
- AC4 test file `pkg/tests/outlet_functions.rs` (the stage 9 test name of TECHNICAL 12).
  `cargo test -p watane-pkg`, `cargo clippy -p watane-pkg --all-targets -- -D warnings`,
  `cargo fmt --check` clean; the workspace still builds (`cargo build -p watane-host -p watane-dev`).
