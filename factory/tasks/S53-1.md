Slice: S53 — J3 and J5 against real GitHub

## Goal

J3's and J5's GitHub journeys run once more, now against the real GitHub organisation `minmax-fund`
with the real `gh` and real `git` over https, instead of `fake-gh` and local bare remotes. They are
new tests next to the existing `ac2_j3_github` and `ac2_j5_github`, which stay as they are (the fast
fake suite). The new tests are behind a cargo feature, so no `--include-ignored` run anywhere else
reaches GitHub. Every repository the tests create is a throwaway, named and removed by the tests
themselves, and the token never appears in any output.

Known limit (decided by the product owner): watane-dev takes its GitHub owner from
`gh api user --jq .login`. With the org-scoped token that returns the human's own login, not
`minmax-fund`, so any repository dev would name itself lands in the wrong account (403). The tests
therefore pre-create every repository and give it to dev: the mod's repository through `repository`
in `mod.toml`, the channel's repository through the git origin of `<home>/dist/site`. Carol's fork
(J5) is not exercised: her `mod.toml` names a pre-created repository, so dev pushes there without
GitHub's fork link. Do not change `dev/src` other than `dev/src/bin/fake-gh.rs`.

## Acceptance

AC1 Real-GitHub harness (`app/tests/support/github.rs`, new; `mod github;` in `support/mod.rs`).
- Reads the token from `CLAUDE_GH_TOKEN` in the test process. If it is unset, the test panics with
  "CLAUDE_GH_TOKEN is not set (real GitHub tests need it)". The token is passed only to child
  processes, as `GH_TOKEN`, never set in the test process's own environment, never written to a
  file, never put in a command line.
- Children get a fresh `GH_CONFIG_DIR` (a tempdir), `GH_PROMPT_DISABLED=1`, `GIT_TERMINAL_PROMPT=0`,
  and a `GIT_CONFIG_GLOBAL` file with a user identity and
  `[credential "https://github.com"] helper = ` then `helper = !gh auth git-credential` (the empty
  line clears inherited helpers). `GIT_CONFIG_NOSYSTEM=1`. The real `gh` on PATH; no `fake-gh`.
- `create(&mut self) -> String` returns `minmax-fund/watane-j-<r>`, where `<r>` is 10 random
  lowercase letters and digits starting with a letter. Before creating, `gh api repos/<name>` must
  answer 404; any other answer (it exists, or an error) panics without creating. It creates with
  `gh repo create <name> --public` and records the name.
- On `Drop` (also when the test panics), it deletes with `gh repo delete <name> --yes` exactly the
  names it recorded, after asserting each starts with `minmax-fund/watane-j-`. A failed delete is
  printed (name and gh's stderr) and does not panic in `Drop`. It never lists, reads or deletes
  any other repository of the org.
- Every string that goes into a panic or assertion message (child stdout/stderr, JSON results)
  passes through `redact(token, text)`, which replaces the token with `[token]`. A check in
  `app/tests/support_selftest.rs` (made-up token, no network): the token is gone from the result.
- Helpers mirror `support::dev::Github`: `dev_command(dev, app, dir, args) -> Command`,
  `git(args) -> String` (with the same environment), `site_origin(home, name)` which runs
  `git init -q -b main` in `<home>/dist/site` (creating the folder if needed), writes `.*` to
  `.git/info/exclude`, and adds origin `https://github.com/<name>`.

AC2 `j3.rs::ac3_j3_real_github` (`#[cfg(feature = "real-github")]`,
`#[ignore = "real: GitHub minmax-fund"]`). Same story and assertions as `ac2_j3_github`, with:
Alice's mod repository and site repository pre-created through the harness; `repository` in her
copied `mod.toml` set to the mod repository's https URL; her site origin set with `site_origin`.
Then `publish --push` waits for her signature and succeeds (`ok`, exit 0); `push.site.raw` is
`https://raw.githubusercontent.com/<site name>/main/`; a fresh `git clone` of the mod repository
over https has the release tag; a fresh clone of the site repository has a non-empty `head` on
`main`; that clone, served by `Site::serve`, gives the link on the retry (`publish.version_exists`);
Bob installs from it and opens the mod. All repositories deleted at the end.

AC3 `j5.rs::ac3_j5_real_github` (same cfg and ignore). Same as `ac2_j5_github` through Carol's
publish, with all four repositories (Alice's mod and site, Carol's mod and site) pre-created; Alice
as in AC2; Carol's `new ratings --from <link>` clones Alice's real repository (assert HEAD is
Alice's tagged commit and `remote.upstream.url` is Alice's https URL); after the agent's rewrite
Carol's `mod.toml` also gets `repository` = her pre-created repository, and her site origin is set.
Carol's `publish --push` succeeds with `push.mod.forked == false` (the known limit above); a fresh
clone of Carol's repository has her release tag, and Alice's tagged commit is an ancestor of it.
No assertion on `fake-gh-parent` or the `watane` branch (those need the fork).

AC4 Feature: `app/Cargo.toml` gains `real-github = ["driver"]`. Without the feature the two tests do
not compile in. `cargo test -p watane-app --features driver` is unchanged.

AC5 Differences from fake-gh. If the real run (done by the foreman, see Notes) shows that `gh` or
GitHub answers something differently from `dev/src/bin/fake-gh.rs` for a command dev runs (output
text, exit code, error text), change `fake-gh.rs` to answer like GitHub, and keep
`ac2_j3_github`, `ac2_j5_github` and dev's fake-gh tests green. List each difference in
`app/NOTES.md` under "S53 real GitHub".
