Slice: s114 — A maker previews an OpenAI-backed mod on scripted responses

## Goal

A development preview can run checked OpenAI requests against the loopback scripted program.

## Acceptance

1. A valid scripted preview starts the program, verifies its TLS name and delivers the streamed response without asking for a participant account.
2. The CLI rejects the setting for real homes before starting the program. Opening an existing participant home as a preview fails before launch.
3. The release host rejects the flags. A wrong origin, method, or missing grant never gains the scripted account. A failed fake connection has no public fallback.
4. Startup failure and ordinary shutdown stop the child.

## Spec

spec/TECHNICAL.md §6 (W5), host/TECHNICAL.md §3, §19.4 and §19.9.

## Interface

Unix development host CLI: `watane --preview <dir> --scripted-openai <program> [--openai-script <file>]`. The child implements the S111 ready line and script interface from dev §18.3.

## Files

host/TECHNICAL.md, host/build.rs, host/src/home.rs and its new preview module, host/src/bin/watane.rs and its new preview module, host/src/agent/https_stream.rs and its new preview module, host integration tests.

## Changed tests

None. Existing host CLI, preview and S111 HTTPS tests keep their expectations without the flag.

## Out of scope

Judge routing, participant accounts, and release previews of OpenAI-backed mods.
