## Goal
1. A WIT syntax error reaches the maker's agent with a line: `watane-dev check --json` on a mod
   whose `wit/world.wit` has a syntax error gives `errors[0].file == "wit/world.wit"` and a
   non-null `line` and `column` (S86-1 makes pkg's message carry wit-parser's `-->` location;
   dev's `wit_location` in dev/src/check.rs reads it; fix it there only if it cannot parse the
   form S86-1 produces).
2. An outside `.wit` read is one problem (dev/src/builder.rs :364-:374). Today a
   `generate!` pointed at another mod's `wit/` yields one `build.reads_outside` per `.wit` file.
   After: all outside paths ending in `.wit` give ONE `build.reads_outside`: for one path, today's
   message and fix; for n > 1, message `the build read <n> .wit files under <folder>, outside the
   mod` and the `.wit` fix of `reads_outside_problem` with `<folder>` in place of `<path>`, where
   `<folder>` is the deepest common ancestor folder of those paths. Every other outside path stays
   one problem each, in today's order after the `.wit` problem. `logic.wasm` is still not written.
3. fake-watane can be told never to answer: `fake.json` `{"answer":"never"}` makes it accept a
   request to the consent routes (`/api/install`, `/api/publish`) and hold it without a response
   until the process is killed (dev/src/bin/fake-watane.rs :210). Then `watane-dev install --json
   --wait 1 --home <fake home>` ends with `host.no_answer`, exit 4, its message `no answer from
   the home host in 1 s` and its fix and `next` as dev/TECHNICAL 2.2 / 2.4 give them. This is a
   fast integration test in dev/tests/install.rs (not slow).
4. `install::ac2_real_home_without_app` (dev/tests/install.rs :425) stops `watane` through the
   existing `Host` guard (`struct Host(Child)` with `Drop`, at install.rs :130; move it to file
   level so both tests use it), so a failed assertion no longer leaves `watane` running.
