## Goal
net's causes say what happened, once. A light machine whose request a full machine refuses with
`not_allowed` (it was removed from Alice's machines) gets `NetError::Refused { node, code:
NotAllowed }` back from `need_blob` (and from every other light fetch path: `need`, the remote
query), not `Unreachable`. A pairing code that the anchor refuses (spent, expired) gives
`NetError::CodeSpent`, whose text says the code was used; `BadCode` stays for a text that does
not parse as a code. A dial that fails says "no direct path" only when this machine knows no
direct address for the node; when it knows addresses that did not answer it says so instead
(e.g. "did not answer at its <n> known addresses"), and a cause never repeats a phrase or a
node's short key (the user-sim saw "no direct path" three times in one message, and the key
twice).

## Acceptance
- AC1 a light machine, removed from the device list by the anchor while a full machine that holds
  a package keeps the new list, calls `need_blob` for that package: the result is
  `Err(NetError::Refused { node: <full>, code: Code::NotAllowed })`; its text is
  `node <short> refused: not_allowed` (app/tests/j8.rs reads that literal; keep it). Same for
  `need` of a channel. Test in net/tests/light.rs (or a new net/tests/regress_s80.rs).
- AC2 a well-formed code that the anchor refuses (used once, declined, expired) gives
  `Err(NetError::CodeSpent)`; its Display is `the pairing code was used or has expired; make a
  new one on the anchor`. A text that does not parse gives `BadCode` (`not a pairing code`).
  No new wire code: the anchor still answers `bad_code`; the joiner maps it (client.rs:211).
- AC3 `join` (and any request) to a node whose direct addresses are known but which is off: the
  error's whole chain (Display plus every `source()`) does not contain `no direct path`, names the
  node's short key exactly once, and says it did not answer at its known address(es) (add the
  relay/DHT advice of `no_path_cause` only once). To a node with no known address: the chain
  contains `no direct path` exactly once. Test at the lowest level that shows it (a unit test of
  the cause text plus one loopback test).
- AC4 every `NetError` variant that carries a `cause` and a `node`: the cause text no longer
  repeats `node <short>` (find where nested errors are formatted into a cause, e.g.
  light.rs:178-186, and strip the inner key); a unit test per place you change.
- AC5 `cargo test -p watane-net` passes (with `-- --include-ignored` once); clippy
  (`--all-targets -D warnings`) and fmt clean.

## Interface
Provides to S80-3 (node), fixed:
- `need_blob` / `need` return `NetError::Refused { node, code: Code::NotAllowed }` when the asked
  full machine answers `not_allowed` (the last such answer if several machines were asked and none
  succeeded; `BadObject` keeps priority as today).
- `NetError::CodeSpent` Display: `the pairing code was used or has expired; make a new one on the anchor`.
- `NetError::BadCode` Display unchanged: `not a pairing code`.
No wire, no disk format change; `Event` and `Code` keep their variants.
