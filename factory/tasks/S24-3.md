## Goal
The S23 user-sim leftovers in dev's text: a person or agent reading `watane-dev` without `--json`
sees one progress line per build that is true on warm builds, a `serve` next line it can copy, a
`check` fix that never says to edit a do-not-edit file, object lists one per line, and an argument
error that names its command.

## Acceptance
- AC1 Progress: one `build` of a mod prints one progress line on stderr, not two (a release build
  plus a unit build of the same mod both print today). The text does not claim "first build" on a
  warm build: e.g. `building <slug>` and, only when the cache copy has no previous target output,
  ` (the first build takes a minute or more)`; state the rule you chose. This changes
  `builder::tests::ac1_release_and_unit_build_progress_stays_on_stderr` (`dev/src/builder.rs`,
  asserts the line twice with "first build"): update its literal to the new rule. stdout stays the
  one result object.
- AC2 `serve`'s `next` (`serve_next` in `dev/src/cli.rs`): the page URL never has a `.` or other
  punctuation glued to its end (put it last, or after `: ` at the end of a sentence with no trailing
  dot, or on its own sentence after the setup text). In text mode the setup sentence names the
  printed keys (`mcp.url`, `mcp.token`) and not `result.mcp.url`; JSON mode keeps `result.mcp.*`.
  Find each existing test that asserts the old `next` text (`dev/tests/serve.rs`, `unit_tests.rs`,
  `journey*.rs`, `cli.rs` tests) and update its literal; name them in your report. Unit test on
  `serve_next` for both modes.
- AC3 `check` on a mod whose `deps.json` lists a provider the world does not import (an unused
  provider) no longer says `Correct deps.json according to the reported rule` (`dev/src/check.rs`
  ~137): `deps.json`, `wit/deps/` and `.watane-dev.json` are do-not-edit (`dev/template/AGENTS.md`
  table). For a violation whose file is one of those, the fix names the user action instead: import
  the provider's interface in `wit/world.wit`, or remove the dependency (state which command or
  edit removes it today; if none exists, the fix says to import it or to ask before deleting
  `wit/deps/<slug>/` and `mods:<slug>` from `deps.json`). Integration test in `dev/tests/check.rs`
  on a fixture, no build.
- AC4 Text mode (TECHNICAL 2.3): a list of objects (e.g. `pages`, `installed`, `providers`) prints
  one line per object with indexed dotted keys (`pages.0.slug: x`, `pages.0.url: ...`) instead of
  one joined line; lists of plain values keep `, ` joining and `none`. Unit test in `outcome.rs`.
- AC5 An argument error (`watane-dev serve --bogus`, `watane-dev publish --wait x`,
  `watane-dev frobnicate`) in text mode ends with `<command>: failed` for every known subcommand
  name found in the arguments (all of them, not only `new`/`check`/`serve`), and
  `watane-dev: failed` when none is found, never a bare `: failed`. JSON keeps the same `command`
  (empty string -> `watane-dev`? state your choice and keep `tests/envelope.rs` green, updating a
  literal only if it asserts `""`). Integration test running the binary.
- AC6 The template guide `dev/template/AGENTS.md` is at its 143-line cap; if any change here needs
  a guide line, cut one first and keep it at most 143 lines (its line-count test stays green).
- AC7 Spec: TECHNICAL 2.3 (object lists, argument errors), 2.4 serve `next`, the builder progress
  rule (6.x). One line under "Spec gaps resolved" in `dev/AGENTS.md`. Default
  `cargo test -p watane-dev`, clippy `--all-targets --all-features -D warnings`, `cargo fmt
  --check` pass.
