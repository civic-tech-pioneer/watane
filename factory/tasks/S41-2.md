## Goal
When pkg refuses `repository` in mod.toml, `watane-dev check` (and every command that reports
pkg violations through `mod_problems`) gives the `mod.invalid` error the fix of dev 2.2 instead
of the generic `Correct mod.toml according to the reported rule`.

## Acceptance
Unit tests in `dev/src/check.rs` (`#[cfg(test)]`), built from a hand-made `watane_pkg::Violation`
(the pkg parser is built in parallel by S41-1; do not depend on it).
- AC1 A violation `{ rule: Rule::ModToml, file: "mod.toml", message: "`repository` must start with https://" }`
  → one problem, code `mod.invalid`, message ``[mod-toml] `repository` must start with https://``,
  file `mod.toml`, fix exactly:
  `Set repository in mod.toml to the https URL of the mod's git repository (for example https://github.com/<owner>/<slug>), or remove the line`
  The same fix for each of the other four messages of pkg 4.2 (longer than 256 bytes; user name or
  password; no host; may hold only ...).
- AC2 A `ModToml` violation whose message does not start with `` `repository` `` (e.g.
  ``name must have 1..=64 characters, no control characters or surrounding whitespace``) keeps
  today's fix `Correct mod.toml according to the reported rule`; a violation of another rule whose
  message starts with `` `repository` `` keeps its own fix too.
- AC3 `cargo test -p watane-dev` (default set), `cargo clippy -p watane-dev --all-targets -- -D warnings`,
  `cargo fmt --check` green.

## Spec
dev `TECHNICAL.md` 2.2: the paragraph after the class notes ("In step 6, `<rerun>` ...  A

Takes from S41-1 (pkg): a `repository` refusal is `Violation { rule: Rule::ModToml, file:
"mod.toml", message }` with `message` starting with `` `repository` ``. No new public API in dev.
