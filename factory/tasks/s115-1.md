## Goal

Changing net's switches (`Net::set_options`, which rebuilds the endpoint) and closing
net close the blob store's database before anything opens it again, on every platform.

The cause, named: each rebuild in `Net::apply` (net/src/lib.rs) drops the old router and
calls `blobs::open`, which runs `FsStore::load` on the same `blobs/` folder. The old
store's redb database is closed only when iroh-blobs' metadata actor ends, and that
actor ends only once every clone of the old store is dropped, asynchronously, on the
runtime (the router's shutdown is bounded by `CLOSE_WAIT`, so clones can outlive it).
redb holds an exclusive lock on its file while open. On Linux and macOS the last clone
is usually gone in time; on Windows the old handle (and its `LockFileEx` lock) is often
still held, and the reopen fails with `database error: Database already open. Cannot
acquire lock.` (PR #28, run 45465209516, `reach.rs:193`). A person hits this too: the
app's relay or DHT switch calls `set_options`. The fix: keep the store in `Running` and,
on teardown, await `Store::shutdown()` (iroh-blobs drops the redb `Database` before it
answers) after the router stopped and before any new `FsStore::load`.

## Acceptance

1. AC1. `set_options` that rebuilds the endpoint 20 times in a row on one node (relays
   switched between two lists, a paired machine connected) returns `Ok` each time, and
   the node still answers `hello` from its paired machine afterwards.
2. AC2. `close()` then `Net::open` on the same folder at once, in the same process,
   opens (no `Io` error), 10 times in a row.
3. AC3. The rebuild path awaits the old store's shutdown before `blobs::open` runs again;
   the wait is bounded (a few seconds, not `CLOSE_WAIT`), and a timeout there still
   reports the reopen's own error, not a hang.
4. AC4. `reach::s11_machines_on_different_networks_connect_through_the_servers_relay`
   unchanged and green.
