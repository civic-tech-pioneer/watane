Subsystem: pkg
Effort: medium
Depends on: none
Slice: S15 — Packages say what is wrong: a maker packs a mod with a bad file and the error names the real cause.

## Goal
`pack`, `Package::from_bytes` and `Package::unpack` (`pkg/src/package.rs`) refuse the same inputs as
today, but each refusal names its real cause: too many files says so with the limit; a hidden link
is a link; a path with a NUL or control character prints escaped; a failed unpack reports its own
error even when the cleanup fails too. And `pack` reads each file without following a link, so a
file swapped for a link between the walk and the read is refused, never read through.

## Acceptance
Each criterion's test at the lowest level that shows it: unit tests (`#[cfg(test)]` in
`package.rs`) for the private helpers, `pkg/tests/package.rs` (or a new `pkg/tests/regress_s15.rs`)
for the public behaviour.
- AC1 Too many files. `from_bytes` of raw bytes (the test's raw writer) with count 4097 →
  `PackageError::TooManyFiles`, whose text contains `too many files` and `4096`. `pack` of a valid
  page-only mod with 4097 files under `ui/` → the same variant and text. Count 0 stays `Format`.
  No message anywhere still says `count must be 1..=4096`.
- AC2 Hidden link. `pack` of a valid mod folder with a symbolic link `ui/.x` (to a file inside or
  outside the folder) → `PackageError::Symlink { path: "ui/.x" }`, not `PackageError::Mod(..)`.
  A hidden regular file `ui/.y` is still skipped silently (A13 unchanged).
- AC3 Escaped paths. A path holding a NUL, a newline, ESC (`\x1b`) or DEL: the `Display` text of the
  resulting `Path` (from `from_bytes`, and from `pack` with a file named e.g. `ui/a\nb.js`) and of a
  `Symlink` (a link named `ui/a\x1bb`) contains no byte below 0x20 and no 0x7f; the character is
  written as its Rust escape (`\0`, `\n`, `\u{1b}`, `\u{7f}`). The `path` field keeps the raw text.
  An ordinary path prints exactly as before (existing message tests stay green).
- AC4 First error wins. A unit test makes `unpack`'s cleanup fail after the unpack failed (e.g. the
  cleanup step is a small private function the test can drive with a dest whose removal fails, such
  as a read-only parent on unix) and checks the returned error is the unpack error (e.g.
  `Mod(Invalid ..)` with rule `mod-toml`), not an `Io` from the cleanup. Normal case unchanged: a
  failed unpack removes dest (A18).
- AC5 No-follow read. The private function that opens a file for `pack` refuses a path whose last
  component is a symbolic link with `PackageError::Symlink` naming the relative path (unit test: a
  link to a regular file inside the folder; and a link to a FIFO, which must return, not hang), and
  refuses a non-regular file (a FIFO at that path) with `PackageError::Path`, again without hanging.
  `pack` uses it for every file read.
- AC6 `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` green in pkg;
  existing tests (golden, determinism, round trip) stay green; package bytes and ids unchanged.

## Interface
Fixed (host, dev and dist print `PackageError` with `Display` and match no variant):
- New variant `PackageError::TooManyFiles` (unit variant), message
  `too many files; the limit is 4096`. Used by both `pack` and `from_bytes`.
- `Path` and `Symlink` keep their fields and message shapes; only the `{path}` part is printed with
  `str::escape_debug` (`Path { path: String, reason: &'static str }`, `Symlink { path: String }`).
- No other public signature changes. The byte format does not change.
- No-follow open on unix: `std::os::unix::fs::OpenOptionsExt::custom_flags(libc::O_NOFOLLOW |
  libc::O_NONBLOCK)`, then `file.metadata()` must be a regular file; `ELOOP` (and macOS's `EMLINK`
  if it shows up) maps to `Symlink`. Decided: add `libc = "0.2"` to pkg's `[dependencies]` under
  `[target.'cfg(unix)'.dependencies]`; it is already in the workspace `Cargo.lock`, so no new crate
  enters the tree. Still no `unsafe`. Non-unix builds keep a plain open plus the metadata check.
