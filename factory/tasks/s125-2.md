Slice: S125 — keep judge key removal available and guard app reopen

## Goal
Alice can see and remove a kept judge key after withdrawing the provider's Claude Code grant. The judge editor explains why Save is unavailable and which origins the provider can reach. The committed app fixtures exercise immediate reopen repeatedly.

## Acceptance
1. AC1. Save a judge key and withdraw the provider's Claude Code grant. The manager still shows the stored origin and Remove key. The editor is unavailable. Removing the key clears the manager section and deletes the file.
2. AC2. Save an origin outside the granted HTTP hosts, or try to save for an ineligible mod. The command refuses without saving a key. Withheld HTTP grants do not authorize saves. Invalid origins and missing input explain why Save is unavailable.
3. AC3. A key replacement ends the stream that used the old key. Removing the key ends a stream using the replacement. Uninstall uses the same revocation operation and deletes the key file.
4. AC4. After the committed fixture calls and writes state, drop the host and reopen immediately, 20 times, with no retries. The persisted state is still readable.

## Interface
No subsystem interface changes. The app uses the existing watane_host::judge_origin, Host::grant, Host::revoke and Host::account_changed APIs. For a kept key on an ineligible provider, ModView.judge has kept=true, the origin, and an empty hosts list.
