## Goal

A package path with a Windows reserved device name in any segment is refused on
every platform, when packing, when decoding and when reading a mod folder, so a
package that unpacks on Unix cannot fail or misbehave on Windows (S110 R2).

## Acceptance

1. AC1. `Package::from_bytes` of a package with a segment `con`, `aux.txt`,
   `COM1`, `lpt9.wit`, ... is `PackageError::Path` with the reason
   "a Windows device name is reserved".
2. AC2. `pack` of a folder with such a segment (Unix, where it can exist) is
   refused the same way, naming the first offending path.
3. AC3 (r1, P1.5). `Mod::read` of a folder with `wit/deps/aux.wit` is
   `ModError::Invalid` with a `Rule::Path` violation on that file.

## Spec

`pkg/TECHNICAL.md` 6.2 (path grammar) and 4.6 (`Mod::read` uses the 6.2 grammar).
