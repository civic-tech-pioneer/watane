Slice: S24 — Publish and install edges: Bob's coding agent publishes and installs, and every
refusal tells it exactly what to do next, with no leaked paths or repeated text.

## Goal
`watane-dev publish` asks the app which versions Bob already published before it tests and
builds. If this mod's slug and version are out, it stops at once with `publish.version_exists`,
the existing release and its link, and says to raise the version. That also closes the S12b-shared
gap: Bob approved after the agent's `--wait` ran out, the release was signed but the agent never
got the link, and "run again with a longer --wait" hit "already exists". Now that retry reports
the release and its link. Every refusal of `publish` and `install` carries a `next`.

## Interface
Takes from app (S24-1 builds it in parallel; build against this, test with `fake-watane` and
loopback stubs):
- `GET /api/releases` -> 200 `{"releases":[{"slug":string,"version":string,"release":string,
  "seq":number,"link":string|null}]}`; an error answer `{"error":{"code","message"}}` is
  `host.refused` as other routes are.
- `POST /api/publish` duplicate version -> 409 `{"error":{"code":"version_exists","message":
  "release <ref> already exists at seq <n>"}}`.
