## Goal
The text and `next` lines an agent reads stop misleading it: text mode prints an empty list as
`none`; `serve` that started a new preview (`reused: false`) tells the agent to set or
update its MCP config, since url and token change; `doctor` run inside a mod folder does not
suggest `watane-dev new`; `check` failing on `mod.invalid` (and any other mod error) gives a
`next`, as `test` does.

## Acceptance
- AC1 Text output (`outcome.rs` `text_value`): an empty JSON array prints `none`, e.g.
  `calls: none`; non-empty lists unchanged. Unit test in `outcome.rs`.
- AC2 `serve` ok with `result.reused == false`: `next` still gives the page link and adds
  that the MCP url and token are new, so the agent sets or updates its MCP config (the guide's
  "MCP tools for your agent" section) with `result.mcp.url` and `result.mcp.token`. With
  `reused == true` `next` is as today. Unit tests on `serve_next` in `cli.rs`.
- AC3 `doctor` with no errors run in a folder that has `mod.toml` (the process's current
  folder or `--dir`): `next` is `watane-dev serve --json`, not `new`. Outside a mod folder
  as today. Test at the lowest level that shows it (doctor may take the folder as an argument).
- AC4 `check` that fails with a mod-class error (e.g. `mod.invalid` from a WIT keyword used as
  a name): `next` is not null; it says to fix the errors and run `watane-dev check --json`
  again (mirror what `test` gives for the same failure). Env-class failures keep doctor.
- AC5 TECHNICAL 2.3 (text output) and 2.4 (doctor, check, serve `next`) say the above.
