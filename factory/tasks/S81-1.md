## Goal
The manager says what it means. In the Library, the main mod is marked as the one that opens at
start. The install consent for a mod that proposes itself as main (pkg 4.2 `main = true`) says,
when it will become the main mod (APP-F-63: none set yet), that it opens when watane starts, in
place of the manager. A connection link in a mod's details (APP-F-66) moves keyboard focus to the
target mod's details, not only scrolls. The warning before disable or remove (APP-F-67) names each
affected mod by how it is connected (it uses the mod, or it extends it), so a mod connected only by
an `Extended by` link is not called a user.

## Acceptance
- AC1 With mod A set main, the Library entry of A shows the text `Opens at start` (a `.main-mark`
  element); no other entry shows it; after `Unset main` none shows it.
- AC2 Installing a folder whose `mod.toml` has `main = true` on a home with no main mod: the
  consent view shows the line `<name> opens when watane starts, in place of the manager.` With a
  main mod already set, that line is absent (the mod does not become main, APP-F-63).
- AC3 Clicking a connection link (`Used by: B` in A's details) leaves `document.activeElement`
  inside B's library entry (B's details open, its first control or its heading focused).
- AC4 Disabling a mod X that an enabled mod Y only extends (Y subscribes to X; Y does not call X):
  the dialog reads `Disable X? These mods extend it: Y.`; when Y calls X it reads `These mods use
  it: Y.`; with both kinds, both sentences, uses first. Same for Remove.
- AC5 Each new text is in app/TECHNICAL.md (5.3, 5.4 or 6.3, where its fact lives) and APP-F-63,
  66, 67 in app/FUNCTIONAL.md say it where they already speak of it.
- AC6 Green: the app's tests (`cargo test -p watane-app --features driver -- --include-ignored`
  with the four front tests skipped), clippy and fmt clean.
