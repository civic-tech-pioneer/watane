# watane: where things are, for agents

An empty host that people fill with their own mods. One Cargo workspace;
one folder per subsystem.

## Find the right document

| You need | Read |
|---|---|
| Why, goals, order of work | `spec/VISION.md` |
| What it does, journeys | `spec/FUNCTIONAL.md` |
| What flows between subsystems, security model | `spec/TECHNICAL.md`; peers: `spec/PEERS.md` |
| One subsystem (`pkg host dev app log dist net node install`) | `<sub>/VISION.md`, `FUNCTIONAL.md`, `TECHNICAL.md`, then `<sub>/AGENTS.md` for its commands and rules |
| A signature | the `TECHNICAL.md` of the subsystem that owns it, nowhere else |
| What a source file does | its `//!` line, which cites its `TECHNICAL` section |
| What is built, what is next | `factory/PLAN.md`; one task's brief: `factory/tasks/<id>.md` |
| How the build process works | `factory/README.md`, `.claude/skills/`, `.claude/agents/` |

Work inside one subsystem from its folder: its `AGENTS.md` is written for
that.

## How to treat them

- **The chain decides**: `spec/` vision, functional, technical, then a
  subsystem's three, then code. When two disagree, fix the lower one at
  once, in the document that owns the fact, and fix each one that cites it.
- **Contracts vs records.** `VISION`, `FUNCTIONAL`, `TECHNICAL`, `PEERS`
  and `AGENTS` are contracts. `NOTES.md`, `net/REVIEW.md`,
  `net/ARCHITECTURE-PROPOSAL.md`, `factory/harness-*.md`,
  `spec/design/*/COMPARISON-*.md` and finished task briefs are records: read
  them for why, never cite them as the rule, and do not rewrite history in
  them.
- **Ask the human** only to go against a vision document or to weaken a
  security check.
- A new source file starts with a `//!` line: what it is for, and
  `(TECHNICAL n.m)` when a section owns it. `factory/check.sh` fails
  without one.

## Do not touch

- `workspace-hack/`: generated by `cargo hakari generate`.
- `target/`: shared by every worktree (`.cargo/config.toml`).
- `../colos`: reference only; code is written new here.

## Commands

```bash
cargo build && cargo test
cargo clippy --all-targets -- -D warnings && cargo +nightly fmt --check
factory/check.sh <task-id>          # a task's full gate, from its worktree
```
